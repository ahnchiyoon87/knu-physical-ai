# HydOps 대조와 경남대 강의 수정 계획

> 최신 방향 변경: 사용자가 대표님 플랫폼·UI 자체를 베이스로 채택하도록 지시했다. 구현 범위와 다음 순서는 [HydOps 베이스 채택 범위](HydOps_베이스_채택범위.md)를 따른다. 아래 비교 근거는 보존하지만 기존 앱 중심 도입 및 기존 앱 측정 출발본은 새 방향의 정본이 아니다.

2026-09-15 · 자료 개편 착수 전 검토. 날짜·시수·반 구성은 유지한다. 이 문서는 수정 계획이며 기존 덱·가이드·코드·학생 ZIP에 반영한 결과가 아니다.

## 판단

**HydOps의 센서→사건→근거→승인 조치→새 관측 흐름을 공통 실습의 중심으로 채택하고, 학생이 코딩 에이전트로 자기 서비스를 만드는 방식은 유지하는 것이 맞다.** 기존 제작본은 표 질문과 여러 분석 기능을 넓게 경험하는 데 무게가 있다. HydOps는 한 사건의 처리 결과를 끝까지 확인하는 데 무게가 있다. 차이는 제목이나 설명량에 그치지 않는다.

직전 `재설계/챕터별_실라버스.md`는 관측·품질·관계·이상·문서를 잇는 순서를 이미 개선했다. 그러나 제안 후 **상태에 영향을 주는 조치와 새 관측의 재측정**은 여전히 구체화가 부족하다. 기존 코드의 `backend/process/gateway.py:record`는 승인된 규칙 폭을 바꾸고 결정·그래프 outbox를 기록한다. 기존 실전 9일차도 같은 입력의 경보 수를 재비교한다. 이 기능은 유용하지만 HydOps의 조치 효과 확인과는 다르다. 경보가 줄어든 것을 설비가 회복한 것으로 바꾸어 설명하면 안 된다.

따라서 **회차 재편이 필요한 규모**로 판정한다. 이번 작업의 강의 개편 범위는 아래 계획까지이며 자료 일괄 재생성은 하지 않는다. 비용 측정은 최신 지시에 따라 사용자가 수행하고, 이번에는 환경·기록 도구·환산 시트만 준비한다.

## 요청한 영상의 소재와 적용 방법

확장판은 `video/lab_videos/실전반/P01_첫_데이터가_흐르는_시스템.mp4`다. ffprobe로 길이 **1603.288초(26분 43초)**를 확인했다. 원래 12분판은 `specs_archive/P01_v1_12min.json`에 남아 있다. 20→49장면으로 늘었으며, 단순히 같은 말을 길게 읽는 변화가 아니다.

| 추가된 설명 | 실습과 연결되는 이유 | 경남대에 적용할 방식 |
|---|---|---|
| 센서·단위·Hz, 파일 한 줄과 사이클 | TS1/FS1/PS1의 60·600·6000개 값 차이를 해석 | 데이터 파일을 여는 행동 옆에 붙임. 샷 데이터와 초 단위 센서를 혼동하지 않기 |
| import·dict·def·타입 힌트·reshape | 학생이 수정 요청을 할 함수의 입력/출력을 읽음 | 모든 문법을 강의하기보다 결과 판단에 필요한 줄만 설명. 에이전트가 만든 코드에도 같은 질문 적용 |
| 첫 샘플 147.21과 평균 170.16 비교 | 평균·min/max·n이 왜 필요한지 실제 숫자로 관찰 | 작은 실행 결과를 먼저 보여 주고 무엇이 손실되는지 질문 |
| SQL·파라미터·assert·pytest | 조회 범위와 완료 기준을 이해 | 테스트 통과 개수보다 어떤 약속을 검사했는지 설명 |
| 구간별 복습과 수정 후 코드 재독 | 앞에서 배운 개념이 실제 수정에 어떻게 쓰였는지 연결 | ‘요약→새 작은 사례 판단’으로 복습. 동일 문장 반복으로 온라인 4시간을 채우지 않음 |

실제 프레임에서 코드 옆 문법 풀이 카드와 수정 전후 비교를 확인했다. 반면 3분 장면의 그래프 축 글씨는 화면 내 비중이 작고, 수정 전후 코드를 양쪽에 놓으면 긴 줄이 여러 번 접힌다. **설명 흐름은 참고하되 디자인 정답으로 쓰지 않는다.** 우리 덱에서는 그래프나 중요한 한 함수가 읽히도록 장면을 나누는 편이 낫다.

이 자료의 19편 합계 약 264분은 **실습 설명 영상**이다. 학교의 온라인 이론 32H/44H를 충족한 자료로 계산하지 않는다. 온라인 대본만 만든다는 기존 요구도 그대로다. HydOps 제작 원고의 gpt-6-astra는 영상 집필용이고 학생 코딩 모델이나 서비스 모델이 아니다.

| 6. 플랫폼 연결 | 수업용 플랫폼/기관 제공 실제 환경 중 가능한 경로 선택. 조회 어댑터와 업무/앱 게시 범위 명시 | 서비스 어댑터·후반 실습·환경 운영표 | 같은 사건을 로컬/플랫폼에서 대조. 로컬 게시를 실제 상용 플랫폼 배포로 표시하지 않음 |
| 7. 설명 보강 | 첫 등장 개념, 짧은 코드/출력, 실패 이유, 수정 효과, 다음 질문을 장면 단위로 연결 | 이론 덱·온라인 대본·실습 가이드 | 화면에 없는 설명 장기 지속 방지. 학생이 위로 돌아가지 않고 실행/판정 가능 |

767장을 일괄 폐기하거나 767장을 채우는 목표로 두지 않는다. 토큰·문맥·품질·관계·RAG·권한 설명은 의미 검토 후 재사용할 수 있다. 회차 전환, 첫 사례, 데이터 수치, 조치 효과, PBL 과제는 새 흐름에 맞춰 다시 써야 한다. 전체 덱과 ZIP 생성부터 먼저 돌리면 같은 수정이 반복된다.

## 제안하는 공통 회차

모든 회차에 짧은 결과 검사를 포함한다. PBL 문제는 첫날 선택하고 이후 매일 필요한 입력·질문·화면·판정 하나씩 자신의 문제에 대응시킨다. 마지막 날에 처음 자유주제를 꺼내지 않는다.

| 공통 회차 | 학생이 만드는 것 | 다음 회차로 넘기는 것 |
|---|---|---|
| 1. 센서에서 첫 화면까지 | 제공 센서 데이터를 읽고 출처·단위·시각을 보이는 자기 화면 | 공통 관측 레코드와 첫 PBL 문제 |
| 2. 품질과 시계열 | 원본을 보존한 품질 플래그·집계·유효 구간 | 판단 가능한 관측과 보류 조건 |
| 3. 설비 관계와 원천 연결 | 질문 3개에 필요한 설비·센서·문서 관계와 조회 | 대상/출처를 찾는 맥락 도구 |
| 4. 이상 사건과 비교 | 규칙/이동 통계, 고정 구간 비교, 중복 사건 억제 | event_id와 탐지 근거 |
| 5. 사건에 맞는 문서와 Skill | 적용 대상·유효 버전 RAG, 확인 순서와 중단 지침 | 인용 가능한 근거와 판단 절차 |
| 6. 도구와 서비스 연결 | 검증된 조회를 도구로 노출, 구조화 제안, 로컬/플랫폼 조회 어댑터 | 근거가 있는 제안 |
| 7. 사람 승인과 조치 | 사건/승인값 고정, 허용 범위, 거부·중복·실패, 시뮬레이터 조치 | 실행 기록과 조치 시점 |
| 8. 새 관측으로 결과 확인 | 조치 이후 창으로 회복/미개선/데이터 부족 판정 | 같은 사건의 끝까지 이어진 이력 |
| 9. 내 서비스로 완성·게시 | 준비된 환경에 게시, 자기 문제의 새 입력과 가정 수정 | 다른 사람이 쓸 수 있는 결과물 |
| 통합반 10회 | 같은 핵심 내용의 복구·실패 비교·PBL 개선 | 새 필수 스택을 더하지 않음 |

온라인 8편/11편에 묶는 상세 분량은 이 회차 입력·출력이 확정된 뒤 설계한다. 학교 일정은 `재설계/일정별_편성표.md`에 보존한다. 평가 전용 회차를 없앤다는 뜻이 아니라 각 단계의 검사와 반례에 평가를 배치한다는 뜻이다.

## 카드 없는 운영과 비용 판단

기관 결제→LiteLLM→학생 Virtual Key라는 방향은 개인 카드 제약을 해결하는 후보로 적합하다. 다만 **코딩 접속만 중앙화해서는 학생 앱의 API·임베딩·평가 호출 및 게시 계정까지 해결되지 않는다.** 이 네 경로의 제공 주체를 운영 계약에 함께 적어야 한다.

Luna 공식 일반 단가는 입력 $0.20, 캐시 읽기 $0.02, 출력 $1.20/1M이다. 같은 문서에 272K 초과 요청의 장문 할증과 캐시 쓰기 조건도 있어, 긴 코딩 세션을 기본 단가만으로 계산하면 안 된다. 이 단가는 모델 선택의 근거 중 하나이며 이 강의에서의 완주 성공·최저 총비용을 증명하지 않는다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)

리서치 74만원은 입력 20M+출력 4M 가정으로 계산한 1인 $8.8, 60명 $528에 환율을 적용한 규모와 비슷하다. 입력을 실측한 결과가 아니다. 110~155만원 운영안과 74만원 모델안을 독립 비용처럼 더하지 않는다. 포함 범위·환율·혼합 모델 비율이 달라질 수 있다.

이번에 준비한 시트는 `실전반 인원×9일의 1인 비용 + 통합반 인원×10일의 1인 비용 + 공유 운영비`로 계산한다. 반별 인원·환율·공유 운영비는 미입력으로 두었다. 사용자 실측이 들어오기 전 전체 금액은 **미측정**이다. Gemini/Vertex의 토큰과 원가를 관측하더라도 Luna의 코딩 성공률·재시도·토크나이저 차이를 측정한 것은 아니다.

## 이번 범위의 종료와 다음 결정

이번에는 비교·수정 영향 계획과 측정 환경을 준비한다. 강의 개편 완료, 사용자 실습 완주, 60명 확정 견적은 아직 아니다. 다음 제작은 공통 데이터/조치 계약과 위 회차안에 맞춘 대표 1일차·8일차를 먼저 구체화한 뒤 전체로 확장한다. 기존 계약의 ‘실행 금지’는 이번 환경 준비/사용자 측정 역할 분담과 구별해 다음 실제 편집 때 정리한다.
