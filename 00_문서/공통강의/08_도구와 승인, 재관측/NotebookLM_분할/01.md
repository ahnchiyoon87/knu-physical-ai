# 도구와 승인, 재관측 · 공통 이론 덱

실전반(4학년)과 통합반이 함께 사용하는 내용입니다.

제작 상태: 공통 내용 집필본. 회차별 시간 배분과 전체 흐름을 검토 중입니다. 표시한 장수는 녹화 분량의 증거가 아닙니다.

삽화는 해당 장의 대상·관계·조건을 정확히 보여 주는 독창적인 장면으로 제작합니다. 아래 지시는 실제 사진이나 실측 화면의 증거가 아닙니다. 표지나 중복 목차를 임의 추가하지 않습니다.

**이 장의 결론** 도구의 책임과 승인 범위를 정하고 변경 뒤 확인한 결과를 다음 판단에 사용합니다.

## U08-S002 · 만드는 에이전트와 일하는 에이전트는 다릅니다

**화면 문구**

코딩 에이전트는 학생의 요구로 프로그램을 만듭니다. 서비스 안의 에이전트는 입력을 받아 도구를 사용하고 정한 흐름으로 업무를 처리합니다. 둘의 권한과 도구는 별도로 설계합니다.

**삽화·구성** 학생 제작 책상과 현장 업무 조사 책상을 다른 공간으로 표현하고 각각의 도구를 구별한 삽화. 두 에이전트를 하나의 만능 로봇으로 그리지 않음.

**이 장의 결론** 만드는 에이전트와 일하는 에이전트는 다릅니다.

**다음 장 연결** 학생은 코딩 에이전트에게 서비스 구현을 요청합니다

**근거·성격** 개념·근거

## U08-S003 · 학생은 코딩 에이전트에게 서비스 구현을 요청합니다

**화면 문구**

학생은 코딩 에이전트에게 서비스 구현을 요청합니다. 완성 서비스의 에이전트는 알람의 관련 기록과 문서를 찾는 일을 맡습니다.

누가 무엇을 만드는지와 서비스가 무엇을 수행하는지를 구별합니다.

**삽화·구성** 학생 제작 책상과 현장 업무 조사 책상을 다른 공간으로 표현하고 각각의 도구를 구별한 삽화. 두 에이전트를 하나의 만능 로봇으로 그리지 않음. 개념 장의 그림을 복제하지 않는다. 이번에는 사례의 대상·기록·조건을 가까이 보여 주고 수치가 있으면 원문대로 별도 텍스트로 얹는다.

**이 장의 결론** 누가 무엇을 만드는지와 서비스가 무엇을 수행하는지를 구별합니다.

**다음 장 연결** 서비스의 문서 조회 도구를 코딩 에이전트에도 반드시 붙여야 할까요?

**화면 문구**

목적과 권한이 다릅니다. 이 과정에서는 일하는 에이전트의 업무 도구로 설계합니다.

## U08-S005 · 도구 호출은 실행할 일을 구조로 요청합니다

**삽화·구성** 도구 요청 전표가 검수대를 통과해 실제 조회 작업으로 이어지는 삽화. LLM 출력이 즉시 기계를 조작하는 화살표 금지.

**이 장의 결론** 도구 호출은 실행할 일을 구조로 요청합니다.

## U08-S008 · MCP는 도구를 연결하는 약속입니다

**화면 문구**

MCP(Model Context Protocol)는 AI 애플리케이션과 외부 도구·자원을 연결하는 프로토콜입니다. 도구의 이름·설명·입력 구조 등을 전달하지만 업무 승인 정책까지 대신 정해 주지는 않습니다.

**삽화·구성** 서로 다른 다섯 작업 도구가 표준 연결부를 통해 서비스에 연결되는 세밀한 삽화. 만능 보안 방패와 자동 승인 도장은 넣지 않음.

**이 장의 결론** MCP는 도구를 연결하는 약속입니다.

**다음 장 연결** 우리 설계에서는 이벤트 조회·문서 검색·관계 조회·조치 제안·결정 기록을 하나의 MCP 서버에 모읍니다

**근거·성격** 개념·근거

**이 장의 결론** 표준 연결과 업무의 올바름은 서로 다른 책임입니다.

**다음 장 연결** 연결 형식이 같아도 결과 상태의 의미는 업무에서 정해야 합니다.
