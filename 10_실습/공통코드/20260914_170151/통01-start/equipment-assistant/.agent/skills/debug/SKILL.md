# 처음 어긋난 경계를 찾는다

사용자가 본 증상과 실제 입력·출력·요청 번호를 확인한다. 입력 원문·계약·현재 관측을 우선하고 모델이 나빴다는 가정을 먼저 두지 않는다.

1. 같은 입력과 조건에서 증상을 확인한다. 허용되지 않은 비용 실행은 반복하지 말고 기존 실행 근거와 확인하지 못한 조건을 구별한다.
2. 원천의 열·단위·범위, 현재 설정, 요청 인자가 계약과 맞는지 확인한다.
3. 요청 관측을 입력부터 읽고 출력이 다음 단계의 전제를 처음 어긴 곳을 찾는다. 마지막 오류 메시지만 고치지 않는다.
4. 후보 경계의 입력을 고정해 문제 범위를 좁힌다. 이미 지나간 정상 단계와 이후 결과를 구별한다.
5. 데이터·설정·호출 계약·로직·저장·모델 순으로 근거를 비교한다. 검사 도구가 틀릴 가능성도 확인한다.
6. 원인 위치를 수정하고 같은 계약을 쓰는 생산자와 소비자를 함께 맞춘다. 빈값·재시도·대체 모델로 문제를 숨기지 않는다.
7. 허용된 범위에서 해당 문제와 기존 기능을 다시 확인한다. 증상·처음 깨진 단계·원인 분류·수정·실제 확인 결과를 기록한다.

예상 오류를 학생에게 미리 정답처럼 알려 주거나 실패를 일부러 만들지 않는다. 재현하지 못한 원인은 추정이라고 말하고, 관측되지 않은 해결을 완료라고 쓰지 않는다.
