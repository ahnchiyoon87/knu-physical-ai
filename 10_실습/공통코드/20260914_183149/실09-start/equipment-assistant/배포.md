# Cloud Run에 같은 서비스를 옮기는 순서

이 파일은 배포 절차입니다. 배포 실행·유료 자원 생성은 이번 제작 중 하지 않았습니다. 무료 제공량과 계정 제한은 실제 수업 계정에서 확인합니다. 이미지 빌드·모델 다운로드·리비전 실행에는 비용과 시간이 들 수 있어 수업에서 실행 범위를 정합니다.

## 준비할 실제 값

| 항목 | 담을 값 | 확인할 것 |
|---|---|---|
| 외부 Postgres | Supabase 등의 영구 DB 연결 | pgvector·lab 스키마·reader 계정·체크포인트 |
| 외부 그래프 | Neo4j 영구 서버 URI·계정 | TLS·접근 정책·재시작 후 관계 |
| 런타임 계정 | Cloud Run 전용 service account | 사용할 Secret 버전 읽기 권한 |
| 이미지 | Artifact Registry의 고정 태그 | 코드·의존성·검색 모델 파일 |
| 비밀 연결 | 환경변수=Secret이름:버전 | 값 자체를 명령·저장소에 넣지 않음 |
| 원본 자료 | 수업에서 허용한 별도 저장 위치 | 로컬 컨테이너에만 보존하지 않음 |

외부 DB에서 bootstrap.py를 한 번 실행합니다. 로컬 `.env`를 덮지 말고 외부 연결용 별도 비밀 환경을 사용합니다. 스키마 작업과 런타임 계정 권한은 별도이며 서버 시작 때마다 마이그레이션하지 않습니다. 로컬 Neo4j의 Docker 볼륨은 Cloud Run으로 자동 이동하지 않습니다.

## 이미지 준비

Dockerfile은 Vue를 빌드한 뒤 Python 런타임에 결과물을 넣습니다. .env·원시 측정 파일·로컬 로그·모델 분석 결과는 이미지에 넣지 않습니다. 기본 생성 자료와 교육용 문서만 포함합니다.

```powershell
docker build --build-arg CACHE_RAG_MODELS=true -t YOUR_IMAGE_URI .
docker push YOUR_IMAGE_URI
```

YOUR_IMAGE_URI는 실제 레지스트리의 고정 버전 주소로 바꿉니다. CACHE_RAG_MODELS=true는 공개 BGE 임베딩·리랭커 파일을 이미지에 준비한다는 선택입니다. false 이미지에서는 기본 표 기능을 확인할 수 있지만 로컬 캐시가 없는 RAG 검색은 준비되지 않습니다. 준비되지 않은 기능을 모델 자동 다운로드로 숨기지 않습니다.

이 배포 이미지는 문서 검색·평가 서비스용이며 비전·Chronos 학습을 Cloud Run 요청 안에서 돌리도록 구성하지 않았습니다. models extra가 필요한 분석은 로컬 CPU 작업에서 수행하고 결과의 출처를 보존합니다. 클라우드 CPU 학습을 확장하려면 작업 실행·저장·자원 조건을 별도 명세로 정해야 합니다.

## 비밀과 배포

DATABASE_URL, READONLY_DATABASE_URL, NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD, SERVICE_TOKEN, APPROVER_TOKEN과 사용할 모델 경로의 이름·주소·키를 Secret Manager에 준비합니다. 비밀 내용을 터미널 기록으로 출력하지 않습니다. 지정한 런타임 계정에 필요한 Secret 버전의 읽기 권한을 부여합니다.

Windows는 deploy.ps1, Cloud Shell/Bash는 deploy.sh를 사용합니다. 각 스크립트의 필수 입력을 실제 프로젝트·리전·서비스·계정·이미지·비밀 연결 이름으로 채웁니다. 스크립트는 공개 접근을 열지 않고 모델 호출을 꺼진 상태로 배포합니다. 이는 아직 선택하지 않은 호출 비용이 서버 시작만으로 발생하지 않게 하는 초기 상태입니다.

첫 연결 후 수업에서 선택한 모델을 사용할 때 Cloud Run 환경의 ALLOW_MODEL_CALLS만 명시적으로 true로 변경하고 새 리비전을 배포합니다. 비밀의 실제 모델 이름과 응답 지원을 먼저 확인합니다. 내부망 전용 모델·그래프는 별도 네트워크 연결 없이는 접근할 수 없습니다.

## 접근과 확인

IAM invoker 권한이 있는 계정으로 Cloud Run 인증 프록시를 사용하거나 수업에서 정한 인증 경로로 주소를 엽니다. 앱의 SERVICE_TOKEN은 Cloud Run IAM을 대체하지 않습니다. 동료에게 보여 줄 때도 해당 사용자의 접근 권한이 먼저입니다.

확인은 `/health`의 연결 상태 다음에 표 집계 하나, 현행 문서 검색 하나, 관계 경로 하나를 읽는 순서입니다. 다음 리비전에서도 같은 표·벡터·그래프·평가 기록을 읽습니다. 통합반 9일차에는 승인 기능이 아직 없으므로 승인 대기 보존을 확인했다고 쓰지 않습니다. 10일차에 승인 기능을 추가한 뒤 실제 대기 상태를 만들어 재배포 후 재개를 확인합니다.

현재 인스턴스 `/trace`는 로컬 로그 범위입니다. Cloud Run에서 stdout으로 나가는 JSON 기록은 Cloud Logging에서 요청 번호로 검색합니다. 컨테이너가 바뀐 뒤 로컬 파일만으로 과거 로그를 볼 수 있다고 주장하지 않습니다. 표·벡터·승인·평가의 영속성과 관측 로그의 저장 경로를 구분합니다.

수업의 결과 기록에는 이미지 버전, 외부 저장소, 실행한 확인과 미확인을 적습니다. 이 절차 파일이 존재하는 것은 실제 클라우드 재시작 시험의 증거가 아닙니다.
