# 의도를 구현과 확인으로 연결한다

현재 사용자의 목적과 서비스 계약을 먼저 읽는다. 특정 구현 파일명이나 함수명을 전제하지 말고 현재 API·입력 설정·화면·요청 관측의 연결을 찾는다.

1. **Specify**: 무엇으로 성공을 확인할지 먼저 정하고 목적·입력·결과·정상/빈값/경계/실패 상황을 적는다. 사용자가 정할 판단을 대신 확정하지 않는다.
2. **Clarify**: 자료와 코드에서 확인 가능한 사실은 직접 확인한다. 미확정은 가정으로 표시하고 결과를 좌우하는 누락만 묻는다.
3. **Plan**: 현재 흐름과 변경 후 흐름, 책임 경계, 계약 양쪽, 기존 기능 유지 방법을 적는다.
4. **Tasks**: 구현과 적절한 확인을 함께 묶는다. 파일 수가 아니라 요구가 실제로 성립한 근거로 진행 상태를 기록한다.
5. **Implement**: 현재 범위의 필요한 변경을 끝까지 한다. 요구와 맞지 않는 구조를 발견하면 계획과 영향부터 고친다.
6. **Verify**: 현재 허용된 범위에서 입력·결과·근거·실패 처리를 대조한다. 모델 호출이나 완주가 금지되면 그 실행만 하지 않고 나머지 제작·검토는 진행한다.

결과에는 만든 동작, 사용자가 확인할 위치, 확인한 범위, 미검증을 남긴다. 단계마다 형식적인 승인 요청으로 멈추지 않는다. 사용자 허락 없는 비용 실행이나 외부 게시로 범위를 넓히지 않는다.
