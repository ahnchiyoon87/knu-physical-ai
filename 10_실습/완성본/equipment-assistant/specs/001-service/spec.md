# 서비스 의도와 수용 기준

표의 뜻과 관계를 확인하고 감지·검색·모델 결과를 근거로 읽으며, 사람의 결정이 반영되는 서비스를 만든다. 입력 자료가 달라져도 원천 매핑·관계·문서·판단 기준을 바꿔 같은 절차를 활용할 수 있어야 한다.

사용자가 결정하는 것은 질문 범위·비교 기준·특징·분할·규칙·근거 충분성·조치 승인이다. 구현은 서버·화면·저장·관측을 이 판단에 연결한다.

수용 기준: 등록 원천만 읽음, 의미를 확인할 수 있음, SQL과 근거가 남음, 빈 결과·누락·실패가 다름, 같은 입력의 비교가 가능함, 승인 우회와 중복 실행이 없음, 적용하지 않은 자료/모델을 사용했다고 말하지 않음.

품질 처리는 원본 보존 뷰로 두고 사용자가 analysis_view를 명시할 때 분석에 사용한다. 감지는 LOT의 적용 조건과 과거 200행 기준을 구분하고, 다채널 조합은 같은 관측 키끼리 계산한다. 예측 평가는 정답 구간을 입력에서 제외하고 직전값 기준선과 같은 구간을 비교한다.

에이전트의 교육용 권한은 0=근거 조회, 1=세 종류 검토 초안, 2=사람 승인 뒤 소프트웨어 상대 규칙 변경이다. 초물검사와 4M 문안 생성은 실제 검사·신고 수행이 아니다. 8D는 관측·후보·승인된 변경·미확인 효과를 구별한다. 저장된 초안 일부를 다시 읽는 기능과 자유로운 자연어 후속 대화는 구분해서 검토한다.

비용·GPU·학생 방식 전체 완주는 이번 제작에서 실행하지 않는다. 간단한 계산·계약 경계·문법·화면 빌드와 내용 검토만 실행 근거로 인정한다. 원본 데이터 수령 및 실제 모델 성능은 미검증이다.
