# 실전반 3일차 · 그림과 보고서가 같은 질문에 답하게 합니다

일정: 2026-11-21(토) 14:00~18:00 · 4시간
연결 이론: 영상3 · [이론 덱 목록](../../../00_문서/이론덱/README.md)

오늘 만들 것: **단위가 맞는 그래프, 항목별 SQL 심사, 출처가 연결된 두 보고서, 내 반복 절차 스킬**

## 0:00–0:20 · 오늘 작업을 엽니다

오늘부터 만들기 전에 무엇을 보면 됐다고 할지 적습니다. 명세(spec)는 구현 방법을 길게 지시하는 글이 아니라 원하는 행동과 확인 기준입니다. 예를 들어 ‘쿠션을 보여 줘’보다 ‘LOT를 바꿔도 축 단위와 선택 범위가 보인다’가 확인하기 좋습니다.

ESNS에서 오늘 공개된 Drive 링크의 **실03-start**와 이 가이드를 받습니다. 잘 이어지는 자기 프로젝트가 있으면 그것을 씁니다. 출발본은 이전 단계의 코드이므로 오늘 기능은 직접 요청해 만듭니다. 내 작업이 막혔다면 기존 폴더는 보존하고 출발본을 새 폴더에 풉니다. 두 폴더에 같은 서버를 동시에 띄우지 않습니다.

VS Code에서 오늘 작업 폴더를 열고 README의 실행 순서를 확인합니다. 이미 만든 서비스는 연결 확인에서 서버·DB 상태를 읽고, 오늘 필요한 원천 파일과 모델 준비 여부를 따로 확인합니다. 첫날 코드 없는 뼈대에서는 아직 앱 화면이 없는 것이 맞습니다. 설치가 남았다면 아래 네 문서 중 해당 단계만 마칩니다.

- [Google Cloud 세팅](../../../실습가이드핸즈온문서/1_GoogleCloud세팅.pdf)
- [VS Code와 코딩 에이전트](../../../실습가이드핸즈온문서/2_VSCode설치및_코딩에이전트세팅.pdf)
- [Docker 설치](../../../실습가이드핸즈온문서/3_도커설치및세팅.pdf)
- [실습 의존성 설치](../../../실습가이드핸즈온문서/4_실습의존성설치.pdf)

설치 뒤의 서버·자료 연결은 [실행 연결 안내](../실행_연결_안내.md)에 모았습니다. 이 문서는 설치 프로그램 설명을 반복하지 않고 실제 프로젝트의 실행과 오류 위치를 이어 줍니다.

자료를 선택할 때 synthetic은 교육용 합성, kamp는 직접 연결한 KAMP 원본입니다. 원본을 선택했는데 파일이 없으면 원본 경로를 먼저 준비합니다. 합성을 썼다면 결과에도 합성이라고 표시합니다. 특정 LOT의 실제 숫자가 가이드와 같아야 통과하는 수업은 아닙니다.

## 0:20–1:10 · 축부터 정하고 그래프를 만듭니다

시각 열이 없는 샷 자료를 시간 그래프라고 부르면 안 됩니다. 가로축은 행 또는 샷 순서, 세로축은 값과 단위입니다. LOT 경계를 잇는 선은 서로 다른 생산 묶음을 연속 변화처럼 보이게 할 수 있습니다.

**지금 해 볼 일**

쿠션 열과 LOT 하나를 고르고 그래프의 확인 기준을 spec에 적습니다. 에이전트에게 선택 범위·단위·누락 구간이 보이는 그래프를 요청합니다. 교육용 LOT 4의 급변과 LOT 5의 완만한 변화를 나란히 봅니다. 원본이라면 확인된 LOT 358·92를 사용하되 실제 관측을 먼저 확인합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

LOT 경계와 결측을 가로질러 선을 긋지 않아야 합니다. 큰 자료는 범위 선택 또는 다운샘플링 사실을 표시하고, 확대했을 때 원래 행과 대조할 수 있어야 합니다.

**막혔을 때**

그래프가 평평하면 잘못된 열, 전체 범위, 단위를 먼저 봅니다. 모양을 극적으로 만들려고 축 범위를 숨기지 않습니다.

그림이 분명해졌지만 질문의 집계가 맞는지는 별도 확인이 필요합니다.

## 1:10–2:00 · SQL을 대상·범위·계산·의미로 심사합니다

루브릭은 답이 지켜야 할 항목별 확인표입니다. SQL이 실행된다는 것과 질문에 맞는다는 것을 분리합니다. UNKNOWN은 애매한 합격이 아니라 아직 판단하지 못했다는 표시입니다.

**지금 해 볼 일**

‘LOT별 쿠션 평균’ 질문의 대상·범위·계산·의미를 먼저 써 봅니다. 모델은 항목마다 PASS/FAIL/UNKNOWN과 이유를 내고, 코드는 통과 여부를 정하도록 요청합니다. 실패하면 실패 항목을 지목한 최소 변경을 한 번 시도하고, 변경 뒤 전체 필수 항목을 다시 확인하게 합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

같은 질문을 반복했을 때 SQL 문자 모양보다 결과와 필수 조건이 같은지 봅니다. 이미 맞았던 LOT 묶음이 수리 과정에서 빠졌다면 개선으로 보지 않습니다. 검사 점수만으로 정답을 확정하지 않습니다.

**막혔을 때**

모델 심사가 흔들리면 질문·원천·표본·루브릭 버전을 먼저 고정합니다. 정답을 고정 SQL로 몰래 바꿔 놓고 모델이 나아졌다고 말하지 않습니다.

검토한 수치를 읽는 사람에 맞춰 두 보고서로 옮깁니다.

## 2:00–2:50 · 현장과 관리자의 보고서를 나눕니다

현장 보고서는 어떤 대상에서 무엇을 보고 무엇을 확인할지 담습니다. 관리자 요약은 범위와 중요한 변화, 아직 모르는 것을 짧게 보여 줍니다. 독자는 달라도 숫자의 출처는 같아야 합니다.

**지금 해 볼 일**

리포트 화면에서 원천과 LOT를 정하고 모델 설명 없이 먼저 작성합니다. 행·LOT·규칙 버전별 건수가 코드의 계산으로 나오는지 봅니다. 그다음 근거 번호가 붙은 문장만 모델이 덧붙이게 합니다. 현장 기록 형식과 한 장 요약을 구분하고 현재 화면을 인쇄하여 PDF로 저장합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

두 보고서의 대상과 분모가 같고 출처가 연결되어야 합니다. 원인 미확정은 그대로 남습니다. 규칙 버전별 경보를 더해 고유 불량 수로 부르지 않습니다.

**막혔을 때**

설명이 숫자와 다르면 문장을 먼저 보류하고 집계 근거를 확인합니다. 실제 현장 서식이 없으면 교육용 서식이라고 표시합니다.

여러 번 반복한 마무리 절차를 이제 다음 작업에서도 사용할 수 있게 정리합니다.

## 2:50–3:40 · 반복 절차를 첫 스킬로 만듭니다

스킬은 특정 상황에서 수행할 절차와 확인 방법을 적은 안내입니다. 함수명을 잔뜩 적으면 코드가 바뀔 때 깨집니다. 언제 쓰고 무엇을 확인할지를 중심으로 씁니다.

**지금 해 볼 일**

오늘 반복한 결과 정리 또는 리포트 확인 절차를 골라 leave-notes 스킬로 작성해 달라고 요청합니다. 개인 노트 제출은 없습니다. 스킬을 써 보고 싶은 사람은 ‘오늘 작업 정리해 줘’처럼 자신의 표현으로 요청하고 실제 수행 내용을 확인합니다. 과장된 완료 문장이 나오면 확인한 것과 못 확인한 것을 구분하게 고칩니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

스킬 파일이 있다는 사실과 코딩 에이전트가 실제로 읽었다는 사실을 나눕니다. 읽은 경로와 수행 결과를 확인합니다. 보고서·그래프·SQL의 같은 대상을 설명할 수 있으면 오늘 목적에 도달했습니다.

**막혔을 때**

호스트가 스킬을 자동 발견하지 못하면 파일을 명시해서 읽게 할 수 있습니다. 이를 자동 발견 성공이라고 기록하지 않습니다.

지금은 사람이 그래프를 봐야 이상을 압니다. 다음에는 규칙이 먼저 관측을 표시합니다.

## 3:40–4:00 · 오늘 결과를 설명합니다

직접 실행한 한 동선을 골라 입력→처리→결과→근거를 짧게 설명합니다. 원하는 기능을 어떻게 요청했는지, 결과를 무엇으로 확인했는지, 다음 기능과 어떻게 연결했는지, 어디까지 말할 수 있는지가 보이면 됩니다. 다른 학생과 화면이나 답 문장이 같을 필요는 없습니다.

오늘 작업을 저장합니다. 다음에 열 경로와 마지막으로 되는 동작을 README에 남기면 이어가기 쉽습니다. 개인 비교 노트나 추가 제출 형식을 따로 요구하지 않습니다. 완성본은 본인 작업과 비교할 때 사용하고, 다음 일차에는 다음 출발본으로 다시 합류할 수 있습니다.

모델 호출·학습·배포를 실제로 하지 않은 항목은 미실행으로 표시합니다. 문법 검사나 화면 빌드가 됐다는 이유로 실습 전체를 완료했다고 적지 않습니다.
