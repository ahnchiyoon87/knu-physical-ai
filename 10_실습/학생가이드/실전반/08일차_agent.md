## 0:20–1:10 · 다섯 도구가 같은 약속으로 응답하게 합니다

MCP는 도구를 공통 방식으로 발견하고 호출하는 규격입니다. 도구가 위험을 대신 판단하지는 않습니다. 업무 도구의 입력·출력과 서버의 권한 검사가 필요합니다.

**지금 해 볼 일**

query_events, search_docs, graph_path, propose_action, record_decision의 입력과 응답 상태를 읽습니다. 기존 API를 감싸는 MCP 서버로 묶고 관측 요청 번호를 유지하도록 명세를 씁니다. 사람 승인 도구는 제공하지 않습니다. 빈 사건·없는 대상·승인되지 않은 결정 기록을 각각 다르게 처리하게 합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

다섯 도구만 노출되고, record_decision 호출만으로 승인 상태가 생기지 않아야 합니다. none을 받은 뒤 원인이 없다고 단정하는 문장이 나오면 응답 계약부터 고칩니다.

**막혔을 때**

MCP 연결 실패는 도구 결과 없음과 다릅니다. 로컬 주소·포트·API 응답 형식을 먼저 확인합니다.

도구를 준비했으니 언제 어떤 도구를 쓸지 순서를 연결합니다.

합성 관계표에서는 선택 LOT → 작업일지 → `synthetic:document:FOURM` → `synthetic:document:FIRST`를 따라갈 수 있습니다. 이는 조사할 절차를 연결한 교육용 설계이며 해당 LOT에 실제 조건 변경이 있었다는 증거가 아닙니다. 관계표를 그래프에 적재한 뒤 끝 대상 ID를 입력하고, 문서의 적용 의미를 대조합니다.

## 1:10–2:00 · 진전이 없으면 멈추는 흐름을 만듭니다

LangGraph는 상태와 다음 단계를 명시하는 실행 흐름입니다. 체크포인트는 어디까지 진행했는지를 저장합니다. 승인 대기는 잠깐 기다리는 문장이 아니라 재개할 상태가 DB에 남아 있는 것입니다.

**지금 해 볼 일**

사건 조회→관계 경로→문서 근거→세 종류 초안→승인 대기→기록→재생을 연결합니다. 관계 화면에서 실제 끝 대상 ID를 확인하고 입력합니다. 자율성 0은 근거 조회, 1은 조건 변경·초물검사·4M 초안, 2는 소프트웨어 상대 규칙 폭 변경을 사람 승인에 연결합니다. 이는 교육용 정책입니다. 어떤 수준에서도 실제 검사·신고·설비 변경을 수행했다고 표시하지 않습니다. 전체 걸음은 8 이하로 정합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

근거가 부족하면 제안 전에 멈추고, 같은 단계에서 반복하면 종료 이유가 남아야 합니다. thread_id를 저장하고 서버 재시작 뒤 승인 대기가 남는지 실제 수업 실행에서 확인합니다.

**막혔을 때**

결정 기록이 두 번 생기면 재개 때 다시 실행되는 노드 안에 부수 효과가 있는지 봅니다. 중단 전 준비와 중단 후 기록을 분리합니다.

이제 사람이 실제로 무엇에 동의하는지 정확히 묶습니다.

## 2:00–2:50 · 승인한 바로 그 제안만 기록합니다

가드레일은 제안 뒤 실행 전에 약속 위반을 확인하는 조건입니다. 버전과 해시는 승인 대상이 바뀌지 않았는지 확인하는 표식입니다. 승인 버튼을 눌렀다는 사실만으로 모든 미래 제안을 승인한 것이 아닙니다.

**지금 해 볼 일**

사람 승인 화면에서 제안의 대상·기존 값·새 값·근거·버전·해시를 읽습니다. 별도 승인 토큰으로 승인 또는 반려하고 이름과 이유를 남깁니다. 에이전트 화면에서 같은 thread_id와 proposal_id로 재개합니다. 승인 전 규칙이 바뀌지 않는지, 오래된 버전이면 다시 판단을 요구하는지 확인합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

승인·기록·규칙 변경이 같은 제안을 가리켜야 합니다. 같은 재개를 반복해도 변경이 한 번만 기록됩니다. 표 질문의 후속 문맥은 원천을 바꾸면 초기화하고 이전 필터를 몰래 적용하지 않습니다.

**막혔을 때**

승인 토큰을 서비스 모델이나 도구 인자로 보내지 않습니다. 승인 후 실패라면 결정 저장 여부와 재생 실패를 나눠 읽습니다.

한 바퀴가 끝났는지 통지 수 하나가 아니라 요청 전체로 확인합니다.

폐루프는 관측→판단→조치→다시 관측의 연결입니다. 이 수업의 조치는 교육용 규칙 갱신과 동일 입력 재생입니다. 실제 설비를 제어하거나 생산 품질 개선을 검증한 것은 아닙니다.
