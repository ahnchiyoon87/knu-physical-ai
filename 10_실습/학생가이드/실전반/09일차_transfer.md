# 실전반 9일차 · 다른 데이터에서도 쓸 수 있는 능력을 확인합니다

일정: 2027-01-29(금) 14:00~18:00 · 4시간
연결 이론: 새 영상 없음 · 앞선 내용 적용 · [이론 덱 목록](../../../00_문서/이론덱/README.md)

오늘 만들 것: **새 원천 연결, 제조 가정 수정, 다른 주제의 작은 서비스와 사용 설명**

## 0:00–0:20 · 오늘 작업을 엽니다

오늘은 정해진 화면을 똑같이 만드는 날이 아닙니다. 같은 기술로 다른 문제를 해결하는 것이 목적입니다. 힌트를 늘리기보다 무엇이 작동하고 무엇이 아직 안 되는지 스스로 구분합니다.

ESNS에서 오늘 공개된 Drive 링크의 **실09-start**와 이 가이드를 받습니다. 잘 이어지는 자기 프로젝트가 있으면 그것을 씁니다. 출발본은 이전 단계의 코드이므로 오늘 기능은 직접 요청해 만듭니다. 내 작업이 막혔다면 기존 폴더는 보존하고 출발본을 새 폴더에 풉니다. 두 폴더에 같은 서버를 동시에 띄우지 않습니다.

VS Code에서 오늘 작업 폴더를 열고 README의 실행 순서를 확인합니다. 이미 만든 서비스는 연결 확인에서 서버·DB 상태를 읽고, 오늘 필요한 원천 파일과 모델 준비 여부를 따로 확인합니다. 첫날 코드 없는 뼈대에서는 아직 앱 화면이 없는 것이 맞습니다. 설치가 남았다면 아래 네 문서 중 해당 단계만 마칩니다.

- [Google Cloud 세팅](../../../실습가이드핸즈온문서/1_GoogleCloud세팅.pdf)
- [VS Code와 코딩 에이전트](../../../실습가이드핸즈온문서/2_VSCode설치및_코딩에이전트세팅.pdf)
- [Docker 설치](../../../실습가이드핸즈온문서/3_도커설치및세팅.pdf)
- [실습 의존성 설치](../../../실습가이드핸즈온문서/4_실습의존성설치.pdf)

설치 뒤의 서버·자료 연결은 [실행 연결 안내](../실행_연결_안내.md)에 모았습니다. 이 문서는 설치 프로그램 설명을 반복하지 않고 실제 프로젝트의 실행과 오류 위치를 이어 줍니다.

자료를 선택할 때 synthetic은 교육용 합성, kamp는 직접 연결한 KAMP 원본입니다. 원본을 선택했는데 파일이 없으면 원본 경로를 먼저 준비합니다. 합성을 썼다면 결과에도 합성이라고 표시합니다. 특정 LOT의 실제 숫자가 가이드와 같아야 통과하는 수업은 아닙니다.

## 0:20–1:10 · 새 원천의 기능 전제를 읽습니다

이식은 입력 자료를 바꿔도 기존 기능이 성립하는지 확인하는 일입니다. 파일을 읽을 수 있다는 사실만으로 라벨·시간·관계가 필요한 모든 기능을 쓸 수 있는 것은 아닙니다.

**지금 해 볼 일**

기업에서 제공받은 사용 가능한 자료 또는 공개 자료 한 벌을 고릅니다. 없다면 제공한 transfer 자료부터 시작합니다. mapping의 원천·열·키·단위·라벨·문서 상태를 작성하고 data_check를 실행합니다. 기능별 됨·안 됨·부분과 이유를 읽습니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

준비되지 않은 기능을 합성 값으로 채워 초록으로 만들지 않습니다. 실제 파일과 설정이 맞는지, 없는 전제가 무엇인지 구분할 수 있어야 합니다.

**막혔을 때**

경로 오류와 데이터에 없는 개념을 구분합니다. 이 블록은 정답 구현 힌트 없이 자신의 기준으로 진행합니다.

읽을 수 있는데도 실패하는 기능에서 숨은 가정을 찾습니다.

## 1:10–2:00 · 데이터에 묶인 가정을 고칩니다

전이는 배운 판단 방법을 다른 문제에 적용하는 일입니다. 제조용 ‘LOT’는 도서관의 ‘대출’과 같은 개념이 아닙니다. 이름만 바꾸면 의미가 달라진 계산이 그대로 남을 수 있습니다.

**지금 해 볼 일**

표 질문·그래프·규칙 중 새 원천에서 깨지는 기능 하나를 고릅니다. 코드의 고정 열 번호, LOT 접두어, 단위, 기준값 중 어떤 가정 때문인지 찾습니다. 명세와 관련 검사를 먼저 바꾸고 수정 전후를 비교합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

새 주제에서 맞는 기능과 제조에서만 맞는 기능이 구분되어야 합니다. 기존 제조 기능도 유지할 필요가 있다면 원천별 설정으로 나누고 관련 검사를 확인합니다.

**막혔을 때**

모든 제조 단어를 일괄 치환하지 않습니다. 같은 단어라도 UI 표현인지 계산 조건인지 먼저 가릅니다.

이제 다른 주제의 실제 질문과 기준을 넣습니다.

## 2:00–2:50 · 표·문서·규칙을 새 문제로 연결합니다

서비스의 규칙은 데이터 숫자에서 저절로 나오지 않습니다. 도서관의 연장 가능 여부는 대출 기간뿐 아니라 규정과 상태가 필요합니다. 없는 정보는 부족하다고 말하는 기능도 결과물입니다.

**지금 해 볼 일**

books·loans와 규정 문서를 읽고 해결할 질문 하나를 정합니다. 예를 들어 어떤 대출이 확인 대상인지, 연장 가능 판단에 무엇이 더 필요한지 묻습니다. 열 사전·관계·문서·질문셋을 새 목적에 맞춰 바꿉니다. 제공 days_from_due는 설계된 기준일 대비 값이며 오늘 날짜가 아닙니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

모든 기록은 가상임을 표시하고, 필요한 기준일이나 상태가 없으면 확정 답변을 내지 않습니다. 대규모 스키마 검색 카드는 표가 많아질 때의 다음 학습 방향으로만 읽습니다.

**막혔을 때**

한 번에 서비스 전체를 옮기기 어렵다면 사용자가 할 수 있는 한 작업을 끝까지 연결합니다. 연결하지 않은 기능은 설명에서 제외합니다.

마지막에는 다른 사람이 사용할 수 있게 결과를 설명합니다.

## 2:50–3:40 · 내 서비스의 범위와 다음 한 걸음을 말합니다

사용 설명은 구현한 함수 목록보다 누가 어떤 상황에서 무엇을 할 수 있는지 알려 주는 글입니다. 잘 안 되는 조건과 더 필요한 자료를 함께 쓰면 다음 개발의 출발점이 됩니다.

**지금 해 볼 일**

README에 사용자·상황·입력·행동·확인할 결과·제한을 적습니다. ‘나는 무엇을 만들었고, 누가 언제 쓰며, 무엇이 어려웠고 어떻게 풀었으며, 무엇은 더 필요한가’를 자신의 사례로 설명합니다. 완성 화면이 다른 학생과 같을 필요는 없습니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

실제로 만든 기능과 예정 기능을 나눠 설명할 수 있어야 합니다. 다른 주제에서 그대로 쓴 약속과 고친 가정을 각각 보여 주면 됩니다. 추가 노트 제출 형식은 없습니다.

**막혔을 때**

작동하지 않은 부분을 숨긴 긴 기능 목록보다 확인한 작은 동선을 구체적으로 설명합니다.

이 결과가 개인 PBL의 첫 버전입니다. 다음에는 새 사용자의 질문으로 명세를 다시 고칩니다.

## 3:40–4:00 · 오늘 결과를 설명합니다

직접 실행한 한 동선을 골라 입력→처리→결과→근거를 짧게 설명합니다. 원하는 기능을 어떻게 요청했는지, 결과를 무엇으로 확인했는지, 다음 기능과 어떻게 연결했는지, 어디까지 말할 수 있는지가 보이면 됩니다. 다른 학생과 화면이나 답 문장이 같을 필요는 없습니다.

오늘 작업을 저장합니다. 다음에 열 경로와 마지막으로 되는 동작을 README에 남기면 이어가기 쉽습니다. 개인 비교 노트나 추가 제출 형식을 따로 요구하지 않습니다. 완성본은 본인 작업과 비교할 때 사용하고, 다음 일차에는 다음 출발본으로 다시 합류할 수 있습니다.

모델 호출·학습·배포를 실제로 하지 않은 항목은 미실행으로 표시합니다. 문법 검사나 화면 빌드가 됐다는 이유로 실습 전체를 완료했다고 적지 않습니다.
