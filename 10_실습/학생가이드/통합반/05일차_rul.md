# 통합반 5일차 · 미래 값을 예측하되 실제 수명을 지어내지 않습니다

일정: 2027-01-28(목) 09:00~13:00 · 4시간

오늘 만들 것: **C-MAPSS RUL 기준 실험, 샷 임계 도달 예측, 불확실성 비교와 정비 판단의 범위**

## 0:00–0:20 · 오늘 작업을 엽니다

RUL은 Remaining Useful Life, 정한 고장 기준까지 남은 수명입니다. 고장에 도달한 기록과 그 기준이 있어야 정답을 만들 수 있습니다. 사출 샷 자료에 그런 이력이 없다면 미래 쿠션 값의 임계 도달과 실제 고장 수명을 구분합니다.

ESNS에서 오늘 공개된 Drive 링크의 **통05-start**와 이 가이드를 받습니다. 잘 이어지는 자기 프로젝트가 있으면 그것을 씁니다. 출발본은 이전 단계의 코드이므로 오늘 기능은 직접 요청해 만듭니다. 내 작업이 막혔다면 기존 폴더는 보존하고 출발본을 새 폴더에 풉니다. 두 폴더에 같은 서버를 동시에 띄우지 않습니다.

VS Code에서 오늘 작업 폴더를 열고 README의 실행 순서를 확인합니다. 이미 만든 서비스는 연결 확인에서 서버·DB 상태를 읽고, 오늘 필요한 원천 파일과 모델 준비 여부를 따로 확인합니다. 첫날 코드 없는 뼈대에서는 아직 앱 화면이 없는 것이 맞습니다. 설치가 남았다면 아래 네 문서 중 해당 단계만 마칩니다.

- [Google Cloud 세팅](../../../실습가이드핸즈온문서/1_GoogleCloud세팅.pdf)
- [VS Code와 코딩 에이전트](../../../실습가이드핸즈온문서/2_VSCode설치및_코딩에이전트세팅.pdf)
- [Docker 설치](../../../실습가이드핸즈온문서/3_도커설치및세팅.pdf)
- [실습 의존성 설치](../../../실습가이드핸즈온문서/4_실습의존성설치.pdf)

설치 뒤의 서버·자료 연결은 [실행 연결 안내](../실행_연결_안내.md)에 모았습니다. 이 문서는 설치 프로그램 설명을 반복하지 않고 실제 프로젝트의 실행과 오류 위치를 이어 줍니다.

자료를 선택할 때 synthetic은 교육용 합성, kamp는 직접 연결한 KAMP 원본입니다. 원본을 선택했는데 파일이 없으면 원본 경로를 먼저 준비합니다. 합성을 썼다면 결과에도 합성이라고 표시합니다. 특정 LOT의 실제 숫자가 가이드와 같아야 통과하는 수업은 아닙니다.

## 0:20–1:10 · 수명 정답이 있는 다른 자료에서 방법을 봅니다

C-MAPSS는 항공엔진 열화 시뮬레이션 자료입니다. 장비별 마지막 사이클과 현재 사이클의 차이로 학습 RUL을 만들고, 평가 장비의 마지막 관측 뒤 남은 사이클 정답으로 확인합니다. 다른 도메인에서 방법을 배우는 실험입니다.

**지금 해 볼 일**

공식 자료의 train·test·RUL 파일을 mapping 경로에 준비합니다. FD001처럼 부분집합 하나와 센서 위치를 선택하고 RUL 분석을 실행합니다. 장비 ID와 정답을 입력 특징에서 제외하고 평가 장비가 학습 장비와 섞이지 않게 합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

MAE·RMSE의 단위는 cycle이며 사출 장비의 시간이나 잔여 샷 수가 아닙니다. 평가 장비 수와 정답 수가 맞아야 합니다.

**막혔을 때**

원본 파일이 없으면 이 블록의 실행을 미준비로 둡니다. 샷 합성 자료의 마지막 행을 고장 시점으로 가정해 대신 실행하지 않습니다.

방법을 배웠으니 우리 자료에서 실제로 답할 수 있는 질문으로 좁힙니다.

## 1:10–2:00 · 임계에 도달할 샷 순서를 예측합니다

Chronos의 미래 값에서 임계를 처음 넘는 위치를 찾으면 예측 범위 내 도달 순서를 얻습니다. 범위 안에서 넘지 않는 경우는 무한 수명이나 안전이 아니라 그 범위에서 도달 예측이 없다는 뜻입니다.

**지금 해 볼 일**

합성 변화 구간의 입력 끝과 임계값·방향을 정합니다. 분석 화면에서 threshold를 선택하고 중앙 예측·하한·상한의 도달 위치를 읽습니다. 원본의 완만한 변화에도 같은 질문을 하되 장기 마모의 증거가 없다는 제한을 함께 표시합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

가로축은 다음 샷 순서입니다. null 도달 값을 0 또는 고장 없음으로 바꾸지 않습니다. 합성에서 관찰한 결과를 원본 설비 성능으로 보고하지 않습니다.

**막혔을 때**

모든 곡선이 바로 넘으면 입력 마지막 값이 이미 임계 밖인지 확인합니다. 기준을 결과에 맞춰 바꾸지 않습니다.

이 결과가 정비 요청을 뒷받침하려면 무엇이 더 필요한지 연결합니다.

## 2:00–2:50 · 정비 계획과 관측 근거를 분리합니다

예측은 판단 자료이고 정비 계획은 비용·가동 일정·검사 결과를 포함한 결정입니다. 예측 하나로 부품 교체 시점을 확정하면 빠진 전제가 많습니다.

**지금 해 볼 일**

예측 결과→대상 부품 또는 원천 관계를 정합니다. 작업일지의 실제 검사 기록이 있는 경우에만 대조하고, 없는 검사 결과를 새로 만들지 않습니다. 정비 계획 초안에는 예측 범위·확인할 검사·결정할 사람을 구분합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

관측·예측·사람 결정이 서로 다른 항목으로 보입니다. C-MAPSS 결과에 사출 LOT 출처가 붙지 않아야 합니다.

**막혔을 때**

부품과 연결할 근거가 없으면 원천 수준의 결과로 남깁니다. 근거 없는 부품 이름을 그래프에 넣어 구체적으로 보이게 하지 않습니다.

한 번의 예측이 얼마나 흔들리는지도 확인합니다.

## 2:50–3:40 · 입력 구간을 바꾸고 불확실성을 읽습니다

예측 구간은 모델이 내놓은 분위수 범위입니다. 실제 값이 그 안에 몇 퍼센트 들어가는지는 별도 검증이 필요합니다. 입력 구간을 조금 바꿨을 때 결론이 뒤집히면 결정에 더 신중해야 합니다.

**지금 해 볼 일**

같은 목표 구간에 대해 학습에 제공하는 과거 길이를 두 가지로 정합니다. 중앙 예측과 범위 폭, 임계 도달의 변화가 보이게 비교합니다. ‘현장에 보여 준다면 어떤 제한 문구와 추가 검사로 설명할까’를 자신의 결과로 답합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

예측값만큼 범위가 넓거나 도달 여부가 뒤집히면 그 불안정성을 숨기지 않습니다. 고장 확률을 추정할 근거가 없는 구현에서는 확률 숫자를 만들지 않습니다.

**막혔을 때**

비교의 목표 구간 자체가 달라졌는지 확인합니다. 입력 끝을 바꾸면서 서로 다른 미래를 같은 예측이라고 비교하지 않습니다.

다음에는 수집·감지·예측을 한 서비스에서 같은 상태 계약으로 연결합니다.
