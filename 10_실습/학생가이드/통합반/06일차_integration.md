# 통합반 6일차 · 여러 기능을 하나의 확인 가능한 시스템으로 잇습니다

일정: 2027-01-29(금) 09:00~13:00 · 4시간
연결 이론: 영상6 · [이론 덱 목록](../../../00_문서/이론덱/README.md)

오늘 만들 것: **명세·계획·할 일과 연결된 수집·감지·예측 흐름, 단계 실패 검사, 요청 단위 관측**

## 0:00–0:20 · 오늘 작업을 엽니다

기능 버튼 세 개가 있다고 시스템이 연결된 것은 아닙니다. 같은 입력이 어느 단계를 거쳤고 어디서 멈췄는지 읽을 수 있어야 합니다. 오늘은 명세→계획→할 일→구현→확인을 한 번에 연결합니다.

ESNS에서 오늘 공개된 Drive 링크의 **통06-start**와 이 가이드를 받습니다. 잘 이어지는 자기 프로젝트가 있으면 그것을 씁니다. 출발본은 이전 단계의 코드이므로 오늘 기능은 직접 요청해 만듭니다. 내 작업이 막혔다면 기존 폴더는 보존하고 출발본을 새 폴더에 풉니다. 두 폴더에 같은 서버를 동시에 띄우지 않습니다.

VS Code에서 오늘 작업 폴더를 열고 README의 실행 순서를 확인합니다. 이미 만든 서비스는 연결 확인에서 서버·DB 상태를 읽고, 오늘 필요한 원천 파일과 모델 준비 여부를 따로 확인합니다. 첫날 코드 없는 뼈대에서는 아직 앱 화면이 없는 것이 맞습니다. 설치가 남았다면 아래 네 문서 중 해당 단계만 마칩니다.

- [Google Cloud 세팅](../../../실습가이드핸즈온문서/1_GoogleCloud세팅.pdf)
- [VS Code와 코딩 에이전트](../../../실습가이드핸즈온문서/2_VSCode설치및_코딩에이전트세팅.pdf)
- [Docker 설치](../../../실습가이드핸즈온문서/3_도커설치및세팅.pdf)
- [실습 의존성 설치](../../../실습가이드핸즈온문서/4_실습의존성설치.pdf)

설치 뒤의 서버·자료 연결은 [실행 연결 안내](../실행_연결_안내.md)에 모았습니다. 이 문서는 설치 프로그램 설명을 반복하지 않고 실제 프로젝트의 실행과 오류 위치를 이어 줍니다.

자료를 선택할 때 synthetic은 교육용 합성, kamp는 직접 연결한 KAMP 원본입니다. 원본을 선택했는데 파일이 없으면 원본 경로를 먼저 준비합니다. 합성을 썼다면 결과에도 합성이라고 표시합니다. 특정 LOT의 실제 숫자가 가이드와 같아야 통과하는 수업은 아닙니다.

## 0:20–1:10 · 계획에 책임과 확인 기준을 적습니다

spec은 원하는 행동, plan은 현재에서 그 행동으로 가는 구조와 책임, tasks는 실행할 일과 완료 근거입니다. 파일 세 개를 만드는 것이 목적이 아니라 바꿀 범위와 확인 방법을 함께 정하는 것입니다.

**지금 해 볼 일**

현재 수집·규칙·예측의 입력과 출력을 에이전트에게 읽게 합니다. 새 흐름을 spec에, 담당 모듈과 데이터 이동을 plan에, 확인할 결과를 tasks에 적습니다. 화면·로그·작은 검사 중 어떤 근거가 각 할 일에 맞는지 선택합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

‘구현한다’만 있는 할 일을 실제로 무엇이 보이면 끝인지 바꿉니다. 모델 실행이 필요한 증거와 문법 검사만으로 가능한 증거를 구분합니다.

**막혔을 때**

에이전트가 현재 코드에 없는 동작을 설명하면 해당 파일과 주소를 확인하게 합니다. 계획 문장의 완료 시제를 사실로 받아들이지 않습니다.

가장 중요한 단계 실패 조건부터 연결합니다.

## 1:10–2:00 · 한 단계가 비면 전체 완료를 멈춥니다

시스템의 성공은 필요한 단계가 모두 계약을 만족한 상태입니다. 선택적으로 제외한 단계와 실행하다 실패한 단계를 같은 회색으로 가리지 않습니다.

**지금 해 볼 일**

행이 없는 입력, 기준 구간 부족, 예측 모델 미준비 중 하나를 선택합니다. 해당 단계가 insufficient 또는 failed로 끝나고 뒤 단계가 실행되지 않는 검사를 요청합니다. 정상 입력과 실패 입력을 각각 하나씩 둡니다. 예측 최소 입력 길이는 명세와 config에서 하나로 관리합니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

마지막 함수가 종료됐다는 이유만으로 전체 초록이 되지 않습니다. 입력 부족과 시스템 오류의 이유가 구분됩니다.

**막혔을 때**

검사에서 모델을 호출할 필요가 없다면 단계 경계만 확인합니다. 이 검사를 실제 예측 성공 증거로 쓰지 않습니다.

상태를 정했으니 화면과 관측 기록에 같은 의미로 보이게 합니다.

## 2:00–2:50 · 요청 하나를 처음부터 끝까지 읽습니다

관측은 서비스 안에서 어떤 단계가 얼마의 입력을 받아 무엇을 냈는지 남기는 일입니다. 요청 번호가 같아야 여러 기록을 한 실행으로 이어 읽을 수 있습니다.

**지금 해 볼 일**

한 실행의 적재·감지·예측 결과를 같은 화면에 놓고 단계마다 규칙 계산·모델 추론·사람 판단을 표시합니다. 요청 관측에서 단계·시간·입출력 수·모델명을 확인합니다. 키와 문서 원문 전체는 관측용으로 남기지 않습니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

실패한 단계가 어디인지 화면과 로그가 일치해야 합니다. 모델 호출이 없는 단계의 비용을 실제 0원 측정처럼 표시하지 않습니다.

**막혔을 때**

기록이 여러 요청에 섞이면 요청 번호가 중간 도구에서 바뀌는지 봅니다. 총 소요 시간만으로 모델이 느렸다고 단정하지 않습니다.

연결 뒤에도 앞서 얻은 결과가 유지되는지 확인합니다.

예측을 같은 실행에 묶을 때는 원하는 분석 설정을 JSON 파일로 저장하도록 에이전트에게 요청합니다. 예를 들어 `forecast.json`에 선택 LOT·열 번호·horizon을 넣고 `uv run --env-file .env python scripts/reload.py --profile synthetic --source shots --rule cushion-relative --predict forecast --parameters forecast.json`을 실행합니다. `--predict`를 빼면 예측을 요청하지 않은 실행이며, 요청한 예측이 실패하면 감지 완료와 예측 부족을 나눠 반환해야 합니다.

## 2:50–3:40 · 앞선 비교를 완료 근거로 다시 읽습니다

통합하면 입력 필터나 상태 전달이 바뀔 수 있습니다. 개별 버튼에서 얻은 결과가 새 흐름에서 같은 조건인지 확인하는 것이 통합 검토입니다.

**지금 해 볼 일**

규칙·추세 비교와 임계 예측에서 사용한 입력을 고정합니다. 통합 흐름의 결과와 차이가 있다면 필터·분할·모델 설정을 먼저 대조합니다. tasks에는 실제 확인한 근거와 미확인 범위를 나눠 적습니다.

에이전트에게 줄 요청은 자신의 말로 씁니다. 원하는 행동과 무엇을 보면 됐다고 할지를 전달하고, 나온 이해가 다르면 바로잡습니다. 구현 문법을 직접 완성할 필요는 없습니다.

**됐는지 확인합니다**

완료 체크는 결과가 존재할 때만 합니다. 자료나 모델이 준비되지 않은 항목은 구현 파일이 있어도 실행 확인 대기로 둡니다.

**막혔을 때**

수치를 맞추려고 이전 기록을 바꾸지 않습니다. 조건 차이가 있으면 그 이유를 남깁니다.

다음에는 이 사건에 관련된 문서 근거를 서비스에 붙입니다.

## 3:40–4:00 · 오늘 결과를 설명합니다

직접 실행한 한 동선을 골라 입력→처리→결과→근거를 짧게 설명합니다. 원하는 기능을 어떻게 요청했는지, 결과를 무엇으로 확인했는지, 다음 기능과 어떻게 연결했는지, 어디까지 말할 수 있는지가 보이면 됩니다. 다른 학생과 화면이나 답 문장이 같을 필요는 없습니다.

오늘 작업을 저장합니다. 다음에 열 경로와 마지막으로 되는 동작을 README에 남기면 이어가기 쉽습니다. 개인 비교 노트나 추가 제출 형식을 따로 요구하지 않습니다. 완성본은 본인 작업과 비교할 때 사용하고, 다음 일차에는 다음 출발본으로 다시 합류할 수 있습니다.

모델 호출·학습·배포를 실제로 하지 않은 항목은 미실행으로 표시합니다. 문법 검사나 화면 빌드가 됐다는 이유로 실습 전체를 완료했다고 적지 않습니다.
