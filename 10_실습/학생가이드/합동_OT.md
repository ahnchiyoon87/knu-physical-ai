# 합동 OT · 내 컴퓨터에서 만들 준비를 합니다

2026-09-29(화), 두 반 합동 2시간입니다. 시작 시각은 일정표에 확정되어 있지 않습니다. 같은 합동 행사를 두 번 참석하는 것이 아닙니다.

## 0:00–0:35 · 우리가 만들 서비스의 질문을 봅니다

기계가 남긴 숫자만으로는 현장 질문에 바로 답하기 어렵습니다. 숫자의 뜻을 읽고, 작업 기록과 문서를 연결하고, 근거를 확인한 뒤 판단해야 합니다. 피지컬 AI는 물리 세계의 관측과 행동을 연결하는 넓은 주제입니다. 이 과정에서는 설비 자료를 읽고 대응을 제안하는 서비스를 만들며 그 판단 구조를 배웁니다. 실제 로봇 제어나 자동 공정 변경을 완료했다고 표현하지 않습니다.

LLM은 문장을 생성하는 모델이고, 코딩 에이전트는 여러분의 요청으로 코드를 읽고 만드는 도구입니다. 여러분이 맡을 일은 무엇을 만들지, 어떤 결과가 맞는지, 어디까지 말할 수 있는지 정하는 것입니다. 프로그램 문법을 외워 같은 코드를 타이핑하는 수업은 아닙니다.

‘이상한 LOT는 무엇인가’, ‘그때 어떤 절차를 확인해야 하나’, ‘조건을 바꿔도 되나’ 세 질문을 봅니다. 첫 질문은 표, 두 번째는 문서와 관계, 세 번째는 사람의 결정이 필요합니다. 이런 구분은 나중에 도서관 안내나 자신의 PBL에도 옮길 수 있습니다.

## 0:35–1:20 · 설치 상태를 연결합니다

ESNS에서 OT 자료 링크를 받고 빈 프로젝트 폴더를 자신의 작업 위치에 풉니다. 오늘 뼈대에 앱 코드가 없는 것은 정상입니다. 먼저 아래 네 문서의 설치를 확인합니다.

1. [Google Cloud 세팅](../../실습가이드핸즈온문서/1_GoogleCloud세팅.pdf): 사용할 계정과 프로젝트를 확인합니다. 클라우드 배포는 해당 일차에 진행합니다.
2. [VS Code와 코딩 에이전트](../../실습가이드핸즈온문서/2_VSCode설치및_코딩에이전트세팅.pdf): 폴더를 열고 코딩 에이전트에게 폴더의 목적을 설명하도록 요청합니다.
3. [Docker](../../실습가이드핸즈온문서/3_도커설치및세팅.pdf): 로컬 데이터베이스를 실행할 기반입니다. 앱 창이 열린 것과 엔진이 준비된 것은 다르므로 상태를 확인합니다.
4. [의존성 설치](../../실습가이드핸즈온문서/4_실습의존성설치.pdf): Python·uv·Node 등 실제 프로젝트에 필요한 도구를 확인합니다.

설치가 이미 된 사람은 에이전트에게 `constitution.md`, `AGENTS.md`, `mapping.json`의 역할을 읽고 설명하게 합니다. 헌법은 서비스의 약속, 작업 지침은 코드를 만들 때의 절차, mapping은 자료의 뜻과 연결을 담습니다. 긴 파일을 암기할 필요는 없습니다. 어떤 문제가 생겼을 때 어디를 찾아야 하는지 알면 됩니다.

## 1:20–1:50 · 내 작업을 보존하고 다시 여는 연습을 합니다

Git은 작업 상태를 기록하는 도구이고 GitHub는 저장소를 올려 둘 수 있는 서비스입니다. 외부 업로드 여부는 자신의 계정과 수업 안내에 맞춰 정합니다. 오늘은 로컬에서 새 연습 메모를 저장하고 변경 내용을 보는 것부터 해 봅니다. 자기 작업 전체를 지우는 명령으로 복구 연습을 하지 않습니다.

작업이 엉켰을 때는 기존 폴더를 남겨 두고 같은 일차 출발본을 새 폴더에서 열 수 있습니다. 이전 날을 빠졌더라도 다음 날의 출발본은 그날 바로 시작할 수 있는 이전 단계 코드를 제공합니다. 두 폴더의 서버를 같은 포트로 동시에 띄우면 충돌하므로 하나를 먼저 종료합니다.

비밀키는 로컬 `.env`에 보관하며 자료 파일에 적지 않습니다. 서비스에서 답하는 모델과 코딩 에이전트가 쓰는 모델은 별개입니다. 서비스의 모델 이름을 추정해서 넣거나 실패했을 때 자동으로 다른 모델로 바꾸지 않습니다.

## 1:50–2:00 · 첫 수업을 준비합니다

첫 영상에서는 한 행·한 열·LOT·열 사전의 관계를 봅니다. 영상을 놓쳤더라도 첫날 실습가이드가 필요한 개념을 행동 옆에서 다시 설명합니다. 먼저 자신의 데이터에서 물어보고 싶은 질문 하나를 생각해 오면 됩니다.

오늘 확인할 것은 VS Code에서 올바른 폴더가 열리는지, 코딩 에이전트가 프로젝트 설명을 읽는지, Docker와 필요한 도구가 준비됐는지입니다. 아직 만들지 않은 앱의 실행을 성공으로 표시하지 않습니다. 설치가 남은 항목은 첫 실패 메시지를 확인해 다음 연결 단계에서 마칩니다.
