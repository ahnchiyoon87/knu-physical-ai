# 리뉴얼 제작 기준

기준일: 2026-09-14. 이 문서는 현재 사용자 요청과 제공 ZIP을 이 프로젝트의 작업 기준으로 연결한다. 원본 ZIP의 내용을 고치거나 과거 문서의 권위를 덮어쓴 사본으로 만들지 않는다.

## 목적과 현재 범위

기존 9월 본강은 일정 확정 전에 만든 자료다. 잘못된 설계를 수선하는 작업으로 보지 않는다. 실제 일정과 새 방향에 맞춰 별도 프로젝트에서 새로 제작한다. 기존 본강의 `00_문서 / 10_실습 / 20_도구 / 30_기록` 구조만 참고한다. 기존 코드도 필요한 부분의 의미와 적합성을 검토한 경우에만 참고하며, 이번 이론 덱에는 기존 본강 코드·본문·시나리오를 재사용하지 않았다.

전체 목표는 비컴공 학생이 LLM·RAG·그래프·에이전트를 활용해 자기 문제의 서비스를 다시 만들 수 있게 하는 것이다. 현재 사용자의 마지막 지시인 “오늘 일단 덱”에 따라 이번 산출물은 **반별 이론 영상 19편의 상세 Markdown 덱**이다. PPTX·낭독 대본·신규 실습코드·일차별 실행 가이드의 제작 완료를 뜻하지 않는다.

## 원문과 우선순위

1. 2026-09-14 사용자 요청: 전면 개편, 일정에 맞는 이론, 판단 중심 실습, 자연스러운 설명, 일차별 합류, 비싼 모델 실행 금지, 오늘 덱 우선.
2. ZIP `참고/KNU_PhysicalAI_uEngine.xlsx`: 상세 일정·회차명·반·시수·영상 연결. 개요와 충돌하는 날짜는 서로 일치하는 상세 일정·커리큘럼·캘린더를 기준으로 한다.
3. ZIP `실습흐름_정본.html`, `00-0_지시문_에이전트에게.md`, `00-1_방향_대화정리_20260912.md`, 설계서: 새 서비스와 교육 흐름의 재료. 최신 요청과 다른 의무나 실제 근거가 부족한 단정은 그대로 승계하지 않는다.
4. ZIP 리서치: 제공자가 남긴 조사·측정 기록. 이번 작업의 신규 실측과 구별한다.
5. 리허설 `최종 END/2일차 슬라이드.pptx`: 제목·결론·다음 장의 연결, 설명이 화면에 남는 방식만 참고한다. 디자인·도형·실측값·CNC 사건은 가져오지 않는다.

## 학습과 실습의 기준

- 학생이 원하는 것을 정하고, 에이전트에게 구현을 맡기고, 결과를 판단한다. 손코딩 분량을 늘려 난이도를 만들지 않는다.
- 단순 구현 뒤 같은 질문이나 표본으로 확인하고, 실패 유형에 맞는 장치 하나를 선택한 다음 다시 비교한다. 특정 실패나 개선 수치가 반드시 나온다고 가정하지 않는다.
- 결과 화면이나 코드가 모두 같을 필요는 없다. 목적·입력·근거·판정·한계를 설명하고 필요한 성질이 성립하면 된다.
- 부정행위 방지 장치와 감시 설계는 추가하지 않는다. 개인 노트·비교 회고의 분량이나 제출 형식을 새 의무로 만들지 않는다.
- 이전 작업을 계속 사용할 수 있다. 결석·중단 등으로 이어가기 어려우면 **해당 일차 시작에 필요한 이전 단계가 완성된 출발본**으로 합류한다. 자기 작업은 보존한다. 전체 최종 정답을 모든 날의 출발본으로 배포하지 않는다.
- 학생 안내는 ESNS에서 Google Drive의 해당 일차 링크로 연결하는 방향이다. 조기 전체 공개·링크 생성·업로드는 이번에 수행하지 않는다. 학교의 이수 기록 방식과 자료 전달 방식은 구별한다.
- 실습 가이드는 설치 문서와 별개다. 현재 행동에 필요한 배경·이유·용어·입력·실행·관찰·판단을 그 자리에서 짧게 설명한다. 이전 절을 찾아 위로 돌아가게 하는 의존을 만들지 않는다.

## 이론 덱의 기준

- 반별 영상 제목과 일정을 유지한다. 통합반 영상10·11을 한 편으로 합치지 않는다. 실전반 영상8은 도구와 폐루프를 한 편에 연결한다.
- 각 장에 실제 화면 문구·구체적 예시·삽화 지시·결론·다음 장 연결을 둔다. 제목 목록만 만들지 않는다.
- 용어는 필요한 첫 등장에 정확히 풀고 이후 같은 용어를 쓴다. 비유의 대응 범위를 벗어나 물리적 의미를 왜곡하지 않는다.
- 설명은 읽을 수 있는 문단과 비교로 남긴다. 키워드만 놓고 화면 밖 설명을 길게 이어 가거나 모든 말을 자막으로 붙이지 않는다.
- 그림은 해당 대상과 상황을 정확하게 보여 주는 새 삽화로 지시한다. 표와 그래프는 정확한 수치·축을 우선한다. 삽화는 실제 장비 사진·프로그램 캡처·실행 증거로 제시하지 않는다.
- 편별 4H 배분은 집필 계획이다. 녹화·낭독 뒤 실제 길이를 확인해야 한다. 영상 일시정지 시간을 콘텐츠 길이에 더하지 않는다.
- 제공 자료의 60분 완성본 시연과 ‘특강 이후 완성본 시연 없음’이 충돌한다. 이번 덱의 해당 60분은 **현재 단계의 적용 원리·결과 읽기 스토리보드**로 설계한다. 전체 최종 코드 시연으로 만들지 않는다. 실제 실행 시연을 넣는 녹화 단계에는 해당 구현의 확인 화면이 필요하다.

## 사실과 평가의 기준

- 번호·JSON 형식 제약은 형식을 제한한다. 허용된 잘못된 번호나 틀린 의미까지 없애지는 않는다.
- 모델 심사 결과를 코드로 합산해도 심사 자체가 자동으로 참이 되지는 않는다.
- 그래프의 관련 경로·문서의 일반 원인 후보·실제 고장 원인은 서로 다르다.
- 결측·0건·호출 성공·정상 판정·근거 충분성을 구별한다.
- 샷 순서는 실제 시각이 아니다. 없는 시간 축·고장 시점·LOT 연결을 만들지 않는다.
- 규칙 라벨의 재현, 교육용 합성 동작, 실제 품질 예측, 실제 RUL 검증은 구별한다.
- 모델 비교는 같은 요청의 품질·토큰·단계별 지연·비용 범위를 맞춘다. 조용한 대체 모델 사용을 허용하지 않는다.

## 실행 제한과 후속 확인

이번 작업은 문서·일정·링크·산술 등의 간단한 확인만 수행한다. 실습 완주·GPU 부하·코딩 에이전트 대역 실행·유료 API·배포를 하지 않는다. 비싼 모델은 사용하지 않는다. 사용자가 말한 Gemini Flash 계열의 정확한 모델 식별자·가격·접속 가능성을 임의로 확정하지 않는다. 이후 최소 실행을 하더라도 실제 제공 모델과 낮은 비용 조건을 확인하고 현재 금지 범위를 유지한다.

기존 설치 PDF 4개는 보존한다. 이번 덱 작성에서 설치 문서 내용의 최신성이나 설치 성공을 검증했다고 주장하지 않는다. 강의용 모델·코딩용 모델·평가용 모델을 후속 실습 제작에서 분리해 확정한다.
