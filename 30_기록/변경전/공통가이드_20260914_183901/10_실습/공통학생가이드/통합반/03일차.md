## 분류 점수에서 놓친 불량을 찾아냅니다

만들 결과: **두 분할의 혼동 행렬, 실제·규칙 라벨 구분, 판정과 대상의 연결**

오늘 출발본에는 앞선 공통 실습의 표 읽기·품질·그래프·명세 도구가 들어 있습니다. 두 반 모두 같은 준비 상태에서 시작하며 분류 기능은 오늘 추가합니다. 품질 카드는 결측·0·음수를 관측하고, 그래프의 가로축은 파일 순서입니다. 오늘은 이 숫자들로 라벨을 맞히는 분류기를 만듭니다.

### 1. 전부 양품이라고 해도 높은 점수가 나옵니다 · 약 50분

분류는 입력 특징에서 정해 둔 라벨을 고르는 일입니다. 정확도는 전체에서 맞힌 비율입니다. 불량이 적으면 모두 양품이라 해도 정확도가 높습니다. 혼동 행렬은 놓친 불량과 잘못 버린 양품을 따로 보여 줍니다.

라벨 원천을 선택하고 무엇이 0·1인지 확인합니다. 실제 검사 라벨이면 그 출처를, 합성이면 생성 규칙을 표시합니다. 코딩 에이전트에게 기존 서비스에 표 분류 API와 분석 화면을 추가하도록 요청합니다. 만든 화면에서 특징 열과 학습 비율을 정하고 파일 순서 분할을 실행합니다. 정답 열과 식별자를 특징에서 빼고, 전처리도 학습 구간에만 맞추게 요청합니다.

**먼저 입력을 엽니다.** 합성 프로필의 `labeled`를 선택하고 `data/generated/labeled.csv`와 mapping의 같은 원천을 확인합니다. 이 자료는 302=쿠션, 303=사이클 시간, 304=규칙 라벨입니다. 301은 순서, 305는 라벨 생성 설명입니다. 첫 비교에서는 특징 302·303을 사용하고 정답 304와 순서/설명 열은 넣지 않습니다. 다른 원본이면 이 번호를 복사하지 말고 자기 열 사전에서 다시 정합니다.

**분류 기능을 만든 다음 실행합니다.** 에이전트에게 첫 분류는 CPU에서 동작하는 모델로 구성하고, 전처리는 학습 자료로만 맞추며 결과에 학습/평가 행 수·혼동 행렬·행별 예측과 라벨을 보여 주도록 요청합니다. 참고 구현은 Random Forest이며, 이 실행은 자연어 답변용 API 모델 호출과 다릅니다. ALLOW_MODEL_CALLS를 켠다고 분류 라이브러리가 설치되는 것은 아닙니다.

구현한 의존성과 잠금 파일을 확인한 뒤 프로젝트 루트에서 `uv sync --frozen --extra models --extra dev`를 사용합니다. 이 extra는 다른 모델 실습의 패키지도 포함하지만 설치가 모델 실행을 뜻하지는 않습니다. 서버를 다시 시작하고 labeled를 적재합니다. 새 분석 화면에서 방법 `table`과 다음 설정의 뜻을 읽어 첫 비교를 요청합니다.

```json
{"feature_ids": [302, 303], "split": "ordered", "train_fraction": 0.7}
```

학습 비율 0.7은 이 예제의 첫 비교 설정입니다. 실행 전 에이전트와 현재 입력 수와 라벨 분포를 확인합니다. 참고 구조는 최소20행과 학습 비율0.5~0.9를 요구하고, 학습 라벨이 하나뿐이거나 특징 전체가 결측이면 이유를 표시합니다. 오류가 나면 라벨을 임의로 옮기지 말고 어떤 조건이 부족한지 읽습니다.

**결과를 읽습니다.** tp·tn·fp·fn의 합이 평가 행 수와 같아야 합니다. 항상 양품인 기준 모델과 비교하고, 불량 재현율의 분모가 0이면 미정의로 보입니다. 실제 2020 원본의 전체 불량 71건이 평가 구간에도 그대로 71건 있다고 가정하지 않습니다.

**막히면 여기서 확인합니다.** 학습 구간에 한 라벨뿐이면 입력·순서를 먼저 봅니다. 평가 라벨을 옮겨 학습 점수를 올리지 않습니다.

같은 모델이어도 나누는 방법이 바뀌면 점수가 달라질 수 있습니다.

### 2. 분할과 라벨의 의미를 함께 비교합니다 · 약 50분

무작위 분할은 행을 섞고, 순서 분할은 앞에서 배워 뒤를 평가합니다. 같은 LOT의 비슷한 샷이 양쪽에 섞이면 새 LOT 성능처럼 해석하기 어렵습니다. 순서 열도 실제 시각이라는 보장은 없습니다.

동일 특징·라벨로 무작위 분할과 순서 분할을 비교합니다. 라벨 없는 샷 자료에는 LOT별 IQR 같은 규칙으로 만든 라벨을 별도 열에 둡니다. IQR은 가운데 절반의 값이 차지하는 범위입니다. 규칙 라벨을 학습하는 분류기는 그 규칙을 얼마나 재현하는지 보는 것임을 화면에 적습니다.

**한 조건만 바꿉니다.** 첫 실행의 원천·특징·학습 비율을 유지하고 split만 `random`으로 바꿉니다. 파일 순서 분할은 앞부분으로 학습하고 뒤를 평가하며, 이 사실만으로 새 LOT나 새 설비의 독립 평가가 되지는 않습니다. 실제 묶음 정보가 있으면 학습과 평가에 같은 묶음이 겹치는지 확인합니다.

샷 표의 IQR 라벨 실험은 labeled의 기존 라벨과 별개입니다. 직접 추가하려면 생성에 사용한 대상·구간·기준을 정하고 새 원천 또는 별도 파생 열로 보존하도록 요청합니다. 원본 검사 라벨을 덮지 않습니다. 현재 labeled만 비교한 결과를 IQR 라벨 생성까지 실행한 것으로 쓰지 않습니다. 규칙을 학습한 높은 점수는 실제 불량을 찾아낸 증거가 아닙니다.

**결과를 읽습니다.** 분할 이름·학습/평가 행·라벨 출처가 결과와 함께 있어야 합니다. 규칙 라벨 점수를 현장 검사 불량 예측 성능으로 바꾸지 않습니다.

**막히면 여기서 확인합니다.** 특징을 고를 때 라벨 생성에 쓴 값이 사실상 정답을 드러내는지 살펴봅니다. 높은 점수의 이유도 확인 대상입니다.

판정을 숫자만 남기지 않고 어떤 대상의 결과인지 연결합니다.

### 3. 판정 결과를 다시 찾을 수 있게 저장합니다 · 약 50분

추론 결과는 모델·특징·분할·입력 출처가 함께 있어야 비교할 수 있습니다. 같은 행에 다른 모델이 내린 판정을 서로 덮으면 개선 전후를 잃습니다.

분석 기록에서 실행 ID와 입력 설정을 확인합니다. 판정 결과를 row_no와 LOT에 연결하고 관계표에 결과→대상 관계를 추가합니다. 파이프라인에 분류 단계를 넣을 때 라벨 없는 입력과 특징 누락의 종료 상태도 정합니다.

**결과에서 원본으로 돌아갑니다.** 실행 결과의 id·profile·source_id·parameters와 predictions의 row_no·expected·predicted를 함께 읽습니다. 같은 row_no가 다른 원천에도 있을 수 있으므로 원천을 빼고 연결하지 않습니다. LOT가 있는 자료에서는 원본 행을 통해 실제 LOT를 확인하고, 없는 자료에는 LOT를 지어내지 않습니다.

관계와 후속 파이프라인 연결은 오늘 만드는 확장입니다. 기존 결과 저장만으로 행별 관계 투영이나 자동 파이프라인 실행까지 끝났다고 판단하지 않습니다. 먼저 저장한 실행 ID를 ‘이전 결과’에서 다시 찾고, 이후 추가한 관계가 같은 원천/대상을 가리키는지 대조합니다. 아직 설치하지 않은 그래프 DB의 성공을 가정하지 않고, 현재 관계표 기반 확인과 나중 DB 반영을 구분합니다.

**결과를 읽습니다.** 다른 프로필의 같은 행 번호와 섞이지 않고, 이전 결과를 새 결과가 덮지 않아야 합니다. 모델 실행이 실패하면 성공 판정 관계가 생기면 안 됩니다.

**막히면 여기서 확인합니다.** 연결할 LOT가 없는 자료라면 제품이나 행 ID를 사용합니다. 빈 LOT를 임의 번호로 만들어 잇지 않습니다.

어떤 특징이 작용했는지 읽되 인과관계로 과장하지 않습니다.

### 4. 점수가 높은 이유와 옮길 조건을 설명합니다 · 약 50분

특징 중요도는 모델이 학습에 사용한 패턴의 요약입니다. 그 변수를 바꾸면 불량이 줄어든다는 실험 결과는 아닙니다. 다른 기계·제품·기간에서 같은 패턴일지도 확인해야 합니다.

중요 특징과 누락·라벨 생성 과정을 같이 읽습니다. 같은 공개 자료를 사용한 연구가 있다면 분할·라벨·특징이 같은지 먼저 비교합니다. 내 주제에서 사람 라벨은 어디서 얻고 무엇을 놓치면 더 큰 비용인지 한 사례를 정합니다.

**기준선과 설명 출력을 요청합니다.** 항상 0으로 예측하는 기준선을 같은 평가 행의 expected와 비교해 tp·tn·fp·fn과 재현율을 계산하도록 요청합니다. 전체 원본 분포를 평가 분모로 쓰지 않습니다. 모델의 특징 중요도를 보려면 선택한 특징 ID와 실제 모델이 반환한 중요도 값을 연결하는 출력도 구현해야 합니다. 값이 아직 없으면 그림을 추정해 채우지 않습니다.

참고 완성본은 결과 화면에 모델/항상 0 기준선 비교와 특징 중요도 표를 제공합니다. 전체 결과의 baseline.metrics와 feature_importances에서도 같은 값을 확인할 수 있습니다. 예전 저장 기록에 이 필드가 없으면 기준선을 임의로 채우지 않습니다. 중요도는 학습된 숲의 불순도 감소 기반 값이며, 값 종류가 많은 열에 편향될 수 있습니다.

중요도가 높은 열이 라벨 생성 규칙에 사용됐는지, 실제 예측 전에 알 수 있는 값인지 확인합니다. 두 분할의 결과와 중요도의 의미를 설명하되 특정 변수를 바꾸면 불량이 줄어든다고 결론내리지 않습니다. 계산·출력 구현 여부와 실제 모델 실행으로 확인한 범위를 구분합니다.

**결과를 읽습니다.** 정확도 하나 대신 놓침과 오탐을 설명할 수 있으면 됩니다. 참고 완성본과 예측이 다르더라도 입력과 분할 차이를 설명하면 비교가 가능합니다.

**막히면 여기서 확인합니다.** 논문의 점수와 다르다고 맞추려 하지 않습니다. 평가 조건을 확인할 자료가 없으면 직접 비교 불가로 둡니다.

표에서 배운 분할과 라벨의 원칙을 유지합니다. 다음 시간에는 규칙 감지와 파이프라인을 만들고 이후 이미지와 수명 자료로 범위를 넓힙니다.

## 오늘 만든 것을 이어갈 준비 · 20분

현재 폴더와 실행 설정을 저장하고 오늘 확인한 대표 입력을 다시 찾을 수 있게 둡니다. 아직 실행하지 않은 모델이나 부족한 자료는 성공 결과로 바꾸지 않습니다. 다음 시간에는 자기 프로젝트를 이어가거나 그날 출발본으로 합류할 수 있습니다.

참고 완성본과 화면이나 코드가 같을 필요는 없습니다. 원하는 입력과 결과가 연결되고, 근거와 한계를 설명할 수 있는지 확인합니다. 별도 회고문 제출이나 정해진 모양의 개인 노트는 요구하지 않습니다.
