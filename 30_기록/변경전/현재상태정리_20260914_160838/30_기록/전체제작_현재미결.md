# 전체 제작 현재 미결 · 2026-09-14

원래 goal은 이론 덱·대본·실습가이드·실습코드 전체다. 덱만으로 완료 처리했던 판단은 철회했고 현재 goal은 active다. 사용자 질문에 답한 뒤 제작을 계속하고 있다. 이 문서는 최종 보고가 아니다.

## 이번 제작의 실제 파일

- 신규 equipment-assistant: Vue/FastAPI/Postgres·pgvector/Neo4j/MCP/LangGraph/CPU 분석/RAG/평가/승인/보고서 코드와 설정을 작성했다. 이전 본강 코드는 복사하지 않았다.
- 실전 9·통합 10, 총 19 일차 가이드와 OT·실행 연결 안내를 작성했다. build_lab_guides.py와 lab_guide_content.py가 집필 소스다.
- 실제 이전 기능만 남기는 AST 기반 출발본 제작기를 만들고 19 출발본을 생성했다. 전체 코드를 메뉴로만 숨기는 방식이 아니다. 생성 뒤 각 Python 구문·API import는 오류 0, Vue SFC 147개 구문·script/template·로컬 import 확인도 오류 0이었다. 이 숫자는 당시 생성 버전의 구조 검사다.
- 최종 앱 화면 빌드는 23 modules, 성공했다. 작은 계약 검사 25개가 2.18초에 통과했다. pytest를 executable로 부르면 backend import가 실패해, README와 실행을 `uv run --no-sync python -m pytest -q`로 고쳤다. 경고 1개는 Starlette의 anyio alias deprecation이다.
- 실제 모델·DB·GPU·학생 완주·클라우드 배포는 실행하지 않았다. 무상 공개 모델 파일도 다운로드 실행하지 않았다. 의존성 일부 설치/import와 Vue 빌드만 했다.
- 합성 샷 1,440행·6 LOT, 조건표·일지·분류 데이터, 교육용 문서 30장, 도서관 전이 자료, 학생 RAG 질문 20·30개 작성틀, 강사 기대 근거 20을 작성했다. 기대 근거는 모델 실행 답안이 아니다.

## 반드시 이어서 처리

1. **대본은 아직 제작하지 않았다.** 19개 덱 1,170장의 실제 발화 원고를 만들고 화면·대본 의미를 대조해야 한다. 시간은 기존 4H 배분일 뿐 녹화 실측이 아니며 짧은 문구 복제로 채우지 않는다. 현재 전체 완료가 아니다.
2. **코드와 가이드의 기능 차이를 해결해야 한다.** 현재 품질은 기본 집계뿐이라 원본 보존 정제 뷰·중복 열·오류 코드·근거 있는 열 뜻 제안이 부족하다. 규칙은 고정 범위/표준편차/같은 채널 AND이며 원문 조건표 기반·다채널 조합과 차이가 있다. 파이프라인은 LangGraph 적재→규칙→관계이며 예측까지의 통합은 아직 부족하다. 실제 원시 데이터·C-MAPSS 파일은 미수령이라 원본 연결 실행은 미확인이다. 원시 데이터 위치 async 질문은 응답 대기다.
3. **비전 이미지 전용 평가 구성을 확인해야 한다.** Anomalib Engine 기본 pixel metric/visualizer와 gt_mask 없는 ImageBatch가 호환되는지 원문/API 대조를 마쳐야 한다. 실제 CPU 학습은 하지 않는다. 비전 결과 화면은 현재 일반 JSON이며 실제 이미지·임계 비교를 더 연결해야 한다.
4. **에이전트의 원문 범위를 대조해야 한다.** 현재 6단계 흐름은 규칙 폭 변경 제안 하나이며 그래프 경로를 흐름 안에서 호출하지 않는다. 4M·초물검사 초안, 자율성 0/1/2 정책, 8D 출력과 충분한 후속 대화는 보완 대상이다. 사람 승인·버전/해시·중복 기록 방지와 재생 실패 응답은 구현했다.
5. **출발본은 최근 코드 수정 뒤 재생성·재검사 필요.** build_checkpoints.py의 manifest로 기존 파일 해시를 확인하고 외부 편집이 있으면 중단한다. 최신 ZIP은 타임스탬프 새 이름으로 만들고 이전 ZIP을 보존한다. 최초 타임스탬프 없는 ZIP들은 구버전이다. __pycache__는 배포 제외한다. stage별 UI/API 기능 집합, ModelJob method enum, pyproject의 미래 의존성 노출, 도구별 단계 코드를 추가 대조한다. 각 일차 완성본 명칭과 당일 가이드·재료를 함께 묶는 배포 구조도 아직 필요하다.
6. **배포 구성은 실행 미검증이다.** 현재 Dockerfile은 RAG/evaluation만 설치하고 models는 제외한다. 문서 검색 가중치를 CACHE_RAG_MODELS=true에서 준비하게 했다. 로컬 모델 분석을 클라우드에서도 수행한 것처럼 가이드에 쓰지 않는다. 모델 호출 초기 false·IAM 비공개는 실제 운영 설정으로 설명했다. 최종 통10 단계의 재배포와 승인 대기 보존은 가이드에만 실행 절차가 있다.
7. **가이드 링크/전체 의미 검토 및 강사용 대비 자료/장치 카드가 필요.** 학생 RAG JSON 링크, 설정 명령과 실제 parser 옵션, 모든 상대경로, 원문 필수 사고 루프를 대조한다. 추가 노트 의무·부정행위 통제·파괴적 reset은 사용자 지시로 제외했다.
8. **기존 이론 덱 전체 의미 검토가 아직이다.** build_decks.py는 현재 원고를 바로 덮는 제작기라 현재 매니페스트 해시를 확인하고 WIP 보호 후에만 실행한다. 원본 리허설 디자인은 따라하지 않는다. 이번에는 PPTX를 만드는 것이 아니라 NotebookLM용 MD를 만든다.
9. 마지막에 0_인계·1_규범·2_커리큘럼·10_실습 README·요구반영표·작업계획을 실제 상태에 맞추고 기존 보고서 한 개를 전체 범위 최종 보고로 갱신한다. 미완료인데 완료 goal로 바꾸지 않는다.

## 재생성 주의

build_lab_data.py → build_lab_documents.py → build_transfer_data.py는 mapping을 다시 쓴다. 이후 직접 추가한 synthetic shots.joins, transfer loans.joins와 COND-B §4 표를 덮을 수 있으므로 현재 파일을 보호하고 생성 소스에 반영한 뒤에만 다시 돌린다. 출발본 작성기는 현재 APP 파일을 읽는다. build_questions.py는 모델을 호출하지 않는다.

현재검증과 원본 보호의 근거는 30_기록의 각 매니페스트·검사 JSON, 원자료해시.json에 있다. 원자료 ZIP·HTML·PDF는 보존했다. 보고서 여러 개로 분리하지 않는다.
