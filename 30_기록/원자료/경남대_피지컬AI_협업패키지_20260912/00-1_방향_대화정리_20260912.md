# 00-1 · 방향 정리 — 2026-09-11~12 대화에서 정한 것 (말로)

00 §3 확정 #19~28과 `실습흐름_정본.html` §0에 반영된 것의 원문 취지. 여기 없는 건 대화에서 정하지 않은 것.

## 1. 과정의 목표
- 최종 목표는 「이 스택(LLM·RAG·에이전트·그래프)으로 **주제가 바뀌어도 같은 것을 다시 만들 수 있는 사람**」. 그래야 PBL과 이어진다.
- 재는 것은 스택이 아니라 활용 능력 넷 — 시키기 / 확인하기 / 이어 붙이기 / 한계 알기.
- LLM·에이전트는 「기본 베이스」다. 현업 고도화 팁을 옮기는 게 아니라 **이 베이스로 어디까지 가능한가**를 학생과 같이 재 본다. 고도화 장치는 그 한계가 실제로 드러난 자리에서만 들어간다.
- 너무 어렵게는 안 되지만 어느 정도 고도화는 필요하다. HyDE·리랭크 같은 장치의 이름·용도·언제 쓰는지는 알아야 한다(만들지 않아도).

## 2. 난이도의 축
- 어려운 인프라(DB·배포·인덱스·트랜잭션)는 에이전트가 헌법대로 알아서 한다 — 이게 「와 포인트」. 학생 가이드에 인프라 용어를 설명하지 않는다.
- 학생의 난이도는 모델·에이전트를 다루는 **판단**에 둔다 — 무엇을 주고 무엇을 안 주나, 답이 맞나, 어디서 깨졌나, 뭘로 고치나.
- 시간을 이유로 내용을 줄이지 않는다. 바이브코딩·SDD는 빨라서 시간은 남는다. 엑셀 회차 주제에 담긴 것을 전부, 자연스럽게, 바쁘게.

## 3. 페인포인트
- 억지로 넣은 페인포인트 금지. 페인포인트란 의도하지 않아도 저절로 생기는 것(바이브코딩→SDD, 반복→스킬, RAG로 안 됨→그래프).
- 일부러 깨뜨리기 금지. 규칙(「참이어야 하는 것」)을 먼저 주고 맞추게 하기 금지.
- 추측에 근거한 「대비」(나올 수 있는 것과 그때 한 걸음)는 남겨도 된다 — 대비하면 되니까. 단 학생 가이드가 아니라 강사용 파일에.
- 「느리다→두 번 올라감→LOT 800→debug」 같은 실측 없는 사슬은 폐기.

## 4. 학습 능력을 키우는 방식
- 완성본을 주면 「쓰는 사람」, 하나씩 쌓으면 「만드는 사람」. 쌓되 쌓는 사람이 학생이어야 한다.
- 답을 먼저 보여 주지 않는다. 특강의 완성본 시연이 마지막으로 보는 자리. 완성본 코드는 학생에게 안 간다. 출발본은 「어제까지 네가 만들었어야 할 것」이고 받으면 「다른 점 하나」를 적는다.
- **발판을 회차마다 뺀다** — 프롬프트는 처음부터 학생 것이었고, 프롬프트 **앞뒤의 판단**(뭘 만들지·뭘로 잴지·뭐가 맞는지·어디가 깨졌는지·뭘로 고칠지)을 우리에서 학생으로 옮긴다.

| 발판 | 주는 회차 | 학생이 정하는 회차 |
|---|---|---|
| 잴 질문 | 실1~3 | 실7부터 30개 |
| 무엇이 「맞다」인지 | 실1~2 | 실3부터 체크리스트 |
| 어디가 깨졌나 | 실1~2 | 실3부터 채점표만 보고 |
| 어떤 장치를 쓸지 | 실1~5(카드 한 장 지정) | 실6부터 묶음에서 고름 |
| 명세 | 실3(역추출) | 실4부터 처음부터 |
| 검사 | 실5(첫 줄) | 실7부터 스킬로 |
| 무엇을 만들지 | 실1~8 | 실9 다른 주제 |

- 깨진 자리는 학생이 찾는다(채점표가 보여 준다). 가이드가 「여기서 틀린다」고 말하면 강의다.
- 매일 세 줄 — 판단 / 한계 / 옮겨 보기(제조 아닌 데 쓰면 뭐가 바뀌나).
- 같은 절차를 세 번 손으로 한 뒤 네 번째에 스킬로 접는다. 우리가 대신 만들어 주지 않는다. 경험을 도구로 접는 것이 학습 능력이다.
- 실9에 「다른 주제」 한 벌로 전이를 검사한다 — 데이터만 바꾸는 건 이식이지 전이가 아니다.

## 5. 가이드의 모양
- 학생은 프롬프트만 쓴다. 가이드는 정답이 아니라 유도 힌트 — 퀴즈처럼: 상황 → 문제 → 「어떻게 시킬까?」 + 주석형 힌트(`-- 뭐가 필요하지 않을까`) → 빈칸 → 됐는지.
- 힌트는 끝까지 준다(안 주면 무한 뺑뺑이). 대신 세기를 낮춘다 — 실1·2 세 줄 → 실3~5 두 줄 → 실6·7 한 줄 → 실8·9 0~1.
- 시간으로 여는 힌트 같은 건 없다(시간을 잴 수 없다). 학생이 막혔다고 느끼면 스스로 묻는다.
- 정답·강한 힌트는 가이드에 넣지 않고 강사가 단톡방에서 준다(다음 한 걸음만, 프롬프트 아님, 개인 DM 아님). **가이드에 「단톡방에 물어라」 문구도 넣지 않는다.** 회차 뒤 실제 질문을 강사용 파일에 쌓아 다음 판 수정 근거로.
- 부정행위(힌트 몰래 열기 등)는 고려하지 않는다. 막을 수 없고, 열심히 잘 따라온다는 가정.

## 6. LLM 자리의 수준
- 자사 robo-data-text2sql·Analyzer와 대조: 이전 초안은 모델 자리가 「mapping 주고 SQL 만들어」 한 줄 — 장난감 수준이었다. 인프라는 엄격했는데 모델 자리는 얕았다.
- 다만 자사 장치 25개를 다 넣지 않는다. 표 수백 개에서만 깨지는 검색 장치(HyDE·다축·PRF·FK)는 우리 데이터(표 셋)로는 안 깨지므로 「안다」 카드로만.
- 규모 무관하게 성립하는 장치(체크리스트 채점·정찰 SQL·LOT 앵커·번호로 받기·결정론 감점·최소 변경 수리·거절·표 행 자르기·하이브리드+리랭크·그래프 홉·상태 필터·도구 계약·가드레일·대화 상태·요청 구조)는 「만든다」.
- 컨텍스트 개념은 모델 둘(API + 사내 GPU)로 같은 질문셋을 돌려 토큰·비용·지연·점수를 재면서 들어온다.
- 폴백은 「금지」가 아니라 「조용한 폴백 금지」(자사 정책과 일치).
- 에이전트는 8일차에 갑자기 오지 않는다 — 실5 파이프라인 자동 실행 → 실6 길 찾기 → 실7 라우터 → 실8 잇기. 후속 질문(대화 상태)이 없으면 장난감.
