# 전체 제작 작업계획 · 2026-09-14 재개

사용자 요청 범위를 좁혀 덱 단계만 완료했던 판정을 정정했다. 목표는 이론 덱·대본·일차별 실습가이드·실습코드 전체다. 제작 순서는 완성 구현 → 진도별 출발본 → 실제 코드에 맞춘 가이드 → 덱 보완과 대본 → 내용 대조다. 실행 금지는 제작을 생략할 이유가 아니다.

최신 추가 지시: 대본은 온라인 이론만. 통합반과 4학년은 동일 내용. 원자료의 실전반·통합반 명칭과 4학년의 연결을 확인 중이며 실습 진행 대본은 추가하지 않는다.

## 구현 결정

- 프로젝트 이름 `equipment-assistant`. 기존 본강 코드를 복사하지 않고 새로 작성한다.
- 표·영속 기록·벡터는 로컬 Supabase의 Postgres, 그래프는 Neo4j. 그래프 선택은 설치 실측 결과가 아닌 API 문서와 유지보수 범위를 고려한 설계 결정이다.
- `mapping.json`이 원천·열 뜻·단위·키·라벨·문서 상태의 진입점. 교육용 합성 입력은 원본 대신 자동 선택하지 않고 사용자가 선택한 프로필로만 연결한다.
- 일반 서비스 의존성과 CPU 모델/문서 인덱싱/평가 의존성을 분리한다. 설치나 서버 시작만으로 모델 다운로드·API 호출이 일어나지 않는다.
- 이중 저장은 같은 원자 트랜잭션처럼 가장하지 않는다. Postgres에 그래프 반영 작업을 함께 남기고 멱등 반영·오류 재확인을 제공한다.
- 학생 지시와 서비스 모델 지시를 분리한다. 제공 스킬은 spec/debug, 학생이 만드는 세 스킬은 가이드에서 절차와 계약을 배우며 작성한다.
- 제공 ZIP의 `git reset --hard`를 기본 복구 동선으로 사용하지 않는다. 자기 폴더를 보존하고 해당 일차 출발본을 새 폴더에서 연다.
- 학생 추가 노트 의무, 부정행위 통제, 미시청자 제한은 최신 사용자 지시에 따라 제외한다.
- 캡처는 실제 화면만 사용한다. 간단한 화면 확인 가능 범위를 넘어 모델·실습 전체를 실행하지 않는다. 확인하지 못한 화면을 합성 캡처로 만들지 않는다.
