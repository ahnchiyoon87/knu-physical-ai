# 1일차 관측과 출처를 사용하는 수업

제작 중 · 대표님 P01/I01의 학습 결과를 기준으로 학생 역할을 이미 합의한 AI 코딩·이해/판단 방식으로 작성했다. 기존27구간 표본은 섞지 않았다. 그 표본의 부분 사용은 별도 질문 중이며 답변 전 적용하지 않는다. 대표님 자료의 오류도 그대로 정답으로 옮기지 않는다.

## 오늘의 학습 결과

공통: 센서별 주기·단위를 구분하고, 같은1초 구간의 관측에서 원본 사이클과 경과 초를 추적한다. 통합반은 제공 노트북으로 재생·저장본을 남긴다. 실전반은 제공 코드로 PostgreSQL 적재와 run_id를 지정한 최근60초 조회까지 수행한다. 두 반 모두 다음 회차까지 품질·DB라는 같은 핵심에 도달한다.

## 연결된 제작물

- 학생 활동: [관측에서원본까지 실습가이드](../실습자료/1일차/관측에서원본까지_실습가이드.md).
- 시작 파일: `실습자료/1일차/원문시작본/practical`, `integrated`. 원문 코드이며 `TODO/____`는 코딩 에이전트가 수정한다. 학생에게 문법 작성 과제를 주지 않는다.
- 원본 입력: `플랫폼코드/data/raw`에 TS1/PS1/FS1/profile과 원문 데이터 설명을 도입했다. 전체2205행을 보존해 사이클 번호와 파일 줄의 대응을 바꾸지 않았다. 실습에서 선택하는 구간은100~102의60초 전체다.
- 제공 축약본: 기존 `플랫폼코드/data/reduced`. 새 계산 결과의 비교 기준으로 사용한다.
- 온라인 이론: `이론자료/1회차/관측과출처_덱.md`, `관측과출처_온라인대본.md`. 첫 설명 단위이며 온라인1편4시간 전체 완성본이 아니다.

## 강사·에이전트 준비와 검증 경계

원문 시작 파일에는 원래 저장소의 system 경로를 찾는 코드와 설명이 있다. 학생 작업 복사본에서 한글 프로젝트의 플랫폼코드 경로로 맞춘다. 노트북에는 nbformat·nbclient·ipykernel/IPython 등 실행 도구가 추가로 필요하며 기존 플랫폼 requirements만으로 준비됐다고 판단하지 않는다. 변경된 학습 스택이 아니라 노트북 실행 도구 준비다. 실제 설치와 커널 실행은 미검증이다.

원문 practical 테스트3개와 integrated 테스트4개를 보존했다. 테스트 실행을 위한 환경과 실제 DB는 아직 준비 완료가 아니다. 테스트 통과만으로 학생의 출처 이해나4시간 완주를 인정하지 않는다. 시작본에는 의도된 미완성 코드가 있으므로 처음부터 전부 통과해야 한다고 요구하지 않는다.

학생에게 전체 플랫폼 정답본을 첫날 작업 폴더로 배포하지 않는다. 현재는 내부 제작 중 원문시작본 도입이며 학생 ZIP은 아직 만들지 않았다. 단계별 출발본은 필요한 제공 라이브러리와 그날 입력만 포함하도록 별도 선별해야 한다.

## 원문에서 발견한 확인 사항

P01의 품질 OK와 냉각기 상태3은 다른 평가 축이므로 모순이 아니다. 재검토에서 최초 충돌 단정을 철회했다. 전체2205개 최대 변화폭을 정상 구간만의 값처럼 설명하는 대목과 정상의 대상을 명확히 하는 안을 제시했고, 사용자가 설명 범위만 반영하도록 승인했다. 새 가이드와 덱·대본에 반영했다. 데이터·임계값·순서는 유지했다. 근거는 작업기록/첫날제작_20260915/정상표현_재검토.md다.

기존27구간 표본의 혼합, 원문 사실 설명 수정 외에는 첫날 내용을 다시 승인받는 관문을 두지 않는다. 기존 대응표의 A/B/C 일괄 대기 때문에 승인 범위 제작을 멈추지 않는다. PBL의 구체적인 시간 재배치와 기존 리뉴얼 기법 혼합은 해당 지점에서 별도로 논의한다.
