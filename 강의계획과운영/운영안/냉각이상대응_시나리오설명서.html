01 / 교육 시나리오

온도 한 줄에서
근거 있는 조치와 회복 확인까지

학생은 제공된 제조 AI 플랫폼을 직접 사용하고, 결과를 설명하며 자기 문제에 적용합니다.

교육 상황은 유압설비의 냉각 이상 대응입니다. 온도가 높다는 이유만으로 AI가 바로 조치하지 않습니다. 값의 품질, 설비와 문서의 관계, 사람의 승인, 조치 후 새 관측이 연결되어야 합니다.

→
품질·저장출처와 실행 구분
→
이상 사건조건·지속시간
→
적용 근거설비 관계·SOP
조치 제안도구 결과·문서 인용
→
사람 승인대상·조치·값 판단
→
실행실제 결과 기록
→
새 관측회복·보류·이관

위 두 줄은 이어지는 하나의 흐름입니다. 새 관측으로 다시 상태를 판단하는 연결을 폐루프라고 부릅니다.

UCI 파일 재생기록된 실제 센서값을 읽어 집계·품질·출처 추적을 배웁니다. 과거 파일을 다시 읽어서 이번 조치의 효과를 입증할 수는 없습니다.
교육용 합성 시뮬레이터프로그램이 새 관측을 만듭니다. 구현된 조치와 이후 값의 변화를 연결해 회복 확인을 연습합니다. 실제 공장의 효과로 일반화하지 않습니다.
품질 OK는 제공 센서 품질 규칙을 통과했다는 뜻입니다. 설비 정상이나 조치 후 회복을 뜻하지 않습니다.

02 / 학습과 시스템의 역할

누가 만들고, 누가 판단하는가

학생목적·입력·원하는 동작·확인 기준을 정합니다. 실행 결과와 근거를 읽어 수용하거나 수정을 요청합니다.
코딩 에이전트개발 도구 안에서 설치·코드 작성·MCP 연결·검사를 수행합니다. 학생이 요구한 시스템을 만드는 역할입니다.
업무 에이전트만들어진 플랫폼 안에서 사건의 근거를 조회하고 조치를 제안합니다. 코딩 에이전트와 다른 실행 주체입니다.

각 기술은 다음 판단에 필요한 정보를 연결합니다

구성맡는 역할학생이 확인할 것
Python · PostgreSQL관측 처리와 실행·사건 기록 저장같은 센서·실행·시간 구간을 다시 찾는가
온톨로지 · Neo4j설비·센서·허용 조치·문서 관계 조회이 설비에 적용할 수 있는 근거인가
SOP 검색 · RAG관련 절차의 문서와 절을 찾아 제안에 연결문서의 대상·버전·내용이 제안을 뒷받침하는가
데이터 패브릭 · 도구 연결흩어진 데이터와 관계·접근 경로를 연결해 활용필요한 정보의 위치와 조회 경로를 설명할 수 있는가
MCP · 업무 흐름 · 관제도구 호출, 승인·실행·재측정과 결과 관찰제안·승인·실행·회복 기록을 구분하는가

짧은 명세에서 개인 산출물로

예: “사이클100의 온도 그래프를 만들고, 선택한 값의 단위·원본 위치를 확인할 수 있게 해 줘.” 학생은 실제 출력과 원본을 대조합니다. 이렇게 구현 전에 요구와 확인 기준을 적는 방식이 SDD입니다.

공통 실습에서는 안내를 충분히 제공하고, 개인 PBL에서는 익숙한 스택으로 자신의 요구를 정의하고 결과를 만듭니다. 개인 PBL의 구체 시간 배분은 별도 확정 대상입니다.
