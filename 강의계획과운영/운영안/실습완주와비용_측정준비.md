# 사용자 리허설과 비용 측정 준비

2026-09-15 · 강사용 작업 문서. **로컬 기동·첫날 기능·기록 집계 도구 확인 / 중앙 중계 호환·학생 완주·비용은 미검증**.

사용자가 실습을 완주하고 비용을 측정한다. 에이전트는 실행 환경·회차 출발 상태·증거 기록을 준비한다. 기본 방향은 개인 PC 플랫폼과 중앙 LiteLLM, 코딩 기본 모델은 GPT-5.6 Luna다. 이 이름을 검증된 Provider API 모델 ID로 간주하지 않는다. 학생별 키에 연결할 실제 모델 식별자·API 방식·단가는 아직 채우지 않는다.

## 2. 서로 다른 모델 요청 경로

| 경로 기록값 | 호출 지점 | 측정 전에 확인할 것 |
|---|---|---|
| `coding` | 최종 선택할 코딩 에이전트 | 학생별 Virtual Key, 중앙 URL, 실제 Luna 모델 ID, 사용하는 API 방식, 파일 수정·터미널·도구 호출·스트리밍·긴 대화 지원 |
| `hydops_agent` | `hydops/b7_agent/agent.py:run_llm_agent`의 ChatOpenAI | 중계 경유 여부, 도구 호출과 구조화 Proposal, 한국어 근거·인용 검증. 현재 기본 모드는 offline |
| `platform_agent` | `labplatform/agents.py:run_agent_async`의 ChatOpenAI | 플랫폼 등록 모델과 중계 URL/키, MCP 도구 조회, 구조화 결과. 이 함수에는 HYDOPS offline 우회가 없음 |
| `embedding_index` / `embedding_query` | `hydops/b6_sop/search.py:_embedding_backend` | 인덱싱과 검색 질의 호출을 분리. 실제 임베딩 모델·차원·인덱스 일치. 코드에 LLM 모드 차원 1536이 고정돼 있음 |

`HYDOPS_LLM_MODEL`은 현재 앱 모델 설정이다. 코딩 에이전트 기본 Luna가 확정됐다고 이 변수까지 Luna로 자동 변경하지 않는다. `HYDOPS_EMBEDDING_MODEL`도 별도로 검증한다. 소스는 ChatOpenAI/OpenAIEmbeddings에 base URL을 명시 전달하지 않으며 현재 Compose에도 중앙 URL·학생별 키 전달이 없다. SDK 환경변수 지원과 컨테이너 전달을 확인한 뒤 연결해야 한다. 모델 이름만 바꿔 중계가 완성됐다고 하지 않는다.

offline 검색은 384차원 HashEmbeddings이고 LLM/유료 임베딩 시험이 아니다. offline 결과·비용을 실제 중계 품질·비용으로 환산하지 않는다. 플랫폼 업무 시작과 Watch 활성화는 별도 호출 경로이므로 무과금 준비 과정에 넣지 않는다.

## 3. 리허설 환경을 여는 순서

다음은 사용자가 실행을 시작할 때 코딩 에이전트에 맡길 작업이다. 현재 수행 결과가 아니다.

1. 개인 작업 폴더·버전·시작본 해시와 OS/RAM/가용 저장공간, Docker/코딩 에이전트 버전을 기록한다. 비밀값은 기록하지 않는다.
2. Docker Desktop Linux 엔진과 포트 충돌을 확인한다. 다른 작업을 종료하거나 기존 볼륨을 삭제하지 않는다.
3. [기존 로컬 준비 안내](../../플랫폼코드/LOCAL_SETUP.md)의 개인 Compose로 DB·API를 기동하고 상태를 확인한다. 최초 빌드 시간과 평소 재개 시간을 따로 잰다.
4. 회차에 필요한 UCI 원본/축약 입력과 run_id를 확인한다. 관제 화면의 합성 시뮬레이터 온도를 UCI 원본 적재 완료로 계산하지 않는다.
5. 초기 그래프·인덱스는 새 환경에 한 번 준비한다. 학생 수정 후 seed/bootstrap을 반복하면 사용자 변경에 영향을 줄 수 있다. 원문 `bootstrap_platform.py --all`은 강사 완성 시연 준비용이며 모든 회차 학생 출발본에 쓰지 않는다. P06/I07은 발행 전 상태 등 해당 회차 선행 결과까지만 준비한다.
6. 무과금 로컬 준비를 끝낸 뒤 중앙 LiteLLM의 실제 endpoint·모델 ID·학생별 키·사용량 기록을 확인한다. 키는 별도 비밀 저장 위치에서 전달하고 `.env` 본문이나 인증 헤더를 증거에 넣지 않는다. 코딩 도구 선택과 endpoint가 미정인 동안 가짜 작동 설정을 만들지 않는다.
7. 사용자가 2절의 경로별 실제 호출을 수행한다. 단순 텍스트 응답에 이어 도구 호출·구조화 결과·임베딩·MCP를 각각 확인한다. 실패나 모델 전환도 같은 시험 기록에 남긴다.
8. 승인된 회차 가이드로 처음부터 실행한다. 정상 결과뿐 아니라 해당 회차의 센서 오류·근거 없음·승인 거부·중복·미개선·자료 부족을 확인한다. 마지막에는 `stop` 후 `start`로 보존·재개를 확인하며 `down -v`로 초기화하지 않는다.

학생 PC 최소 사양, 최종 코딩 도구, 중앙 endpoint, 반별 인원은 미확정이다. 한 PC 리허설은 60명 동시 요청의 성공 증거가 아니며 동시성·429·대기시간은 별도 운영 시험으로 남긴다.

## 4. 기록 파일과 적는 시점

[회차별 측정 틀](../../작업기록/실습측정/회차별_측정틀.json)은 학교의 실전9·통합10 슬롯으로 구성했다. 모든 실제 값은 `null`, 상태는 `미측정`이다. 틀을 시험별 별도 파일로 복사하고 원문 교재/승인된 개편 버전 중 어느 가이드로 진행했는지 적는다. `null`은 미측정이며 비용 0이 아니다. 실제 측정하지 않은 날을 다른 날의 값으로 채우지 않는다.

- 시작: `trial_id`, 익명 참여자 ID, 반·회차, 가이드 버전·입력 해시·시작본, 환경과 실제 모델 ID를 기록한다. 원문 재현과 개편 가이드 리허설을 섞지 않는다.
- 진행: [요청 기록 양식](../../작업기록/실습측정/요청기록_양식.json)에 요청/시도 단위로 기록한다. 중앙 usage 원본을 비밀값 제거 후 보관하고 `evidence_path`로 연결한다. 한 학생 작업에서 생긴 여러 도구 호출·재시도·상위모델 전환도 포함한다.
- 종료: 학생이 요구를 이해하고 결과를 판단한 시간, AI 대기, 환경 복구, 강사 도움을 구분해 기록한다. 전체 경과시간에서 단순히 토큰 시간을 빼 학생 학습시간으로 추정하지 않는다. 겹친 구간은 중복 합산하지 않는다.
- 결과: 시작 상태→수행한 요구→기대한 관찰→실제 화면/출력→검증됨/실패/미검증을 적는다. 에이전트 완료 메시지와 학생의 실제 사용 결과를 구분한다.

### 요청 기록의 비용 규칙

사용량의 기준은 **하나의 실제 Provider 과금 요청/시도**다. 클라이언트와 중계의 같은 요청을 중복 더하지 않는다. 서로 다른 재시도는 별도로 남기며, 요청 ID가 없으면 확인 가능한 원본 로그 위치와 시각을 기록한다. 실패한 요청도 과금 여부 확인 전 0원 처리하지 않는다.

`provider_billed_usd`는 Provider의 청구/usage로 확인한 금액, `proxy_estimated_usd`는 중계 설정 단가로 계산된 추정액이다. 둘을 더하지 않는다. proxy 값만 있으면 단가 동기화 여부와 추정 상태를 명시한다. 입력·출력·캐시 토큰의 포함 관계는 실제 Provider 명세를 기록해 이중 계산을 방지한다. 모델별 단가 근거 URL·확인일·환율일·수수료·세금은 실제 측정 시 채운다.

### 기록 도구 사용

프로젝트 루트에서 코딩 에이전트가 [실습측정.py](../../제작도구/실습측정.py)를 사용합니다. 네트워크·모델 호출 없이 파일을 준비하고 기록을 집계합니다.

```powershell
python 제작도구/실습측정.py init 실1 TEST-001 MY-DAY01-P --file 실습자료/1일차/관측에서원본까지_실습가이드.md --file 실습자료/1일차/원문시작본/practical/mapping.py --file 플랫폼코드/data/raw/TS1.txt --file 플랫폼코드/data/raw/PS1.txt --file 플랫폼코드/data/raw/FS1.txt
```

새 기록은 `.runtime/measurements/MY-DAY01-P`에 생깁니다. `session.json`에는 학교 회차·가이드/입력 해시·Git 리비전을 남깁니다. 준비 시각과 실제 실습 시작 시각은 다릅니다. 통합반은 회차 `통1`과 해당 시작 노트북을 지정합니다. 같은 시험 ID로 재실행하면 덮어쓰지 않고 거부합니다.

현재 제작 PC에는 `DAY01-P-REHEARSAL`, `DAY01-I-REHEARSAL` 두 시험 폴더가 준비돼 있습니다. 아직 실습 시작·요청·금액을 입력하지 않았습니다. 개인 기록은 Git에서 제외합니다.

1. 실제 실습 시작 시 `session.json`의 환경·시작 시각을 채웁니다. 끝나면 종료 시각과 관찰 결과를 남깁니다.
2. `request-template.json`을 이용해 **실제 과금 요청/시도마다 한 JSON 객체**를 `requests.jsonl`의 한 줄로 기록합니다. 사용량 로그를 연결할 때 임의 금액이나 가짜 모델 ID를 채우지 않습니다.
3. `record_kind`는 실제 기록일 때만 `실측`, `status`는 `success`/`failed`/`cancelled`/`unknown`으로 적습니다. 원래 양식의 미측정 행은 집계에서 거부합니다.
4. `provider_name`, 실제 모델 ID, `logical_task_id`, 1부터 시작하는 `attempt`와 시간대 포함 시작·종료 시각을 남깁니다. 중계가 같은 논리 요청을 재시도하면 각 Provider 시도의 ID·시도 번호를 구분합니다.
5. `cost_scope`는 학생 1회 준비 `student_once`, 회차 반복 `session_recurring`, 강사·공용 준비 `shared_setup`, 추가 연습 `extra_practice` 중 실제 용도에 맞춥니다.
6. 비밀값·인증 헤더·프롬프트 본문을 제거한 근거 파일을 시험 폴더의 `evidence` 아래에 보관합니다. `evidence_path`는 시험 폴더 기준 상대 경로, `evidence_record_id`는 그 파일 안의 행 번호 또는 고유 요청 항목입니다. 파일이 있다고 청구액이 옳다고 자동 보증하지 않으므로 원자료와 대조합니다.

```powershell
python 제작도구/실습측정.py summary .runtime/measurements/DAY01-P-REHEARSAL
```

`--output`에 새 경로를 주면 JSON 집계 결과를 저장합니다. 집계는 경로·비용 범위·제공사·실제 모델별로 분리합니다. 제공사 확인 금액과 중계 추정액을 더하지 않고, 금액이 없는 요청은 `unknown_requests`로 남겨 `complete_total`을 null로 표시합니다. 확인된 일부 금액은 `known_subtotal`입니다. 요청이 없으면 미측정이며 0원 실측이 아닙니다. 토큰은 캐시·추론 포함 규칙이 서로 다를 수 있어 자동 합산하거나 임의 단가로 비용을 만들지 않습니다.

중복 Provider 요청 ID, 같은 중계 요청의 같은 시도, 같은 근거 항목은 중복 오류로 거부합니다. 누락·중복을 해결한 뒤 집계하며 실패 요청을 삭제해 총액을 줄이지 않습니다. 이 도구는 usage 내보내기 자동 연결이나 청구서 대조까지 수행한 것이 아닙니다.

## 5. 과정 비용 환산

먼저 학생 한 명의 **회차별 반복 비용**을 코딩/앱/임베딩 경로별로 구한다. 설치·첫 인덱싱 같은 학생별 1회 비용과 중앙 준비의 공용 비용은 별도 집계한다. 여러 사람이 측정하면 학생별로 비교하고 표본 수·변동 범위를 함께 남긴다.

반별 인원을 N실, N통이라고 할 때:

`수업 모델비 = N실 × (실전 학생별 1회 준비비 + 실1~실9의 학생 1인 반복비 합) + N통 × (통합 학생별 1회 준비비 + 통1~통10의 학생 1인 반복비 합)`

`운영 총비용 = 수업 모델비 + 승인된 온라인/개인 연습 사용비 + 강사/공용 준비 모델비 + 중앙 중계·DB·저장·네트워크 비용 + 결제 수수료·세금`

N실+N통=60은 전체 인원 조건이며 두 반 인원을 30명씩으로 가정하지 않는다. **60명×19일**로 계산하지 않는다. 실전 학생은9일, 통합 학생은10일이다. 온라인 이론 시수를 모델 사용시간으로 바꾸지 않는다. 비용 하나라도 미측정이면 총비용은 미완성 추산으로 표시한다.

예산 상한·quota·자동 fallback은 비용 측정값과 다르다. 원문 운영안의 값을 그대로 작동 설정에 넣지 않는다. 상위 모델 사용은 허용된 방향이지만 자동 전환을 새로 도입했다는 뜻은 아니다.

## 6. 이번 준비의 완료 범위

작성됨: 원문 회차 기반 측정 슬롯19개, 요청 기록 양식, 호출 경로·환경 선행조건·환산 방법, 개인 시험 폴더 준비 및 요청 집계 도구. 확인됨: 제작 PC 네 서비스 기동·HTTP200, 첫날 기능 검사와 실제 화면, 합성 기록으로 집계 도구12개 검사. 실제 사용자 기록은 미측정이다. 미완료: 중앙 중계 연결 설정, 학생별 키 발급, API 모델 제공 여부와 호환, 전 회차 합류 배포본, 사용자 실습 완주·비용 실측·청구서 대조·전체 과정 비용 환산.

이 문서는 학생 배포용 설치 가이드나 완주 결과가 아니다. 사용자 의견으로 교과 편성이 정해지면 각 측정 슬롯의 `guide_version`과 실제 시작본을 연결한다.
