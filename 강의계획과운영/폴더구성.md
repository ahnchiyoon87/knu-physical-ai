# 협업용 폴더 구성 — 최종 적용본

사용자가 승인한 한글 구조를 `D:/work/study/경남대 제조 피지컬 AI`에 적용했다. 최상위 숫자 접두사를 없애고 폴더 이름으로 자료의 역할을 알 수 있게 했다.

```text
경남대 제조 피지컬 AI/
├─ 강의계획과운영/   실라버스·일정·운영안·받은자료·인계
├─ 이론자료/         온라인 슬라이드 구성·대본
├─ 실습자료/         일차별 가이드·시작코드·완성코드
├─ 플랫폼코드/       교육용 플랫폼 실행 코드
├─ 공용자료/         그림·화면 캡처·공용 데이터
├─ 제작도구/         자료 준비·검사·배포 프로그램
├─ 학생배포본/       학생에게 전달할 ZIP·PDF
└─ 작업기록/         변경 내용·검증 결과·보고
```

## 어디서 작업하나요?

| 할 일 | 위치 |
|---|---|
| 다음 세션 시작 | [인계.md](인계.md) |
| 실라버스 검토 | [공통실라버스_초안.md](공통실라버스_초안.md) |
| 학교 일정 확인 | 받은자료의 엑셀과 학교편성_기존초안.json. 초안의 챕터명은 미확정 |
| 학생 환경·모델 제공 계획 | [60명 AI 이용 운영안](운영안/60명_AI이용운영안.md) |
| 1일차 실습 수정 | 실습자료/1일차의 실습가이드_초안.md와 시작코드 |
| 플랫폼 수정 | 플랫폼코드. 내부 영문 코드 구조는 유지 |
| 가벼운 준비 검사 | 프로젝트 루트에서 python 제작도구/check_preparation.py |

온라인은 `이론자료/1회차`, 오프라인은 `실습자료/1일차`처럼 실제 제작할 회차부터 만든다. 두 반의 공통 자료를 복제하지 않고 편성표에서 연결한다. 이론자료·공용자료·학생배포본은 현재 안내만 있으며 완성 자료는 아직 없다.

시작코드는 해당 일차에 합류할 수 있는 상태, 완성코드는 그 일차가 끝난 비교 기준이다. 학생 공개는 일차별로 정하며 프로젝트 전체를 그대로 압축하지 않는다. 플랫폼 전체를 매번 수작업 복제하는 대신 필요한 버전·변경분을 기준으로 배포하는 방법은 후속 제작에서 구현한다.

기존 리뉴얼과 대표님 저장소는 원본·참고로 보존한다. 수정하는 정본은 이 프로젝트 한 곳이다. 이번 작업은 구조·경로 이관이며 강의 재집필·UI 개편·유료 모델 실행·전체 실습 검증은 포함하지 않는다.
