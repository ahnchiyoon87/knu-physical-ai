# 관측과 출처

센서값의 단위·시간·출처를 이해하고, 처리된 결과에서 원본으로 돌아가는 방법을 배웁니다.

## S01 숫자 하나에서 출처까지

**오늘 배울 것: 화면의 값을 원본 관측까지 설명하기**

온도53°C라는 숫자만으로는 부족합니다.

- 무엇의 온도인가: 설비와 센서
- 어떤 구간인가: 사이클과 경과 초
- 어디서 왔는가: 실제 센서 파일 또는 합성 시뮬레이터
- 어떤 처리를 했는가: 원래 샘플 또는1초 요약

다음: 이 설명이 전체 제조 운영에서 왜 필요한가?

## S02 관측이 업무의 출발점이 된다

설명용 흐름도. 실제 실행 화면이 아닙니다.

```text
센서 관측 → 품질 확인·저장 → 이상 사건
                              ↓
설비 관계·SOP 근거 → 조치 제안 → 사람 승인
                              ↓
                   시뮬레이터 조치 → 새 관측 확인
```

**잘못된 설비나 구간을 읽으면 이후의 근거와 조치도 다른 대상을 향할 수 있습니다.** 오늘은 이 흐름의 출발점인 관측과 출처를 사용합니다.

## S03 제공된 시스템에서 역할을 나누어 본다

| 블록 | 역할 | 첫날에 하는 일 |
|---|---|---|
| B1 데이터 | 파일을 읽거나 시뮬레이터의 관측을 생성 | 원본 파일·재생·출처 확인 |
| B2 품질 | 관측에 품질 정보를 붙임 | 제공 검사기를 사용하고 결과 필드를 확인 |
| B3 PostgreSQL | 관측과 실행 묶음을 저장·조회 | 실전 첫날, 통합 다음 회차에 연결 |

Python은 데이터를 처리하는 코드, pandas는 표 형태 데이터를 다루는 도구입니다. 코딩 에이전트가 이 도구를 사용하도록 작업을 맡기고, 학생은 결과를 확인합니다.

## S04 실제 관측과 합성 관측

| UCI 파일 재생 | 교육용 시뮬레이터 |
|---|---|
| 실험 설비에서 수집된 센서값을 다시 읽음 | 프로그램의 상태와 가정으로 값을 만듦 |
| 원본 사이클·파일 위치로 추적 | 실행 상태·조치 시점으로 추적 |
| 조치해도 과거 파일값 자체는 바뀌지 않음 | 구현된 조치가 이후 생성값에 영향을 줄 수 있음 |

**둘 모두 수업에 쓰지만 출처와 할 수 있는 검증이 다릅니다.** CSV 재조회만으로 조치 후 회복을 증명할 수 없습니다.

## S05 한 줄이 나타내는 시간

UCI 파일의 한 줄은60초 운전 사이클입니다.

```text
파일의101번째 줄 → 코드에서 origin_cycle_id=100
그 줄 안의 위치 → 센서별 측정 간격을 적용해야 시간을 알 수 있음
```

사이클 번호는 이 수업 코드에서0부터 셉니다. 행 번호와 사이클 번호를 무심코 같게 쓰면 다른 원본을 읽게 됩니다.

## S06 같은60초를 서로 다른 횟수로 측정한다

| 센서 | 측정량·단위 | 샘플링 주파수 |60초의 값 개수 |
|---|---|---:|---:|
| TS1 | 온도·°C |1Hz |60 |
| FS1 | 유량·L/min |10Hz |600 |
| PS1 | 압력·bar |100Hz |6,000 |

**Hz는1초에 측정한 횟수입니다.** 값 개수가 많아도 관측한 전체 시간은 같습니다.

## S07 같은 열 번호가 같은 시점은 아니다

아래는 간격을 설명하는 개념도입니다.

```text
TS1  1초 구간: [ 값1개 ]
FS1  1초 구간: [ 값10개 ]
PS1  1초 구간: [ 값100개 ]
```

각 파일의 두 번째 숫자를 한 줄에 붙이는 것만으로 같은 시점의 온도·유량·압력을 얻을 수 없습니다. 먼저 **같은 시간 구간**을 정합니다.

## S08 한 구간을 요약할 때 남길 정보

| 정보 | 알 수 있는 것 | 이것만으로 알 수 없는 것 |
|---|---|---|
| 평균 | 구간의 대표적인 값 | 구간 안에서 움직인 전체 모양 |
| 최솟값·최댓값 | 변화 범위 | 값이 나온 순서 |
| 개수 | 요약에 사용한 샘플 수 | 모든 샘플의 정확성 |

압력의 순간 변화를 평균 하나로 숨기지 않도록 범위와 개수도 남깁니다. 원본 위치도 남겨 필요할 때 다시 읽습니다.

## S09 첫 값과 평균은 실제로 다르다

UCI PS1·사이클100·첫1초의 원본100개를 직접 계산한 값입니다.

| 첫 측정값 |1초 평균 |최솟값 |최댓값 |개수 |
|---:|---:|---:|---:|---:|
|147.21 |170.1621 |141.27 |189.88 |100 |

단위: bar. **첫 값147.21을 평균으로 표시하면 다른 계산을 한 것입니다.** 숫자가 표시됐다는 사실만으로 요청한 집계가 구현됐다고 할 수 없습니다.

## S10 관측 레코드는 값과 맥락을 함께 담는다

| 필드 | 읽는 말 |
|---|---|
| asset_id / sensor_id | 어느 설비 / 어느 센서 |
| raw_value / unit | 제공 관측 형식의1초 값 / 단위 |
| origin_cycle_id / elapsed_s | 원본 사이클 / 그 안의 경과 초 |
| ts | 실습용 재생 시각 |
| agg |1초 구간의 범위·개수 등 추가 통계 |
| is_synthetic | 합성 관측 여부 |

여기서 `raw_value`는 제공 코드의 필드 이름입니다. 고주파 센서에서는 이미1초 평균으로 바뀐 값이므로 원본의 단일 샘플과 구별합니다.

## S11 재생 시각과 원본 시각을 구별한다

```text
원본 위치: 사이클100의30초째
재생 시각: 수업 프로그램이 정한 시작 시각 +30초
```

재생 시작 시각을 바꿔도 원본에서 읽은 값과 위치는 바뀌지 않습니다. `ts`를 실제 실험이 수행된 날짜로 설명하지 않습니다.

## S12 세 사이클을 이어도 출처는 유지한다

```text
재생 경과  0~59초     60~119초    120~179초
원본       사이클100   사이클101   사이클102
각 사이클  elapsed_s는 각각0부터59까지
```

3사이클×60초×3센서 = **540개1초 관측**. 원본 사이클 번호와 재생 시각이 모두 있어야 이어 붙인 결과에서 원본을 찾을 수 있습니다.

## S13 최근60초를 묻기 전에 실행 묶음을 정한다

`run_id`는 이번 실행 묶음의 식별자입니다.

| 조건 | 포함될 수 있는 것 |
|---|---|
| HYD-01만 선택 | 같은 설비 이름을 쓰는 다른 실행의 관측 |
| HYD-01 + 내 run_id 선택 | 내가 확인하려는 실행 묶음의 관측 |

**‘최근’의 범위도 질문의 일부입니다.** 실전 첫날 DB 조회에서 사용하고, 통합반은 저장본을 다음 회차 DB로 연결하며 확인합니다.

## S14 에이전트에 맡길 요구와 학생의 판단

요구 예시:

> 세 센서를 같은1초 구간으로 요약해 줘. 단위·출처·샘플 수를 보존하고, 저장된 결과에서 원본의 같은 구간으로 돌아가 비교할 수 있어야 해.

학생이 확인할 것:

1. 요청이 무엇을 만들라는 뜻인지 이해한다.
2. 결과 파일이나 화면을 직접 사용한다.
3. 같은 입력·구간을 비교했는지 판단한다.
4. 요구와 다르면 차이를 말하고 수정 요청한다.

## S15 품질 규칙 통과와 설비 정상은 다르다

| 같은 사이클100~102에서 확인한 것 | 뜻 |
|---|---|
| 관측540개가 제공 B2 규칙에서 OK | 해당 센서 품질 규칙에 걸리지 않음 |
| profile의 냉각기 상태 라벨3 | 냉각기 고장에 가까운 상태 범주 |
| stable_flag=1 | 정적 안정 상태에 아직 도달하지 않았을 수 있음 |

**측정된 관측을 사용할 수 있어도, 그 관측이 나타내는 설비 상태는 이상일 수 있습니다.** 두 결과는 모순이 아닙니다.

## S16 기준값의 근거에는 계산 범위도 포함된다

제공 품질 설정의 설명에 등장하는 인접1초 평균의 최대 변화폭:

| 센서 | 전체2,205개 사이클의 최대 | 단위 |
|---|---:|---|
| TS1 |0.227 |°C |
| PS1 |40.2613 |bar |
| FS1 |10.9423 |L/min |

이 계산에는 냉각 이상 상태도 포함됩니다. 정상 운전 구간만 골라 계산한 값이라고 설명하지 않습니다. **무슨 데이터를 대상으로 계산했는지까지 근거입니다.**
