# 제조 데이터를 판단으로 연결하는 시스템

## S01 냉각 이상 대응의 전체 흐름

| 1. 관측 | 2. 품질 확인·저장 | 3. 이상 사건 | 4. 적용 근거 |
|---|---|---|---|
| 5. 조치 제안 | 6. 사람 승인 | 7. 조치 | 8. 새 관측 |

1~4에서 판단할 근거를 모으고, 5~8에서 조치와 이후 상태를 확인합니다.

**이번 영상의 목표: 각 단계가 무엇을 확인하며, 학생이 어떤 결과를 판단하는지 설명하기**

## S02 온도53°C만으로 알 수 없는 것

설명용 예시입니다.

| 확인할 정보 | 예시 | 빠지면 생기는 문제 |
|---|---|---|
| 대상 | HYD-01의 TS1 | 다른 설비의 값을 판단할 수 있음 |
| 단위 | °C | 서로 다른 측정량을 혼동함 |
| 구간 | 특정 사이클의 경과30초 | 이전 값과 현재 값을 혼동함 |
| 출처 | UCI 파일 또는 합성 시뮬레이터 | 데이터가 보여 줄 수 있는 범위를 잘못 해석함 |

숫자에 **대상·단위·구간·출처**를 붙여야 관측을 설명할 수 있습니다.

## S03 데이터를 받아 판단 가능한 기록으로 만들기

| 역할 | 입력 | 남는 결과 |
|---|---|---|
| 데이터 수집·재생 | 센서 파일 또는 시뮬레이터 | 값과 시점·출처 |
| 품질 확인 | 관측과 품질 규칙 | 사용 여부를 판단할 품질 정보 |
| 저장·조회 | 관측 레코드와 실행 정보 | 같은 실행·구간을 다시 찾을 수 있는 기록 |

품질OK는 **제공 센서 품질 규칙을 통과했다는 뜻**입니다. 설비 전체의 정상 판정은 아닙니다.

## S04 설비 관계와 적용 문서

관측의 설비 ID → 그 설비의 센서·허용 조치 → 적용되는 현행 SOP

SOP는 작업 절차를 담은 문서입니다. 온도가 비슷해도 다른 설비의 절차를 그대로 적용할 수는 없습니다.

| 확인 | 판단에 필요한 이유 |
|---|---|
| 어느 설비에 적용되는가 | 대상이 다르면 조치도 다를 수 있음 |
| 현재 유효한 버전인가 | 폐기된 절차의 사용을 막음 |
| 지금 사건에 해당하는가 | 센서 오류와 냉각 이상을 구분함 |

## S05 제안·승인·실행·회복

| 결과 | 알 수 있는 것 | 다음 확인 |
|---|---|---|
| 조치 제안 | 도구와 근거로 어떤 조치를 제시했는가 | 적용 조건과 사람의 승인 |
| 승인 기록 | 누가 어떤 조치와 값을 허용했는가 | 실행 조건과 실제 실행 결과 |
| 명령 성공 | 명령이 수행됐는가 | 조치 이후 새 관측 |
| 회복 판단 | 새 관측이 회복 기준을 충족했는가 | 종결·추가 확인·이관 |

**명령 성공만으로 회복을 선언하지 않습니다.**

## S06 파일 재생과 시뮬레이터

| UCI 파일 재생 | 교육용 합성 시뮬레이터 |
|---|---|
| 수집된 센서값을 다시 읽음 | 프로그램의 상태로 새 값을 생성 |
| 원본 사이클·위치로 추적 | 실행 ID·상태·조치 시점으로 추적 |
| 조치해도 과거 파일값은 바뀌지 않음 | 구현된 조치가 이후 생성값에 영향을 줄 수 있음 |
| 읽기·집계·출처 추적을 확인 | 승인·조치·재측정의 연결을 확인 |

시뮬레이터 결과는 해당 교육용 모델의 결과입니다. 실제 공장의 효과로 일반화하지 않습니다.

## S08 구현을 맡길 때 필요한 요구

‘온도 그래프를 만들어 줘’에 추가할 조건

| 항목 | 요구 예시 |
|---|---|
| 목적 | 표시된 값을 원본에서 찾을 수 있게 한다 |
| 입력 | 지정한 UCI 사이클의 TS1 관측 |
| 동작 | 경과 초별 온도를 표시하고 원본 위치를 함께 남긴다 |
| 확인 기준 | 단위·사이클·경과 초가 원본과 일치해야 한다 |

SDD: 구현 전에 필요한 동작과 확인 기준을 명세로 정리하는 방식

## S09 이해 확인

1. 부하 감소 뒤 과거 UCI 파일을 다시 읽었습니다. 온도가 내려간 구간이 보이면 이번 조치의 효과라고 할 수 있을까요?
2. 에이전트가 ‘승인받았다’고 답했습니다. 실제 실행 전에 어떤 기록을 확인해야 할까요?
3. 품질OK인 높은 온도가 보입니다. 센서 품질 확인 다음에는 무엇을 확인해야 할까요?

판단 이유를 생각한 뒤 해설과 비교합니다.

## S10 결과를 수용할 근거

| 출력 | 수용 전에 확인할 것 |
|---|---|
| 온도 곡선만 있음 | 대상·단위·원본 위치·시간축 |
| ‘테스트 통과’라는 보고만 있음 | 어떤 입력과 조건을 검사했는지, 실제 출력 |
| 과거 파일에서 온도가 하락함 | 이번 조치 뒤 생성된 관측인지 |
| ‘승인 완료’라는 문장만 있음 | 해당 사건·조치·값에 대한 실제 승인 기록 |

결과가 요구에 맞으면 수용합니다. 부족하면 빠진 조건과 관찰 결과를 들어 수정을 요청합니다.

## S11 다음 판단의 출발점

제안에는 적용 근거를, 실행에는 승인을, 회복 판단에는 새 관측을 확인합니다.

학생은 제공 스택을 직접 사용하고 **요구와 결과를 대조**합니다.
