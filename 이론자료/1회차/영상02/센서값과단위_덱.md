# 숫자 하나를 관측으로 읽기

## S01 화면에 45만 남았다

**45**

무엇을 측정했는가? → 어떤 단위인가? → 어느 설비인가?

설명용 상황: 온도 화면을 만들어 달라고 했는데 숫자만 표시됐습니다.

## S02 숫자 옆에 측정 대상을 붙인다

45 → **온도 45**

| 측정 대상 | 알고 싶은 것 |
|---|---|
| 온도 | 얼마나 뜨겁거나 차가운가 |
| 압력 | 유체가 얼마나 강하게 미는가 |
| 유량 | 일정 시간에 유체가 얼마나 지나가는가 |

세 값은 같은 설비를 서로 다른 측면에서 설명합니다.

## S03 단위는 숫자의 의미를 완성한다

온도45 → **온도45°C**

| 제공 센서 코드 | 측정 대상 | 단위 |
|---|---|---|
| TS1 | 온도 | °C |
| PS1 | 압력 | bar |
| FS1 | 유량 | L/min |

예시 숫자가 같아도 **45°C · 45bar · 45L/min**은 서로 다른 관측입니다.

## S04 이름만 바꾸면 값도 바뀔까

```text
원본 값 + 원본 단위
        ↓ 필요한 변환 계산
변환된 값 + 변환된 단위
```

라벨만 교체 ≠ 단위 변환

같은 대상·같은 단위인지 확인한 뒤 비교합니다.

## S05 같은 온도 센서가 두 대에 있다

```text
HYD-01 ── TS1 ── 온도
HYD-02 ── TS1 ── 온도
```

`asset_id`: 어느 설비인가

`sensor_id`: 그 설비의 어느 센서인가

센서 코드만 같다고 같은 설비의 값은 아닙니다.

## S06 사람이 읽는 이름과 연결할 ID

| 역할 | 이 수업의 예 |
|---|---|
| 사람이 읽는 설비 이름 | 유압설비 1호기 |
| 설비를 연결하는 ID | HYD-01 |
| 관측에서 쓰는 센서 코드 | TS1 |
| 그래프에서 쓰는 센서 ID | HYD-01.TS1 |

문자열을 추측해 붙이지 말고 **해당 저장소의 약속**을 확인합니다.

## S07 SENSOR_SPEC은 읽는 방법의 안내표

```python
"PS1": {"file": "PS1.txt", "hz": 100, "unit": "bar"}
```

PS1 → 어떤 센서 항목을 찾는가

file → 어떤 파일을 읽는가

unit → 읽은 값을 어떤 단위로 해석하는가

hz → 1초에 몇 번 측정했는가

## S08 표가 있어도 연결은 확인한다

```text
원본 PS1.txt → SENSOR_SPEC의 PS1 → 관측 PS1 / bar → 화면 압력 / bar
```

확인할 세 가지: **파일 · 센서 코드 · 단위**

프로그램 실행 성공과 올바른 대응은 서로 다른 확인입니다.

## S09 에이전트에게 결과의 조건을 전달한다

| 요구 항목 | 이번 화면의 조건 |
|---|---|
| 목적 | 표시된 값이 무엇인지 설명할 수 있다 |
| 입력 | 지정한 설비·센서의 제공 파일 |
| 동작 | 설정에 따라 읽고 대상·값·단위를 표시한다 |
| 확인 | 원본·설정·관측·화면의 대응이 일치한다 |

구현은 에이전트에게, 수용 판단은 실제 결과로 합니다.

## S10 세 출력을 그대로 사용해도 될까

설명용 출력입니다. **어떤 확인을 요청할지와 그 이유**를 먼저 생각해 보세요.

| 번호 | 출력 |
|---|---|
| ① | TS1: 45 |
| ② | HYD-01 / PS1 / 45 / °C |
| ③ | HYD-01 / TS1 / 45 / °C |

표시된 숫자만으로 지금 설비 상태를 판단할 수 있을까요?

## S11 빠진 정보와 잘못된 연결 찾기

| 설명용 출력 | 먼저 확인할 것 |
|---|---|
| TS1: 45 | 설비와 단위 |
| HYD-01 / PS1 / 45 / °C | 센서 코드와 단위의 대응 |
| HYD-01 / TS1 / 45 / °C | 측정 시점과 원본 위치 |

보기 좋은 출력도 필요한 정보가 빠질 수 있습니다.
