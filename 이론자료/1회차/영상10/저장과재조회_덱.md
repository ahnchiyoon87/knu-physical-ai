# 관측을 보관하고 다시 읽기

## S01 프로그램을 닫은 뒤에도 다시 읽으려면

품질 표시까지 붙은 관측을 만들었습니다.

프로그램 안의 목록 → **DB에 저장한 기록**

목표: 다음에 다시 접속해 같은 관측을 읽기

## S02 CSV와 DB는 어디에 쓸까

| 방식 | 이번 수업에서의 쓰임 |
|---|---|
| CSV 파일 | 선택한 결과를 파일로 내보내고 전달하기 |
| PostgreSQL | 실행별 관측을 쌓고 필요한 조건으로 조회하기 |

파일 내보내기와 DB 저장은 각각 확인합니다.

## S03 어느 DB에 접속했는지도 결과의 일부다

```text
학생의 실행 코드 → PostgreSQL 접속 → 지정한 데이터베이스
```

접속할 주소·포트·DB 이름을 구분합니다.

저장과 조회가 **같은 대상**을 사용하는지 확인합니다.

## S04 테이블은 저장할 항목과 종류를 정한다

관측을 보관하는 테이블: **observation**

| 항목 예 | 저장할 정보 종류 |
|---|---|
| sensor_id·unit | 글자 |
| raw_value·value | 숫자 |
| ts | 시간대가 있는 시각 |
| agg | 구조가 있는 집계 정보 |

테이블 정의를 스키마라고 부릅니다.

## S05 실행 정보와 관측은 두 테이블로 연결한다

| 테이블 | 담는 정보 |
|---|---|
| run | 실행 이름·원천 종류·시나리오 등 |
| observation | 그 실행에서 만든 개별 관측 |

observation의 **run_id → run의 run_id**

등록한 실행에 관측을 연결합니다.

## S06 DB의 행 번호는 관측 출처가 아니다

observation에는 DB가 부여하는 **id**가 추가됩니다.

| 항목 | 구분할 역할 |
|---|---|
| id | DB 안의 관측 행 식별 |
| run_id | 실행과 연결 |
| origin_cycle_id | 원본 사이클 출처 |

행 번호만 보고 원본 위치를 추측하지 않습니다.

## S07 비어 있는 값도 DB에 의미를 남긴다

프로그램의 **None → DB의 NULL**

value가 NULL인 행에도 다음 항목을 남깁니다.

- raw_value
- quality_flag
- 설비·센서·시각·출처

빈 값을0으로 바꾸지 않습니다.

## S08 제공 함수가 관측을 보내는 순서

```text
create_run → 품질 처리한 관측 → insert_observations
```

insert_observations는 **COPY**로 관측을 전달합니다.

COPY는 여러 행을 DB에 넣는 제공 함수의 적재 방식입니다.

## S09 DB가 거부한 내용을 확인한다

제공 적재 함수로 확인한 실행 결과입니다.

| 입력 문제 | 실제 결과 |
|---|---|
| 등록하지 않은 run_id | 연결 조건 위반으로 거부 |
| 필수 unit이 비어 있음 | 필수값 조건 위반으로 거부 |

오류를 없애기 전에 **어떤 조건을 어겼는지** 읽습니다.

## S10 저장한 뒤 새로 접속해 대조한다

실제 제공 load_cycles 실행: **540개 저장 반환**

별도 프로세스의 DB 조회: **540개 확인**

원본에서 다시 만든 관측과 전체 행의 **값·품질·단위·시간·출처·집계**를 대조했습니다.

## S11 중간에 실패했다면 실제 저장 상태부터 본다

load_cycles는 사이클마다 관측을 적재합니다.

한 적재가 실패했다고 **이전 적재까지 모두 취소됐다고 가정하지 않습니다.**

확인할 것: 실행 존재·관측 개수·누락 구간

재실행 전 이미 저장된 범위를 확인합니다.
