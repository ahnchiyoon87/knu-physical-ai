# 원하는 실행과 시간 구간 조회

## S01 지금 보고 싶은 관측을 먼저 정한다

저장한 전체 관측 중 무엇을 볼까요?

**어느 설비 · 어느 실행 · 어느 센서 · 어느 시간 구간**

예: 이번 재생 실행의 압력 센서, 마지막60초

## S02 SQL은 어떤 항목을 어디에서 읽을지 표현한다

설명용 조회 예입니다.

```sql
SELECT ts, sensor_id, value
FROM observation
WHERE sensor_id = 'PS1'
```

SELECT: 읽을 항목 / FROM: 대상 테이블 / WHERE: 선택 조건

## S03 여러 조건을 함께 만족하는 행을 고른다

```text
설비 = HYD-01
AND 실행 = 내가 선택한 실행
AND 센서 = PS1
```

AND: **세 조건을 모두 만족**

조건 하나가 빠지면 선택 범위가 달라집니다.

## S04 조회 문장과 조건값을 따로 전달한다

제공 코드의 조건 일부입니다.

```text
WHERE asset_id = %s
전달할 값: HYD-01
```

%s는 실제 조건값을 전달할 자리입니다.

함수 인수와 조회 결과를 대조합니다.

## S05 읽는 순서도 지정한다

제공 함수의 마지막 조건:

```sql
ORDER BY ts, sensor_id
```

시각순으로, 같은 시각에서는 센서 이름순으로 읽습니다.

저장한 순서와 조회 순서를 같은 것으로 가정하지 않습니다.

## S06 최근이라는 말의 기준을 확인한다

제공 recent_window의 기본 끝 시각:

**선택한 설비·실행의 max(ts)**

끝 시각을 별도로 지정하면 그 값을 사용합니다.

센서 조건은 이후 관측 선택에 적용됩니다.

## S07 기본 마지막60초의 결과를 읽는다

같은 날짜·UTC 기준입니다.

| 확인 항목 | 실제 결과 |
|---|---|
| 마지막 관측 시각 | 00:02:59 |
| 선택된 시각 | 00:02:00~00:02:59 |
| 전체 센서 | 180행 |
| PS1만 선택 | 60행 |
| 원본 사이클 | 102 |

## S08 끝 시각을 옮기면 두 사이클을 함께 읽는다

끝 시각until = **00:01:30**, 길이60초

실제 선택: **00:00:31~00:01:30**

| 원본 사이클 | 센서별 행 수 | 세 센서 합계 |
|---|---:|---:|
| 100 | 29 | 87 |
| 101 | 31 | 93 |
| 합계 | 60 | 180 |

## S09 끝 경계를 포함하는 조회 조건

제공 함수는 관측의 ts를 다음 조건으로 고릅니다.

```text
ts > 끝 시각 - 60초
AND ts <= 끝 시각
```

00:00:30은 제외 / 00:01:30은 포함

시작도 포함하도록 바꾸면 이 예에서는 **183행**이 됩니다.

## S10 실행 조건이 없으면 다른 결과가 최신이 된다

같은 설비에 재생 시작이1시간 뒤인 별도 실행도 저장했습니다.

| 조회 조건 | 선택된 마지막 구간 |
|---|---|
| 내 실행 지정 | 00:02:00~00:02:59 |
| 실행 조건 없음 | 01:02:00~01:02:59 |

**둘 다180행이어도 실행이 다릅니다.**

## S11 빈 결과를0으로 해석하지 않는다

등록하지 않은 실행을 지정한 실제 조회 결과: **0행**

0행 ≠ 센서값0

확인 순서: DB 대상 → 실행 이름 → 센서·시간 조건 → 저장 여부

**요청 예시**
