# 관측을 사건으로 바꾸는 기준

## S01 높은 값 하나로 시작하지 않는다

관측의 품질 → 비교 기준 → 지속 조건 → 사건 등록 → 사람의 확인

**높은 값이 있다는 사실과 대응할 사건이 있다는 판단을 구분합니다.**

## S02 데이터에 맞는 비교를 선택한다

| 입력 | 제공 감지 방식 |
|---|---|
| UCI 60초 사이클 | 같은 경과 초의 기준과 온도 차이 비교 |
| 합성 시뮬레이터 스트림 | 유효 온도60°C 초과 관측10개 |

60°C는 교육용 시뮬레이터 설정입니다. UCI 실제 설비의 운전 기준이 아닙니다.

## S03 같은 운전 위치끼리 비교한다

사이클 시작의 온도 ↔ 기준 사이클 시작의 온도

사이클 끝의 온도 ↔ 기준 사이클 끝의 온도

위상은 사이클 안의 위치입니다. **위치에 따른 정상 변화와 기준에서 벗어난 변화를 구분합니다.**

## S04 흔들림과 기준 차이를 계산한다

이동평균: 연속된 주변 값의 평균

잔차: 비교 대상 온도 − 같은 위상의 기준 온도

허용 한계: `max(k_sigma × 기준 표준편차, min_delta_c)`

평활·허용 한계·지속 시간을 각각 구분합니다.

## S05 기준과 시험을 나눈다

| 역할 | 제공 데이터 구성 |
|---|---|
| 기준 | 냉각기100%·안정 상태에서 선정한244사이클 |
| 시험 | 기준과 겹치지 않는180사이클 |
| 시험 라벨 | 냉각기100%·20%·3% 각각60개 |

profile은 평가용입니다. 탐지 입력에 정답을 넣지 않습니다.

## S06 지속 조건은 유효 관측을 센다

높은 OK6개 → MISSING1개 → 높은 OK4개

유효 기준 초과10개, 처음과 끝의 시각 차이10초

- MISSING·SPIKE 단발: 세지 않고 기존 카운트 유지
- 유효 값이 기준 이하 또는 GAP: 카운트 초기화

이 구현에서 ‘10개’가 언제나 끊김 없는 벽시계10초를 뜻하지는 않습니다.

## S07 원시 급등값을 다시 세지 않는다

높은 OK9개 + SPIKE1개 → 유효 기준 초과는9개

`raw_value`: 근거 보존

`value`와 `quality_flag`: 탐지 사용 여부

품질 검사에서 제외한 값을 탐지에서 다시 사용하면 앞 단계의 판단이 사라집니다.

## S08 신호와 사건은 개수가 다를 수 있다

실제 합성 경계 스트림 비교:300초, 시드7, 냉각효율0.5

| 지속 조건 | 탐지 신호 | 새 사건 | 중복 억제 |
|---|---:|---:|---:|
| 1초 | 65 | 1 | 64 |
| 5초 | 0 | 0 | 0 |
| 10초 | 0 | 0 | 0 |

지속 조건은 신호를, 열린 사건 확인은 중복 등록을 제어합니다.

## S09 같은 설비와 유형의 열린 사건을 찾는다

신호 도착 → 같은 설비·유형의 열린 사건 조회

- 있음: 기존 사건 사용
- 없음: 새 사건 등록

다른 설비나 다른 유형은 별도 사건입니다. 이전 사건이 닫힌 뒤의 새 신호도 구분합니다.

## S10 평가 결과는 네 칸으로 읽는다

| | 탐지 이상 | 탐지 이상 아님 |
|---|---|---|
| 평가 라벨 이상 | TP: 발견 | FN: 누락 |
| 평가 라벨 정상 | FP: 오탐 | TN: 정상 구분 |

기본 설정의 고정 시험: TP120·FN0·FP1·TN59.

‘정상’은 이 평가의 냉각기 라벨 기준이며 모든 설비 부품의 정상 보증이 아닙니다.

## S11 지속시간을 늘리면 항상 오탐이 줄까

고정 시험180개, 4σ·최소차이3°C·평활5초 유지:

| 지속 | 오탐 | 평균 감지 지연 |
|---|---:|---:|
| 1초 | 1 | 0초 |
| 5초 | 1 | 4초 |
| 10초 | 1 | 9초 |
| 20초 | 1 | 19초 |

이 데이터에서는 오탐이 같고 지연이 증가했습니다.

## S12 조건 하나씩 바꾸어 이유를 찾는다

지속10초·평활5초 고정, 실제 비교:

| 기준 편차 배수 | 최소차이1°C 오탐 | 최소차이3°C 오탐 |
|---|---:|---:|
| 2σ | 4 | 1 |
| 4σ | 3 | 1 |

**조건을 여러 개 바꾼 결과만으로 한 조건의 효과를 설명하지 않습니다.**

## S13 제품 품질과 센서 품질을 구분한다

| 자료 | 판단 대상 |
|---|---|
| observation.quality_flag | 센서 관측의 품질 |
| profile.cooler_pct | 설비 냉각기 상태 라벨 |
| 합성 inspection.bore_diameter | 교육용 제품 치수의 규격 이탈 |

제품 규격 이탈은 PRODUCT_QUALITY로 기록합니다. 냉각 조치로 자동 연결하지 않습니다.

## S14 현재 상태와 이전 구간의 문제

전체60초의 품질 요약 ≠ 현재15초의 센서 상태

고착이 끝난 후에는 과거 구간에 STUCK이 남아도 현재 센서는 VALID일 수 있습니다.

과제의 전체 구간 분류와 플랫폼의 현재 상태 판정은 보는 범위가 다릅니다.

## S15 화면에서 같은 사건의 근거를 읽는다

event_id · asset_id · event_type · status

탐지 구간 · 규칙 버전 · 임계값 · 유효 표본 수

| 실제 합성 관제 입력 | 확인된 결과 | 판단의 범위 |
|---|---|---|
| 단발 급등 | 품질 SPIKE · 사건0 | 해당 규칙의 사건 없음 |
| 센서 결측 | GAP · SENSOR_CHECK | 센서 점검, 설비 조치 없음 |
| 냉각 성능 저하 | 유효 초과10개 · 승인 대기 | 감지·근거 확인, 조치 전 |

현재 실행과 이전 실행을 구분합니다. RUN_ENDED는 실행 종료이며 회복 확인이 아닙니다.

## S16 다시 실행할 수 있는 결과를 남긴다

작업 코드 + 데이터 식별 정보 + 규칙 + 시험 구간 + 사건 이력

**플랫폼 기본값 / 내가 비교한 설정 / 사건이 생성될 때의 규칙**을 구분합니다.

파일 재열기 → 입력·설정 대조 → 같은 조건으로 실행 → 결과 비교

다음 수업의 질문: **이 사건에는 어떤 SOP가 적용되며, 그 근거로 무엇을 제안할 수 있는가?**

기록을 저장한 뒤 다시 열고, 같은 입력·설정으로 비교할 수 있는지 확인합니다.
