- DB/사용자: litellm. Cloud SQL 소켓 연결, 허용 네트워크를 열지 않는다.
- Cloud Run: knu-litellm. IAM 인증 필요, 최소0/최대1 인스턴스, CPU1/메모리2Gi/동시요청20/요청제한600초. 아직 학생 공개 서비스가 아니다.

- 빌드 계정 knu-litellm-build: 빌드 소스 버킷 읽기, knu-ai-gateway 저장소 쓰기, 로그 쓰기.
- Secret Manager: knu-litellm-master-key, salt-key, db-password, database-url. 실제 값은 출력·Git·로컬파일에 저장하지 않았다. 실행 계정은 db-password 원본 대신 database-url만 읽는다.
- Artifact Registry: knu-ai-gateway. LiteLLM v1.90.2의 amd64 이미지 digest를 고정한 빌드.
- 성공한 빌드: 374c2556-6a9e-4c51-8e28-46b335c2b81c. 배포 이미지 sha256:ce03f5f693f47f7ae57dde05734683f9a53768a3abc996559c1a38f6ff255bc5.

첫 빌드는 기본 Compute 계정의 소스 읽기 권한 부족으로 실패했다. 전용 빌드 계정에 필요한 범위만 부여해 다음 빌드가 성공했다. 이 실패를 진행 중 작업으로 재시작하지 않는다.

## 재현과 다음 작업

제작도구/중앙중계의 Dockerfile·config.yaml·cloudbuild.yaml과 비밀값준비.py·DB연결준비.py·배포.ps1·중계접속확인.py를 사용한다. .gcloudignore는 Dockerfile/config.yaml 두 파일만 빌드로 전송한다. 자격 증명과 다른 강의 파일을 업로드하지 않는다.

1. 기본 서버/접속/키 검증은 완료. Cloud Run 주소 https://knu-litellm-h4ifvih7fq-du.a.run.app 는 현재 IAM 인증 필요. 학생 공개 주소로 안내하지 않는다.
2. 최초 마이그레이션 후 DISABLE_SCHEMA_UPDATE=true를 적용했다. 배포.ps1 기본값도 비활성화이며 최초 빈DB에만 -InitializeSchema를 사용한다. 추후 버전 업그레이드의 별도 마이그레이션 절차는 남아 있다.
3. 제한된 시험용 가상키의 생성/조회/권한 차이/폐기와 새 revision 보존은 완료. 모델 호출 한도·사용량 집계와 학생 동시성 검증은 별도다.
4. 제공사 키 위치 응답에 따라 Secret Manager 연결. Luna는 coding 별칭으로 연결 예정이며 다른 모델로 임의 대체하지 않는다.
5. 학생 배포용 주소·코딩 에이전트 설정·실제 UI 캡처·기록 방법 준비. 60명 키 배포/동시성·실습 완주·비용 실측은 완료로 표시하지 않는다.
