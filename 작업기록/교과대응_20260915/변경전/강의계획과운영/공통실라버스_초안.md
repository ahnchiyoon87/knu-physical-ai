# 공통 실라버스 — 관찰에서 자기 응용까지

## 목적과 수업 방식

코딩 경험이 없는 학생이 하나의 설비 이상 대응을 따라 데이터·관계·문서·도구·사람의 역할을 이해하고, 코딩 에이전트에게 기능 구현을 맡겨 자기 문제에 적용한다. 기본 시나리오는 HydOps 냉각 이상 대응이다. 실제 UCI 관측과 합성 시뮬레이터의 역할을 구별한다.

학생이 직접 문법·설치 명령·JSON을 작성해야 하는 과제로 구성하지 않는다. 그렇다고 에이전트의 완료 보고만 보고 끝내지 않는다. 모든 실습은 ‘오늘의 질문 → 요구와 확인 기준 → AI 작업 → 실제 결과 관찰 → 한 조건 변경’으로 진행한다. 명세 초안도 에이전트가 작성할 수 있고 학생이 뜻을 확인한다.

## 공통 9단계

| 단계 | 학생의 질문 | AI와 할 작업 | 눈으로 판단할 결과 | 다음 단계 연결 |
|---|---|---|---|---|
| 1. 관측 읽기 | 이 숫자는 무엇을 언제 몇 번 잰 것인가? | 작은 UCI 표본을 읽고 1초 요약 기능 만들기 | 평균·범위·개수·단위와 원본 일치 | 비교 가능한 관측 |
| 2. 품질과 변화 | 설비가 변했나, 센서가 잘못됐나? | 결측·고착을 표시하고 원본/처리 화면 비교 | 이상 값을 감추지 않고 표시, 무조건 정상으로 바꾸지 않음 | 믿을 수 있는 구간 |
| 3. 데이터와 대상 연결 | 이 관측과 절차는 누구의 것인가? | Fabric 원천 등록, Studio 관계·바인딩·발행 | HYD-01과 HYD-02의 원천·적용 절차 차이 | 대상 맥락 |
| 4. 이상 사건 | 언제 점검을 시작해야 하나? | 지속 조건과 경보 기준을 명세로 정해 수정 | 튀는 값과 지속 변화, 중복 사건 비교 | 처리할 사건 |
| 5. 근거 검색 | 어떤 절차를 근거로 말하는가? | SOP 검색과 근거 표시 개선 | 해당 설비·현행 절차·절 번호, 근거 없음 | 근거 있는 제안 |
| 6. 업무 에이전트 | 어떤 일을 도구에 맡길까? | Skill과 MCP를 연결하고 조회/제안 확인 | 실제 도구 입력·출력과 인용 | 자동화할 반복 업무 |
| 7. 사람과 프로세스 | 누가 승인하고 무엇을 실행하나? | Watch·승인·도구 실행 연결 | 거부 시 실행 없음, 승인한 값과 실제 명령 일치 | 실행 기록 |
| 8. 조치 후 확인 | 끝났다는 말과 회복은 같은가? | 시뮬레이터 조치 시점·새 관측·판정 표시 | 회복·미개선·자료 부족의 차이 | 검증 가능한 운영 앱 |
| 9. 개인 응용 | 같은 기술로 다른 무엇을 만들까? | 개인 명세로 데이터/판정/업무/화면 중 필요한 부분 확장 | 원본→판단→업무의 새 연결이 설명·확인됨 | 스스로 활용하는 경험 |

실전 9일·통합 10일의 날짜와 각 4시간은 원본 일정대로다. 통합 추가 하루는 같은 핵심의 복구·응용·개선에 사용한다. 단계 3 이후에는 개인 PBL 주제를 선택할 수 있도록 매번 작은 변형을 남긴다. 마지막 날 처음 자유과제를 던지지 않는다.

온라인 이론은 실전 8편/32시간, 통합 11편/44시간이며 같은 핵심을 설명·예시·복습 분량으로 조정한다. 아래 단계 수를 영상 수로 오해하지 않는다. 영상별 세부 편성과 상세 덱은 다음 제작 대상이며 아직 완료되지 않았다.

## 고급 기법 배치 원칙

기존 리뉴얼의 모든 기법을 필수로도, 모두 제외로도 정하지 않는다. 먼저 기본 방식으로 해결되는지 본다. 검색 후보는 맞는데 순서가 나쁠 때 리랭커, 질문과 문서 표현 차이가 문제일 때 질의 개선/HyDE를 비교 후보로 검토한다. 효과가 나온다고 전제하지 않는다. 크로스 인코더는 리랭커 구현 선택지로 다루며 별도 필수 제작 과제로 늘리지 않는다.

선택 확장은 제공 설정과 짧은 명세로 AI가 연결하도록 한다. 학생은 같은 질문/문서의 전후 결과·호출량·지연을 비교한다. 학습 효과가 없는 설치 절차는 교육 난이도로 계산하지 않는다. 아직 기법별 효과 검증·최종 포함 목록은 미완료다.

## 개인 응용의 범위

처음에는 제공된 냉각 사례에서 대상·표시·확인 기준 하나를 바꾼다. 다음에는 학생이 적용 절차나 처리 조건을 정한다. 후반에는 실제 제조 데이터 또는 출처가 분명한 자기 자료를 연결한다. 새로운 프레임워크를 추가해야 통과하는 과제로 만들지 않는다.

완료 판단은 코드 동일성이 아니라 ‘누구의 어떤 문제인가, 어떤 입력과 근거를 썼는가, 원하는 조건으로 동작하는가, 알 수 없는 것을 구분했는가’다. 추가 감시·의무 회고 양식은 만들지 않는다.
