# 실제 관제 실행과 캡처 검토

원본 플랫폼을 읽기 전용 /app 마운트한 별도 knu-s04-dashboard-review 컨테이너, 호스트127.0.0.1:8804에서 실행했다. PostgreSQL은 새 hydops_s04_review DB다. 기존 hydops DB 사건을 종료하지 않기 위한 검증 환경이며 학생 운영 스택 변경이 아니다. Neo4j는 기존 수업 서버의 설비/SOP를 읽고 새 사건 참조를 추가한다. 완전히 독립된 그래프 DB라는 주장은 하지 않는다.

HYDOPS_AGENT_MODE=offline, ORCHESTRATION=local, SPEED=10. UI 시나리오 버튼과 API 제어를 사용했으며 브라우저 화면·응답을 대체하지 않았다. 승인·조치 없음. 각 경우를 새 run으로 구분했고 reset 시 검증 DB의 이전 열린 사건은 RUN_ENDED로 종료될 수 있다. 각 사건의 캡처 당시 기록은 결과JSON에 보존한다.

- 단발 급등: RUN-6f7937c387, 사건0. 실제 전체 화면에서 SPIKE2 표시와 사건 없음 확인. 단발 주입 횟수와 품질 플래그 관측 수는 같은 단위가 아니다.
- 센서 결측: RUN-0f75f913ce, 사건1, SENSOR_CHECK. API에서 GAP 근거·승인/조치0을 확인.
- 냉각 저하: RUN-c7dbd6d944, 사건1, PENDING_APPROVAL. API에서 valid_samples10·승인/조치0을 확인.
- 기존 수업 서버의 EVT-20270126-090043-HYD-01-e51b 상세 응답은 전후 동일. 페이지 JS오류0.

**화면 검토 실패:** 상세 PNG2장을 열어보니 실제 사건 상세 대신 빈 안내 영역/테두리가 캡처됐다. 화면에 항상 있는 빈 `.detail`과 비동기로 나타나는 사건 상세를 구분하지 못한 캡처 코드 문제다. API 검증 성공을 화면 성공으로 간주하지 않는다. 스크립트를 h2가 포함된 section.detail와 해당 event_id를 기다리도록 수정했지만 수정 후 재실행은 아직 하지 않았다. 학생 가이드에 이 상세 PNG를 넣지 않는다. 전체 PNG 중 급등만 시각 검토했다.

다음: 새 출력 폴더에서 수정 스크립트 재실행 → 모든 사용 후보 PNG 시각 검토 → 실제 확인한 화면만 가이드 반영. 현재 검증용 시뮬레이터는 paused=true로 보존돼 있다. 학생 완주·전체 중복 억제 조건·DB 복원 검증은 아니다.
