# 관제 화면 재검토

수정한 넷째날_관제캡처.py를 새 폴더에서 실행해 종료0을 확인했다. 세 경우 모두 API와 실제 브라우저를 사용했다. 상세 영역은 제목과 해당 event_id가 나타난 뒤 캡처했다. v2의 빈 영역 캡처는 보존하고 학생 자료에는 사용하지 않는다.

검토한 화면: 단발급등_전체.png, 센서결측_상세.png, 냉각저하_상세.png. 화면 내용을 직접 열어 읽었다. 급등은 SPIKE2와 사건0, 결측은 GAP/SENSOR_CHECK/실행기록없음, 냉각은 threshold60/valid_samples10/승인대기/실행기록없음을 확인했다. 승인 입력칸의 기본 이름·값은 실제 승인 기록이 아니다. 도구 요약 문자열은 원본 UI에서 생략 표시되므로 전체 응답이라고 주장하지 않는다. 센서/냉각 전체 PNG는 내부 보존용이며 학생 사용 후보가 아니다.

새 run: 급등 RUN-d95895c21c, 결측 RUN-b9bba1a1b7, 냉각 RUN-ce2fc56a75. 기존 수업 사건 상세 전후 동일, JS오류0, 승인/조치0. 별도 PostgreSQL hydops_s04_review의 기록이며 공유 Neo4j에 새 사건 참조가 추가된다. 마지막 run은 승인 대기·시뮬레이터 일시정지로 보존했다. 단일 냉각 실행에서 사건1개였다는 관찰이 모든 중복 억제 조건을 증명하지는 않는다.

설명 범위 확인: hydops/golden.py의 q2는 냉각 이상 SOP를 고정 조회한다. 센서 점검 사건에서도 하단 Q2에 냉각 SOP가 나오는 것을 확인했다. 실제 센서 사건의 검색·인용은 SOP-SEN-001이다. 가이드에는 두 영역의 역할을 짧게 구분했으며 원본 함수/질문/시나리오는 변경하지 않았다.

학생 가이드에 검토한3장만 복사·연결했다. 이론 S15에는 세 상황 비교, S16에는 실제 비교값과 저장 설정의 출처 구분을 보강했다. 참고 흐름 안의 설명 보강이며 의견 대기 중인 리뉴얼 M01은 적용하지 않았다.
