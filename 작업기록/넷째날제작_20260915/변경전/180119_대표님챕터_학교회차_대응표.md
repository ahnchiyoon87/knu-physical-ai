- 회차별 구현 근거: 대표님 `textbooks/실전반/P01~P09`, `textbooks/통합반/I01~I10`의 회차표·학습목표·활동 제목. 아래 제목은 DOCX 전체 일정표의 원문이며 P/I는 해당 교재 식별자다.

- 작업본은 Git 없음. 이론자료·학생배포본에는 안내 README만 있으며 새 덱·온라인 대본·배포 ZIP은 없다. 현재 1일차 자료는 별도 27구간 표본 초안이다.

DOCX는 후반을 ‘실제 플랫폼’으로 부르지만 README와 후반 교재는 **교육용 Lab Platform**임을 명시한다. 새 설명에는 Data Fabric·Ontology Studio·Agents·Process·Apps의 교육용 구현이라고 쓴다. 실제 제품 설치·연동 완료로 표현하지 않는다.

## 6. 적용 전에 의견을 받을 구체안

### A. 회차 순서 유지와 첫날 범위

**원래 구성:** 위 19개 회차. **문제:** 기존 초안의 플랫폼 조기 도입과 작은 표본만으로는 원문 결과에 도달하지 못한다.

**제안:** 원문 P/I 순서를 유지한다. 첫날 학생 자료는 공통 관측 이해를 공유하되 실전은 DB까지, 통합은 원문대로 재생·저장본까지 진행한다. 두 반 모두 2회 종료 시 품질+DB에 도달한다. 기존 27구간 표본은 혼합하지 않고 보존한다. 향후 짧은 수치 대조 예제로 넣을 필요가 생기면 별도 제안한다.

**영향:** 첫날 가이드의 반별 마무리와 출발본을 나눠야 한다. ‘두 반 핵심 동일’은 회차마다 완전히 같은 종료 상태라는 뜻으로 확대하지 않는다. 다른 선택으로 첫날 모두 DB까지 맞추면 I01 범위 확장과 I02 시간 재배치가 필요하다. 현재는 어느 쪽도 새 가이드에 적용하지 않았다.

### B. 개인 PBL 시간 확보

**원래 구성:** 매 회차 50분 활동 4개+휴식30분+회고10분, 마지막 공통 앱·폐루프 시연. 개인 PBL 독립 시간은 없다.

**문제:** 끝날에만 자유과제를 주면 새 기능을 스스로 정의하고 고칠 시간이 없다. 공통 시연만으로 개인 활용 역량을 확인할 수도 없다.

**제안:** 새 블록 도입 순서는 유지한다. 3회부터 매일 마지막 활동을 ‘공통 연결·검증 30분 + 자기 요구 적용 20분’으로 나누고, 원문의 회고10분은 작업 저장·질문으로 사용한다. 마지막 회차는 공통 기능 연결·복구 60분, 개인 제작·수정 100분, 자기 결과 확인·설명 40분, 휴식30분, 저장·질문10분으로 편성한다. 과제는 이미 제공된 스택에서 학생이 선택한 대상·판정·근거·표시 등 필요한 부분을 바꾸는 것으로 하고, 새 스택이나 실제 제조 데이터 연결을 필수로 만들지 않는다.

**영향:** 실전은 3~8회에 120분+마지막 개인 제작/확인140분, 통합은 3~9회에 140분+마지막140분을 명시적으로 확보한다(계획값). 원문 마지막 활동의 공통 연습은 하루20분 줄고 마지막 앱/통합 기능은 제공 템플릿으로 60분 안에 합류해야 한다. 이는 완주 전에는 성립을 보장할 수 없다. 공통 핵심을 생략해 시간을 맞추지 않는다. 사용자 리허설에서 부족하면 선택 확장 배치와 안내량을 재협의한다.

**남는 개인 결과:** 본인이 정한 짧은 요구, 그 요구로 바뀐 작동 상태, 기대와 실제를 대조할 화면/기록. 별도 반성문·감시용 제출을 추가하지 않는다. 문서 작성은 에이전트가 도와도 학생이 그 뜻과 결과를 판단한다.

### C. 온라인 배정과 선택 기법

4절의 온라인 배정은 원문 핵심을 선행 이론으로 나눈 제안이다. 실전V8에 폐루프·앱·개인 응용이 모여 있으므로 상세 집필 때 각 범위가 4h 안에 설명되는지 점검해야 한다. 통합은 11편으로 같은 내용을 더 나눈다.

Chronos·Watch·합성 제품 검사·What-if의 세부 포함, 기존 리뉴얼 기법 혼합은 아직 결정하지 않는다. 이번에 제안하는 것은 4절의 핵심 배정까지다. 고급 기법을 넣을 때는 해결할 실패·비교 결과·추가 호출량과 어떤 활동 시간을 쓸지를 제시한다.

## 7. 제작 착수점과 남은 검증

의견 반영 후 먼저 P01/I01에 맞는 가이드·시작 상태·확인 기준과 온라인 V1 상세 덱/대본을 만든다. 전체 최종 코드가 모든 학생 출발본에 섞이지 않게 회차 종료 상태를 정의한다. P04→P05, I01→I02의 장기 공백에는 개인 작업 보존·복구를 포함한다.

현재 확인됨: 원문 회차 19개와 학교 실습 슬롯 일치, 학교 원본 해시 일치, 오프라인/온라인 38개 날짜·시수 항목 일치. 미검증: 상세 4시간 학습량, 학생 완주, LiteLLM 경유 코딩/업무/임베딩 호환, 비용, 실제 UI·설치 안내. Docker CLI는 있으나 이번에도 Linux 엔진 연결 실패. 유료 호출·컨테이너 기동·학생 완주는 실행하지 않았다.
