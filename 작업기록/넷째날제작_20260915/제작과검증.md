# 4일차 현재 제작·검증

원문 S04 양쪽 시작본/완성본을 보존 복사하고 한글 플랫폼 경로 conftest를 연결했다. 내용 수정 없음. 도입.json에 원본 해시를 저장했다.

- 실전 완성본9passed/통합16passed, skip 없음.
- 제공 테스트의 범위는 실제 UCI와 메모리 합성 스트림의 감지·분류·중복 억제 및 화면 표시 매핑이다. 실제 DB 사건 저장·관제UI를 증명하지 않는다.
- 탐지비교.json: 고정180시험에서 지속1/5/10/20초의 FP는 모두1, 평균지연0/4/9/19초. 경계 합성 스트림 지속1초는 신호65·사건1·억제64. 지속5/10/20초는 신호0.
- 최초 한계 비교는 k_sigma4 고정: 최소차이1→3일 때 FP3→1. 원문 설명 FP4→1과 차이를 발견해 문맥을 재확인했다. 원문 느슨한 쪽은 k_sigma2이다.
- 교차비교.json: k_sigma2 고정이면 최소차이1→3에서 FP4→1, k_sigma4 고정이면3→1. 원문 주장의 방향은 반증되지 않았으나 비교 조건을 명시해야 한다. 오류라고 단정하거나 원문 기준을 변경하지 않았다.
- 가이드 본문과 부분 이론 모듈은 작성했다. 학생 출발/관제 연결·캡처·전체 체크포인트 재개 동선·선택 제로샷 환경은 미완료다. 제공 테스트25개 통과로 4일차 완료를 주장하지 않는다.


가이드 본문 작성: 원문 P04 활동3/4, I04 활동3/4와 시간 순서 확인. 두 반의 순서가 달라 안내표와 적용 위치를 명시했다. 실제 UI/DB 연결·전체 체크포인트 재개 확인은 남았다. 덱·대본16절은 부분 모듈이며 회차 전체240분·렌더 검증은 아니다. 통합의 최근15초/전체60초 분류 차이는 원문에 설명된 의도된 단순화로 확인했고 알고리즘을 통일하지 않았다.


체크포인트_저장.py 실제 검사: 체크포인트검사/checkpoint.json과 detector_lab.py 사본. 기준244/시험180, 시험ID해시2bb1593b85bc83a9…, 지정LAB-S03 실행 사건1/이력3. 같은 파일 해시 확인. 덮어쓰기/없는run반증 통과. DB자동복원은 구현하지 않았고 전체1~4일차 사용자작업·화면 복원 증거가 아니다.

## 체크포인트 보강

기존 자체 도구는 파일명만 보존해 여러 회차의 동일 파일명을 함께 저장하지 못했고, TH/QR 저장만으로 개인 비교 설정을 보존하지 못했다. 참고 원문 알고리즘·순서·스택 변경 없이 자체 도구를 보완했다.

- `--root` 아래 회차 경로 유지. 1~4일차 제공 완성본25개를 같은 이름 포함 저장했다. 학생 개인 작업25개를 검증한 것이 아니다.
- 명시한 `--compare` 네 설정으로 제공 평가기를 실제 재실행해 각180사이클 전체 결과와 설정을 함께 기록했다. 기본/느슨함/지속1/지속20의 FP는1/4/1/1, 평균 지연9/0/0/19초로 이전 근거와 일치했다.
- 기본 TH/QR, 지금 실행한 위상 비교, 기존 run 사건의 설정을 동일하다고 간주하지 않도록 출처·범위를 분리했다. 학생 수정 코드의 결과·선택 이유는 개인 노트북에 기록해 함께 저장하도록 안내했다.
- `--verify`는 DB 연결 없이 저장 코드 해시·구간·사건 연결만 확인한다. 실제 DB 복원과 재개 실행을 대체하지 않는다.
- 기존폴더/중복명/루트밖/분수 지속시간/없는run/코드변조/시험ID변조/평가ID변조/다른run사건/상위경로의10개 반증 검사가 모두 거부를 확인했다.
- 지정 기존 run·사건·이력의 전후 내용 해시가 동일했다. 실제 호출은 읽기 전용이며 승인·조치·유료 모델 호출 없음.

근거: `체크포인트검사_v2/검증결과.json` 및 `저장본/checkpoint.json`. 다음은 실제 관제 사건 화면과 저장 파일을 보고 재개하는 학생 동선이다. 이 보강은 첫 컨펌 대기 중 가능한 독립 검증이며 후속 영상 확정이나 기존 리뉴얼 자료 혼합이 아니다.
