# 둘째 날 제작과 검증

## 변경의 이유와 경계

기본 틀은 P02/I02. I02에 남은 FS1 기준6은 P01/P02의 초기값 수정 설명과 공통15 기준에 맞지 않는다. 통합에만6을 유지할 근거를 찾지 못하면 통일하라는 사용자 승인으로 새 과제만15로 맞췄다. 원본 저장소는 변경하지 않았다. 파일별 원본/수정본 해시는 도입과변경.json에 기록했다. 의심과 반증은 ../의심과검증.md의 Q04 참조.

## 실행

- 통합 완성본: 실제 PostgreSQL을 사용하는 원문5검사와 FS1 회귀검사, 6passed.
- 실전 완성본: 원문8검사, 8passed. 결측 집계·급등과 수준 변화·냉각 심각 저하·고온 고착·실제 DB 저장 포함.
- FS1 과거값 반증: 별도 복사본만6으로 바꿔 실행, 추가 검사에서1failed/5passed. 원문5개만으로는 이 불일치를 잡지 못함을 확인.
- 관찰 자료: 둘째날_관찰자료.py가 완성 코드를 사용해180관측 적재, TS1 60행 재조회 후 실제값으로 CSV·그래프 저장. TS1 OK49/SPIKE1/MISSING4/GAP3/STUCK3, PS1/FS1 각각OK60. 임시 LAB-S02 run만 정리했다.
- 그림 직접 검토: 한글·축·범례와 표시 확인. 19초 급등,26~32초 결측,50~52초 STUCK가 데이터와 대응. 학생 가이드 그림은 실제 DB 재조회 결과의 그래프이며 브라우저 캡처가 아님.

## 학생 관점의 판단

검사 기준과 정답부터 읽으면 학생이 에이전트의 성공 보고만 확인할 위험이 있다. 원문 활동 순서를 유지하면서 먼저 원본/오류 주입본의 모양을 비교하고, 자신의 요구를 확인한 뒤 표시 이유를 읽게 했다. 코드 직접 수정 요구를 에이전트 요청으로 바꾸되 원시 값 보존·검사 범위·구간 판단은 학생이 직접 확인한다. 그래프의 빈틈과 표시 시작 시점을 읽게 해 숫자 암기만으로 끝나지 않도록 했다. 이는 교육적 판단이며 학생 완주로 효과를 검증한 것은 아니다.

## 실제 UI 보강

완성 코드의 출력5장을 실제 JupyterLab에서 캡처했다. 원본/주입 비교, raw/value/품질표, 구간 판단, 결측 집계, 냉각 변화/센서 고착 비교다. 6개 코드 셀 실행·오류0, 두 반의 전체180관측 품질 결과가 동일하다. 새 run LAB-S02-6aee5060에180행 적재·TS1 60행 재조회, raw결측7/value보류11 확인. 기존 run 삭제 없이 새 실습 run을 보존했다.

구간 표의 긴 플래그 문자열이 말줄임표로 생략되는 것을 발견해, 같은 DB run을 재조회하며 플래그별 열로 펼쳤다. 수정 화면을 직접 확인했고 나머지 화면도 내용·단위·범위를 확인했다. 원본·과제 순서·기준은 바꾸지 않았다. 가이드 그림은 총6개(기존 그래프1개+실제 UI5개)다. 캡처용 노트북은 결과를 보는 도구이며 학생 과제를 노트북으로 변경한 것이 아니다.

실전 시뮬레이터 비교는 원문 테스트의 시드7·냉각 효율0.25를 사용했다. 냉각 저하는 EQUIPMENT_ANOMALY, 고착 추가는 SENSOR_FAULT, 두 사례 SPIKE0이다. 실제 공장 설비 진단 결과가 아니다. 과제·복사본 소스3파일 해시가 일치한다.

증거: 실제화면_검증.json 및 ../첫날제작_20260915/노트북실제화면_v1/둘째날품질조회. 기존 Jupyter 서버 마운트 아래에서 실행했으며 둘째 날 기록에서 연결한다.
