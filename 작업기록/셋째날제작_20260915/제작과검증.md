## 실제 Neo4j Browser 화면

현재 로컬 Browser57474, DB접속57687에서 실제 읽기 질의3개를 실행했다. 유효 SOP→설비→센서 경로27개에서 고유 노드14개·관계15개, 모든 설비에 냉각 이상 SOP를 선택적으로 연결한 표8행, HYD-01 센서 식별자/코드/라벨 표3행을 확인했다. 전3장 확대 화면을 직접 검토하고 학생 가이드에 반영했다. 노드의 긴 이름은 Browser가 요약 표시하므로 정확한 ID는 별도 표에서 확인하게 했다.

최초 연결 직후 DB 선택·목록 로딩 전에 실행하면 No active database가 발생했다. 연결 문구만 기다리는 자동화를 DB준비 확인으로 고쳤다. 실패 화면은 내부에 보존하고 학생에게 정상 결과로 제공하지 않았다. 기존 데이터 초기화·시드 반복·승인·조치는 실행하지 않았다. 캡처 스크립트는 연결·읽기 질의·화면 확대만 수행한다.

READ_ACCESS 의심 Q07도 현재 환경에서 실제 거부(Neo.ClientError.Statement.AccessMode)와 전후 그래프 통계 동일을 확인했다. 공식 문서의 ‘권한 보장으로 사용하지 말 것’과 구분해 기록했다. 과제 동작은 변경하지 않았다.

근거: Browser실제화면/현재/조회기록.json 및 PNG3개, READ_ACCESS_현재환경확인.json. 이전 기능 검사와 새로운 Browser 화면을 학생 전체 완주로 합쳐 주장하지 않는다.

## 사건 인용·ID 되돌리기·최근 관측 결합

추가 검토 노트북의 코드5셀 실행·오류0. 기존 사건 EVT-20270126-090043-HYD-01-e51b의 승인 대기 상태와3개 인용을 조회했다. 그래프의 문서 판·절·제목은 제공 SOP 파일과 대조했고 가이드에서 두 문서로 직접 연결했다. 인용이 있다는 것과 승인·재점검을 수행했다는 것은 구분한다.

같은 ID4개는 생성0·반영True, 틀린 센서ID는 생성될노드1/관계1·반영False·잔존0이었다. 제공 함수가 기존 속성값까지 비교하지 않으므로 실행 전 현재 센서 속성이 제공 값과 같은지 확인해 WIP 덮어쓰기를 방지했다. 해당 한계는 Q09와 학생 가이드에 반영했다. 함수 자체는 변경하지 않았다.

새 LAB-S03-392af1be의 사이클100을 두 반 함수로 조회해 센서3개·각60관측·단위 일치 확인. DB 센서 조건에 전체ID를 사용하면0행, 코드TS1이면60행이다. 결과 JSON을 저장·재열기 확인한 후 제공 cleanup으로 이 임시 run과 관측만 정리해 각각0을 확인했다. 기존 사건·인용은 동일하며 그래프 노드/관계 내용 해시도 전후 동일하다.
