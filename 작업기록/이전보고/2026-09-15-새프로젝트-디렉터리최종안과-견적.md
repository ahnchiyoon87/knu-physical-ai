# 새 강의 프로젝트 디렉터리 최종안과 이관 견적

상태: 설계안 작성 완료, 미적용. 이번 요청은 견적·설계까지이며 새 폴더 생성이나 자료 이동은 하지 않았다.

## 결정 방향

새 제작 프로젝트는 `D:/work/study/knu-physical-ai`에 둔다. 기존 리뉴얼과 대표님 저장소는 입력 자료로 보존하고, 실제 수정은 새 프로젝트 한 곳에서 한다. 앞서 두 폴더만 유지하기로 했던 방향은 이번 새 프로젝트 설계 요청으로 변경됐다.

한글 자체가 문제는 아니다. 현재 `00_문서/10_실습/20_도구/30_기록`의 숫자는 정렬용이며 수업 순서가 아니다. 새 구조는 **역할이 드러나는 짧은 영문 폴더명, 한국어 문서 제목·설명**을 사용한다. 숫자는 회차를 나타내는 곳에만 쓴다.

## 최종 구조

```text
knu-physical-ai/
├─ README.md                    # 무엇을 어디서 찾는지 안내
├─ AGENTS.md                    # AI 작업 규칙
├─ .gitignore
├─ docs/                        # 강의 설계와 운영 문서
│  ├─ syllabus.md               # 챕터·학습목표·학생 산출물
│  ├─ schedule.md               # 학교 날짜·시수·반별 회차 대응
│  ├─ requirements.md           # 확정 요구와 변경 원칙
│  ├─ handoff.md                # 다음 세션 재개 입구
│  ├─ operations/              # 로컬 설치, LiteLLM, 모델·비용 계획
│  └─ sources/                 # 받은 ZIP·엑셀·HTML 등 원자료
├─ theory/                      # 온라인 이론
│  └─ session-01/
│     ├─ deck.md                # 슬라이드별 상세 설계
│     └─ narration.md           # 해당 슬라이드의 온라인 대본
├─ labs/                        # 오프라인 실습
│  └─ day-01/
│     ├─ guide.md               # 학생 행동·이유·관찰·판단·복구
│     ├─ start/                 # 해당 일차에 바로 합류할 출발본
│     └─ solution/              # 해당 일차 완성본·강사용 비교 기준
├─ system/                      # 교육용 플랫폼 실행 코드
│  ├─ README.md                # 실행 방법
│  └─ ...                      # 도입한 플랫폼 내부 구조 유지
├─ materials/                   # 교재 공용 그림·캡처·배포용 데이터
│  ├─ images/
│  └─ datasets/
├─ tools/                       # 준비·검사·배포 자동화
├─ dist/                        # 생성한 학생 배포 ZIP·출력물
└─ .work/                       # 내부 작업·검증 기록, 학생 배포 제외
```

이 트리는 자료의 최종 배치 기준이다. 아직 없는 회차 자료와 빈 폴더를 대량 생성하지 않는다. 영상 폴더는 실제 제작이 필요할 때 추가한다.

## 유지보수 규칙

- 대표님 `system/labs/materials/tools`의 역할 구분을 가져온다. 우리 산출물은 온라인 덱·대본과 오프라인 실습이 분명하므로 `textbooks` 한 곳에 모으기보다 `theory/labs`로 나눈다.
- `session-01`과 `day-01`은 각각 온라인·오프라인 회차다. 두 반의 편성 차이는 `docs/schedule.md`에서 공통 자료와 연결한다. 반별로 동일 내용을 복제하지 않는다.
- `start`는 당일 실습을 시작할 수 있는 상태다. 앞 일차 결과가 필요하면 그 상태를 포함해 결석자도 합류하게 한다. 학생에게는 당일 필요한 자료만 배포하며 `solution`을 자동 포함하지 않는다.
- 플랫폼 정본은 `system` 한 곳이다. 일차별 출발본·완성본은 고정된 플랫폼 버전과 실습 변경분으로 생성한다. 수작업으로 전체 플랫폼을 회차마다 복제·유지하지 않는다. 오프라인 배포에 필요한 코드는 ZIP 생성 시 포함한다.
- `materials`에는 교재와 여러 실습이 공유하는 자산을 둔다. 플랫폼 내부 DB·캐시·실행 데이터의 경로는 그대로 유지한다. 실습 전용 작은 데이터는 해당 실습 폴더에 둘 수 있다.
- `dist`는 재생성 가능한 배포 결과이며 원본 편집 위치가 아니다. `.env`, 키, 개인 데이터, 가상환경·설치 패키지·로컬 DB는 Git/학생 ZIP에서 제외한다. 필요한 `.env.example`은 빈 값 또는 예시만 둔다.
- 파일 경로는 프로젝트 루트 또는 스크립트 위치를 기준으로 계산한다. 개인 PC의 `D:/...` 경로를 실행 코드에 박아 넣지 않는다.

## 이관 범위와 예상 작업량

| 작업 | 실제 할 일 | 예상 |
|---|---|---|
| 자산 선별 | 현재 작업본·학교 원자료·운영안·확정 지시의 목록과 원본 해시 확보 | 30~45분 |
| 구조 적용 | 새 루트 구성, 필요한 자료 이관, 미확정 초안 표시, 기존 원본 보존 | 30~60분 |
| 경로 정리 | 도구·문서 링크·설치 안내·자료 참조를 새 위치로 수정 | 45~90분 |
| 검증·인계 | 해시·누락·링크·경로 검사, 가벼운 준비 검사, 작업 정본 안내 | 30~60분 |

**합계 약 2시간 15분~4시간 15분, 여유를 포함해 반나절 규모의 이관 작업으로 예상한다.** 에이전트 작업 시간을 실측한 값이나 납기 보장은 아니다. 금액 견적은 작업 단가가 없어 산정하지 않았다.

이번 견적에는 전체 강의 재집필, 플랫폼 UI 개편, 일차별 배포 생성기 신규 구현, 클라우드 배포·유료 모델 호출·학생 실습 완주를 포함하지 않는다. 위 버전 기반 배포 방식은 최종 운영 설계이며, 관련 생성기가 없다면 구현 견적을 별도로 잡는다. 새 프로젝트의 Git 초기화·원격 연결도 기존 저장소와 연결 방식을 정한 뒤 별도로 처리한다.

## 확인 근거와 완료 기준

현재 작업본은 `00_문서/10_실습/20_도구/30_기록` 구조이며, 대표님 저장소에는 `system/labs/textbooks/materials/tools/video`가 있다. 현재 작업본의 Python·YAML·Markdown 검색에서 기존 디렉터리 이름을 참조하는 줄 23개를 확인했다. 이는 일차 점검이며 이관 때 전체 파일과 동적 경로를 다시 확인한다.

완료는 새 정본의 필요한 파일 누락 없음, 도구의 옛 절대경로 의존 제거, 주요 문서 링크 확인, 학생 배포와 내부 자료 구분, 다음 세션 재개 위치 확정으로 판단한다. 폴더 생성만으로 강의 개편 완료를 선언하지 않는다.
