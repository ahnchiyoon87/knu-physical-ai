# 영상05 제작 상태

## 제작 범위

`이론자료/1회차/영상05/원본을1초구간으로_덱.md`·`원본을1초구간으로_온라인대본.md`·`원본을1초구간으로_화면초안.html`을12장면으로 제작했다. 대본 본문은 제목·공백 제외5,546자다. 실제20분·PPTX·사용자 녹화는 미완료다.

영상04의 공통 시간 구간에서 출발해, 원본 배열 → 첫/다음 경계 →60×100 묶음 →reshape →원본 행과 구간 행 구분 →모양의 의미 →센서별 같은 규칙 →반복 처리 →묶기/선택/요약 구분 →결과 확인 →영상06 통계로 이어진다. 용어와 코드 앞에 그 동작이 필요한 이유를 설명했다. 별도 퀴즈는 추가하지 않았다.

## 근거와 의미 검토

- 참고 `textbooks/실전반/P01_첫_데이터가_흐르는_시스템.md` 활동2의 시작본·완성본 비교와 현재 첫날 학생 가이드3절을 근거로 한다. 기존 순서·스택·필수 활동·시간 배분을 바꾸지 않았다.
- 시작본의 `reduce_to_seconds`에도 reshape가 이미 있다. 결함은 그다음 단계의 첫 값 선택이다. ‘묶기부터 새로 만들라’고 설명하지 않으며, 시작본과 완성본 모두 결과60개라는 점을 별도로 설명했다.
- 원본 파일의 한 행은 한 사이클, 선택한 사이클의 원본 배열은1차원, reshape한 배열의 한 행은1초 구간이다. S06에서 이 세 단계를 구분했다.
- S05 코드는 제공 함수의 실제 한 줄을 그대로 사용했다. `samples`를 원본으로 읽었으며 CYCLE_S와hz가 준비된 문맥을 설명했다. 독립적인 전체 실행 명령으로 표시하지 않았다.
- `(100,60)`도 총개수6,000은 맞지만 PS1에서는 묶음당0.6초다. 개수/모양/값 순서 검사를 함께 요구한다. 원본 값의 위치 번호를 실제 압력값으로 표시하지 않았다.
- 새로운 리뉴얼 혼합·알고리즘 추가는 없다. 의무 퀴즈나 학생 직접 문법 작성 요구도 추가하지 않았다.

## 실제 실행

`제작도구/영상05_묶음확인.py`를 `knu-hydops-notebook-ui:review`에서 실행했다. 네트워크 없음, 프로젝트 읽기전용, 증거 폴더만 쓰기 허용. 제공 과제 시작본·완성본을 실제 import했다. DB와 유료 API 호출 없음.

| 확인 | 범위와 결과 |
|---|---|
| 덱 코드 실행 | 실제 함수에서 추출한 reshape 한 줄을 실행 |
| 세 센서 사이클100 | 60×1,60×10,60×100 모양·전체 값 순서·60개 경계 일치 |
| 입력 보존 | 처리 전후 원본 배열의 모든 값 동일 |
| 시작본과 완성본 | 모두60개 출력. 시작본n=1, 완성본n=각Hz |
| 잘못된 길이 | 센서별 한 개 부족/초과, 총6개 입력에서 ValueError |
| 잘못된 묶기 | 100×60,첫 값만 선택,열 방향 배치,한 칸 밀기 네 입력 모두 거부 |

위치 번호를 채운 합성 배열은 중복된 실제 센서값 때문에 순서 오류가 가려지는 것을 막는 검사 입력이다. 실제 센서값으로 발표하지 않는다. 근거 `영상05_묶음확인/묶음_대조.json`에는 실제 원본의 선택 구간 값과 코드 해시도 있다. 이 검증은 학생 시작본에서 에이전트 수정까지의 전체 완주가 아니다.
