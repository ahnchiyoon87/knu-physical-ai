# 영상09 제작 상태

## 산출물

품질정보읽기 덱·온라인대본·HTML12장면을 제작했다. 덱/대본의12개 제목 대응을 확인했다. 대본 본문 공백 제외3,019자이며 실제20분·PPTX·녹화·컨펌은 미완료다.

## 원문과 설명 경계

P01은 제공 B2 검사기를 사용해 B3로 넘기는 흐름이다. 현재 mapping.load_cycles와 b2_quality/checks.py의 처리·정렬·상태 보관을 대조했다. 원본 읽기·집계·레코드·재생 시각 설명을 다시 전개하지 않고, 추가된 quality_flag/value와 raw_value의 관계부터 진행했다. 규칙 수정·오류 주입 실습과 심화 판정은 P02에 남긴다. 이론에서 짧은 설명용 입력의 결과를 보여 주는 것과 해당 실습을 앞당기는 것은 구분한다.

S01~02 검사 필요와 필드, S03~05 통과/보류/입력결측 비교, S06 여섯 상태의 의미, S07~08 이력과 순서, S09 보류 관측 보존, S10 실제540개 결과의 설명 범위, S11 요구와 결과 비교, S12 저장·조회로 연결한다. 자동 의무 퀴즈는 넣지 않았다.

## 실제 기능 근거

- 도구: 제작도구/영상09_품질확인.py. 기존 검토 이미지에서 네트워크 없이 실행, 프로젝트 읽기전용/증거 경로만 쓰기. DB적재·모델 추론 없음.
- 실제 세 센서 사이클100·101·102를 read_raw_cycle/map_cycle로 만들고 동일 검사기를 세 사이클에 이어 사용했다.540개 모두OK, 원래 필드 보존, flag/value 관계 확인.
- 별도 설명용 TS1 입력6묶음으로 OK/MISSING/GAP/SPIKE/STUCK/OUT_OF_RANGE 결과 확인. 입력값과 사용값을 각각 대조했다. UCI 원본 결함 사례로 표시하지 않는다.
- v2는 STUCK 입력의 첫 관측도 기록하고 첫53.0은OK, 여덟 번째53.0은STUCK임을 실제 확인했다. 근거 영상09_품질확인_v2/품질대조.json. v1 근거는 보존한다.
- 품질OK는 설비 정상 판정이 아니라는 기존 승인된 설명 범위를 유지했다. 코드의 교육용 범위/변화 기준을 실제 설비의 보증 한계로 표현하지 않는다.

## 화면·내용 검토

HTML전12장면을 렌더하고 모아보기3장을 직접 확인했다. 표·본문·제목의 잘림/겹침은 보이지 않았다. S06은6종 상태 표가 읽히도록 행 간격을 조정했다. 전12본문이MD와일치하고540→541 변조는 불일치로 검출된다. 근거 영상09_화면검토_v1/렌더검사.json 및 모아보기1~3.png. 도형은 설명용이며 실제 UI 캡처라고 하지 않는다.
