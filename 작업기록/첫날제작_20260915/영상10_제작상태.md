# 영상10 제작 상태

## 산출물과 설명

저장과재조회 덱·온라인대본·HTML12장면 제작. 제목12개 대응, 대본 본문 공백 제외3,495자. 실제20분·PPTX·녹화·컨펌은 미완료다.

프로그램 내 결과와 지속 저장 → CSV/DB 용도 → 접속 대상 → 테이블/스키마 → run과observation 연결 → 행id → NULL → 제공 적재 → 제약 위반 → 별도 접속 재조회 → 부분 실패 확인 → 조회 조건으로 연결한다. run_id·품질 플래그·원본 평균은 짧게 상기하며 이전 영상 설명을 다시 전개하지 않았다. 조건별 SELECT와 시간 경계는 영상11에 남긴다.

## 실제 기능 근거

읽은 정본: P01의 B1→B2→B3 목표, 현재 mapping.load_cycles, b3_tsdb/store.py의 create_run/insert_observations/connect, sql/01_schema.sql의run/observation 정의. 원문 또는 공통 플랫폼 코드는 수정하지 않았다.

도구 영상10_저장확인.py는 대상DB 이름을 hydops_v10_review로 제한한다. 기존 로컬 PostgreSQL 안에 없는 이름임을 확인한 뒤 이 전용DB를 생성했다. 기존 hydops 및 Day4 검토DB, 사건·관제 실행은 수정하지 않았다. 새 DB에는 제공 스키마와 LAB-V10-STORAGE 실행540개가 남아 있다.

1. save: 제공 load_cycles로 원본100·101·102를 실제 품질 검사 후 적재. 반환540.
2. read: 앞 컨테이너 종료 뒤 새 컨테이너/프로세스에서 읽기전용 트랜잭션 조회.540개와 실행source/scenario 확인. 원본을 다시 계산한 전체 관측의 모든 기존 필드와DB행 대조, 각id고유 확인.
3. constraints: 등록하지 않은run과두행COPY의두번째unit=None을 전달. 각각 ForeignKeyViolation/NotNullViolation 발생. 기존540개 유지.

근거 영상10_저장확인/저장.json·재조회.json·제약확인.json. 같은 Docker네트워크에서 별도DB로 연결했고 모델·Neo4j 호출 없음. 데이터베이스 서버 자체를 재시작하거나 전체 학생 환경 복구를 검증한 것은 아니다.

한 COPY 전달분의 실패가 반영되지 않음을 확인했으며, load_cycles 전체가 여러 사이클을 하나로 묶어 취소하는 원자적 작업이라고 주장하지 않는다. 코드상 사이클별 함수 호출·연결 범위와 구분했다. 이 사례는 적재 실패를 읽는 설명이며 원문 활동/시나리오를 바꾸지 않았다.

## 렌더·내용 검토

전12HTML본문이MD와일치하며540→541변조는불일치로검출했다. 전장면 모아보기3장을 직접 검토해 제목·표·본문의 잘림/겹침이 보이지 않음을 확인했다. 설명용 저장 구조이며 실제 제품 UI 캡처로 표시하지 않는다. 학생용 자료에서 검토DB/작업로그 서술을 제거하고 실행 결과를 학습 사례로 설명한다.
