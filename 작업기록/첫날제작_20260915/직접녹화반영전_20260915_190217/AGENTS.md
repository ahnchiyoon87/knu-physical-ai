# 플랫폼 기반 개편 작업 지침

상위 STUDY 계약과 최신 사용자 지시를 따른다. 현재 상태는 `강의계획과운영/인계.md`에서 확인한다.

최신 필수: 대표님 자료는 현재 우리 자료보다 흐름이 나은 주된 참고 토대이며 완벽한 정본으로 맹신하지 않는다. 두 자료의 장점을 합치는 것이 방향이다. 기존 리뉴얼 자료·기법을 혼합할 지점에서는 바로 이유·변경 내용·영향을 제시하고 의견을 받은 뒤 적용한다. 오류 의심은 문맥·코드·데이터를 꼼꼼히 검증하고 단정하지 않는다. 이미 합의한 AI 코딩·학생 판단 방식의 제작은 바로 진행하며 대응표 전체 재승인을 관문으로 만들지 않는다. 자체9단계 초안도 확정본이 아니다. 고가 모델 사용은 허용됐으며 비용 실측은 사용자가 수행한다.

- 대표님 플랫폼·냉각 이상 대응 시나리오가 토대다. 비전공자용 학습 흐름은 다시 설계한다.
- 설치·MCP 설정·코드 작성은 코딩 에이전트가 수행한다. 학생은 목적·요구·결과를 이해하고 판단한다.
- 최신 영상 제작 기준: 온라인 회차당 이론 영상 총240분, 한 편 최대20분.20분 단위로 주제를 설계하며 짧은 편이 있으면 편수가 늘 수 있다. 영상+해당PPTX를 컨펌 단위로 하나씩 완성하고 피드백을 반영한 뒤 확장한다. 오프라인 실습가이드는 별도 단위다. 영상 밖 과제 시간을 더해240분 영상 완성으로 계산하지 않는다.
- 처음에는 명세와 요청 예시를 주고 점차 도움을 줄인다. 개인 PBL은 익숙한 스택의 전이·확장으로 만든다.
- 날짜·시수·반 구성은 현재 편성을 기준으로 한다. 2026-09-15 사용자 전달 최종 학교 회신: ‘시간배분은 확정이고 그 시간 내 구성은 자율입니다 + 영상 오프라인 구성도 크게 차이 안난다면조정 가능’. 이론32/44시간·실습36/40시간을 미확정으로 취급하거나 전면 재편성하지 않는다. 영상/오프라인 간 조정이 필요하면 구체 영향과 사용자 의견을 확인한다. 두 반 핵심 내용은 같고 대본은 온라인 이론에만 둔다. 온라인 영상·PPTX와 오프라인 실습가이드는 별도 컨펌 자료이며 영상 한 편과 실습 하루의 일대일 대응을 강제하지 않는다. 외부 제출은 사용자가 수행한다.
- 학생별 로컬 실행 + 중앙 모델 중계가 기본 운영 방향이다. 유료 호출·비용 측정은 사용자가 수행한다.
- 기존 리뉴얼과 대표님 클론은 원본으로 보존한다. 여기의 수정본만 개편한다.
- 고급 기법은 설치 난이도로 일괄 제외하지 않는다. 해결할 문제·쉽게 관찰할 효과·호출 비용을 보고 선별한다.
- 문법 검사·제공자의 캡처를 이번 실제 완주 증거로 표시하지 않는다. 실측하지 않은 시간·비용·최소 사양을 확정하지 않는다.
- `.env`, 인증정보, 로컬 DB, 생성된 개인 결과는 Git과 학생 ZIP에서 제외한다.

## 상시 검토 원칙 — 의심을 보존하고 반증한다

사용자가 가장 중요하게 지정한 원칙이다. 이상해 보이는 내용은 즉시 오류로 단정하거나 수정하지 않는다. 내부 의심 기록에 위치·가설·영향을 남긴 뒤 원문 앞뒤 설명, 코드, 실제 데이터, 변경 이력, 후속 회차를 계속 대조한다. 가설을 지지하는 근거뿐 아니라 반박하는 근거를 적극적으로 찾으며 에이전트 자신의 이전 결론에도 같은 기준을 적용한다.

각 항목을 오해 / 의도된 차이 / 실제 결함 / 근거 부족으로 구분하고 판정 근거와 후속 행동을 남긴다. 미해결 의심을 조용히 버리거나 테스트 통과만으로 해소하지 않는다. 추가 근거가 나오면 판정을 갱신하며, 실제 변경은 기존 협의 원칙과 해당 사용자 승인을 따른다. 의심 기록·내부 판정은 학생 자료에 넣지 않는다.

학생 관점의 교육적 판단도 명시한다. 지금 활동의 이유를 알 수 있는지, 용어·화면·조작 부담이 적절한지, 에이전트 완료 보고를 넘어 실제 결과를 판단하는지, 다음 활동과 개인 응용에 연결되는지 검토한다. 사실과 교육적 의견을 구분하고 개선의 이점·부담·영향을 설명한다. 설명 보강은 승인 범위에서 진행하고 순서·스택·시나리오 변경 및 기존 자료 혼합은 협의한다.
