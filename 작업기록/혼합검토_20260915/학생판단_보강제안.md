# 학생 판단 보강 후보 — 적용 전 검토

상태: 사용자 의견 대기. 학생 가이드·커리큘럼에 아직 적용하지 않았다.

## 비교한 원문과 범위

- 참고 P05 `textbooks/실전반/P05_SOP와_Skill로_로컬_에이전트_구성.md`: 활동 제목, 7절 과제·8절 완료 확인·9절 회고를 확인했다. HYD-01 REDUCE_LOAD, HYD-02 FAN_BOOST, HYD-03 HOLD, 센서 오류 SENSOR_CHECK 및 잘못된 인용 검사가 이미 있다. 개인 실패 분기 설명도 있다. 검증이나 개인 설명 자체가 없다고 판단하지 않는다.
- 참고 P09 `textbooks/실전반/P09_관제_앱_게시와_통합_시연.md`: 도입·학습목표·강사 시간표와 리허설 조건을 확인했다. 앱 바인딩·업무 시작·게시·센서 별칭·같은 사건의 폐루프를 필수로 다룬다.
- 리뉴얼 `10_실습/학생가이드/자료/질문셋_사용법.md`: 기대 문서·허용 상태를 먼저 정하고 동일 질문으로 변경 전후를 비교한다. 기대 근거와 실제 모델 출력을 구분한다.
- 리뉴얼 `10_실습/학생가이드/실전반/09일차_transfer.md`: 새 입력의 기능 전제, 그대로 쓸 가정/고칠 가정, 사용자·상황·입력·행동·결과·제한을 설명하는 활동을 확인했다. 도서관 예제와 새 원천 연결을 통째로 옮기면 현재 제조 앱 필수 활동과 충돌한다.

이번은 두 지점의 제한된 비교다. 리뉴얼 전체·참고 교재 전체를 검토 완료한 기록이 아니다.

## 제안 M01 — 기존 필수 검증을 실행 전후 판단표로 연결

**원래 구성:** 제공 코드 검사, 실제 검색·인용·분기 확인, 개인 설명.

**교육적 판단:** 에이전트가 구현과 테스트를 맡으면 학생이 통과 보고를 읽는 데 그칠 수 있다. 원문의 검증이 부족해서가 아니라 학생 역할이 바뀌었기 때문에, 실행 전 학생의 예상과 실행 후 근거를 연결하는 안내가 유용하다.

**가져올 것:** 리뉴얼의 ‘기대 상태/근거를 먼저 적고 실제 결과와 비교’하는 형식. 원문의 필수 네 경로를 그대로 사용한다. 질문20/30개, RAGAS·평가용 모델·별도 평가 서버는 이 제안에 포함하지 않는다.

**예상 학생 흐름:** 기존 작업 노트북에서 상황 → 기대 상태 → 필요한 근거 → 실제 상태와 인용 → 차이 설명을 적는다. 예를 들어 HYD-03에서 적용 SOP가 없으면 조치를 추천하는 답 대신 HOLD가 나와야 한다고 먼저 설명하고, 검색 결과와 실제 분기를 확인한다. HYD-01/02와 센서 오류 경로도 기존 필수 범위를 유지한다. 기대값을 실제 측정값으로 기록하지 않는다.

**영향:** 5일차 기존 검색·분기 확인의 안내와 기록 형식이 바뀐다. 스택·SOP·설비·순서·필수 검증을 바꾸지 않는다. 별도 제출 파일이나 질문 개수를 추가하지 않는다. 예상 작성·대조에 필요한 학생 시간은 아직 실측하지 않았다. 기존 활동 안에서 가능한지는 사용자 리허설로 확인하며, 부족하다고 원문 필수 검증을 생략하지 않는다. 두 반의 기존 활동 위치를 유지한다.

**협의할 내용:** 이 형식을 새 5일차 가이드에 도입할지. 승인 전 본문 변경 없음.

## 당장 옮기지 않을 것

- 리뉴얼의 도서관 전이 실습 전체: 새 데이터 의미·규정·화면 작업이 추가된다. 참고 P09 앱 게시와 폐루프를 대체하면 필수 목표가 빠진다. 개인 PBL 방향 후보로만 보존하며 구체 시간과 요구를 별도 협의한다.
- 리뉴얼 질문20/30개와 평가 기술 묶음: 참고 P05의 기존 검증으로 우선 확인할 수 있는 부분과 중복된다. 추가 비용·환경·시간을 정하지 않은 채 가져오지 않는다. 전체 과정에서 가치가 없다는 결론은 아니다.

개인 PBL 시간 제안은 기존 대응표6절의 미결 상태를 유지한다. 이번 M01은 그 시간 배분을 승인받거나 대신 확정하는 안이 아니다.
