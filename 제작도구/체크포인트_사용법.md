# 체크포인트 저장 도구

코딩 에이전트·강사용 실행 안내다. 학생의 개인 작업 폴더에서 파일을 명시해 저장한다. 전체 폴더 자동 수집이나 DB 복원은 하지 않는다.

## 저장

제공 플랫폼을 import할 수 있고 PostgreSQL에 연결되는 Python 환경에서 실행한다. 아래 경로와 실행 ID는 실제 개인 작업에 맞게 바꾼다. 파일이 더 있으면 `--file`을 반복한다.

```powershell
python 제작도구/체크포인트_저장.py 개인체크포인트/중간저장01 --root 개인작업 --file 개인작업/1일차/replay_lab.py --file 개인작업/4일차/detector_lab.py --run-id 내실행ID --compare 4 3 10 5 --compare 2 1 1 1
```

- `--root`: 공통 개인 작업 폴더. 그 아래 상대 경로를 유지하므로 회차별 같은 파일명을 함께 저장할 수 있다. 이 경로 밖의 파일은 거부한다.
- `--file`: 저장할 `.py` 또는 `.ipynb`를 각각 명시한다. 키·`.env`·DB 파일은 대상이 아니다. 노트북 출력·코드 안에 직접 적힌 비밀값까지 자동 검출하는 도구는 아니므로 포함 전에 확인한다.
- `--run-id`: 내 실행 ID. 그 실행의 사건과 이력만 읽기 전용으로 내보낸다.
- `--compare`: `k_sigma min_delta_c sustain_s smooth_s` 순서. 제공 `evaluate.evaluate`를 해당 값으로 실제 실행하고 설정·전체 사이클별 결과·요약을 함께 저장한다. 여러 번 지정할 수 있다. 생략하면 평가 결과는 저장하지 않는다.

`thresholds`와 `quality_rules`는 저장 시 불러온 플랫폼 값이다. 지정 run이 실제 사용한 값이라는 증거가 아니다. `phase_evaluations` 역시 지금 제공 평가기로 실행한 결과이며 학생이 수정한 탐지 코드의 실행 결과와 구분한다. 개인 코드의 비교 결과·선택 이유·실제 실행 설정은 해당 노트북에 함께 기록해 저장한다. 빈 노트북 또는 출력 없는 코드를 복사하는 것만으로 이 기록이 충족되지는 않는다.

현재 입력 축약 데이터의 해시와 기준/시험 ID도 기록한다. 데이터 원본 자체는 이 폴더에 복사하지 않는다. 수업 재개 시 원본 데이터와 플랫폼 환경이 따로 필요하다.

## 저장본 다시 검사

```powershell
python 제작도구/체크포인트_저장.py 개인체크포인트/중간저장01 --verify
```

이 검사는 표준 Python만 필요하며 DB에 연결하지 않는다. 저장 코드 해시, 기준/시험 구간, 평가 사이클 ID, 사건과 실행·이력 연결을 대조한다. 저장본이 변경됐는지 확인하는 제한된 검사이며, 악의적인 변경 방지·결과 재계산·학생 코드 완주·DB 복원·설치 재현을 증명하지 않는다. 기존 형식의 체크포인트도 읽을 수 있지만 없던 비교 설정을 복원해 주지는 않는다.

같은 저장 폴더에 다시 쓰는 것은 거부한다. 다음 기록에는 새 폴더를 쓴다.
