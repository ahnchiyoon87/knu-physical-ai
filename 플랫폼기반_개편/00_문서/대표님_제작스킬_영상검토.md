## 영상·음성 제작의 실제 흐름

1. `specs/<ID>.json`: 장면 제목·화면 내용·나레이션·코드/앱 행동·기대 결과를 한 장면씩 정의한다.
2. `polish.py`: 원고 초안을 `gpt-6-astra`로 다듬는다. 사실·숫자·단위·코드 이름을 바꾸지 말도록 지시하고 캐시를 사용한다. 프롬프트 지시만으로 사실 보존이 증명되는 것은 아니다.
3. `tts.py`: **gpt-4o-mini-tts / marin** 음성으로 장면별 WAV를 생성한다. 차분하고 친절한 한국어 설명 지시를 넣고 ffprobe로 실제 음성 길이를 읽는다. 실습 영상 TTS는 본문이 같으면 재사용한다.
4. `render.mjs`: 개념/코드 설명은 HTML 화면을 만들고, 실행 장면은 실제 프로세스 출력을 화면에 표시하며, 앱 장면은 Playwright로 브라우저를 조작·녹화한다. 일반 터미널 앱을 그대로 녹화하는 것과 실제 출력을 HTML 터미널에 표시하는 것을 구별해야 한다.
5. `assemble.py`: ffmpeg로 장면·음성을 합치고 SRT 및 MP4 내부 자막을 만든다. 디코드 오류·음량·실행 기대 결과를 검사한다.

첫 영상 확장판은 README 기준 26:43, 49장면이다. 긴 설명을 한 화면에 얹은 것이 아니라 부 구분·기초 풀이·실행·반복 리뷰를 추가했다. 영상 전체를 실시간 청취 검수한 것은 아니며 앞서 장면 원고와 실제 MP4 길이·표본 프레임을 확인했다.

## UI 상호작용 자동화 — 가져올 핵심

`scripts/lab_videos/app_actions.mjs`가 앱별 행동을 담당한다. AI가 녹화할 때마다 화면을 보고 다음 클릭을 즉흥 결정하는 형태가 아니라, **준비된 행동 스크립트를 반복 실행**한다.

| 장치 | 원천에서 하는 일 | 우리에게 주는 이점 |
|---|---|---|
| 장면 사양/앱 동작 분리 | 장면의 action·params를 앱별 동작 함수가 수행 | 대본 수정과 클릭 코드 수정을 분리 |
| UI 식별자 | data-testid·역할·라벨로 클릭·입력 대상 지정 | 화면 위치가 조금 달라도 대상 추적 가능 |
| 상태 기반 대기 | API에서 사건 발생/처리 상태를 반복 확인, UI 요소 출현 대기 | 단순히 몇 초 쉬고 다음 버튼을 누르는 실패 감소 |
| 준비와 시연 분리 | 서버 모드·시드·시뮬레이터 상태를 준비한 후 UI 조작 | 항상 같은 시작 조건으로 장면 재현 |
| 단계별 검사 | 기대 상태/요소/실행 종료 결과를 확인 | 실패 장면을 정상 영상으로 내보내는 위험 감소 |
| 장면별 클립 | 장면별 녹화·음성·부분 렌더, 앞 수정 순서 재적용 | 한 장면 오류로 전체를 다시 촬영하는 부담 감소 |
| 화면 강조 | 선택 영역 강조·캡션·스크롤 | 시청자가 지금 볼 대상을 따라가기 쉬움 |
| 서버 잠금 | 앱 상태를 바꾸는 녹화를 직렬화 | 다른 장면의 초기화/모드 변경으로 녹화 깨짐 방지 |

중요한 한계: 원천도 모든 작업을 UI로만 하지는 않는다. API로 시뮬레이터 초기화·사건 주입 등을 수행하고 일부 행동은 화면 클릭으로 보여 준다. 따라서 UI로 하지 않은 초기 설정을 학생이 화면에서 수행한 것처럼 편집하지 않아야 한다. 고정 대기와 좌표 클릭도 일부 남아 있어 그대로 옮긴다고 안정성이 자동 보장되지 않는다.

## 이식 시 보강한 지침

- 공유 서버 리셋/재시작을 그대로 사용하지 않고 **녹화 전용 실행 공간**을 둔다. 학생 작업이나 다른 앱을 초기화하지 않는다.
- 원천의 macOS 경로·zsh·pkill 의존을 Windows 작업 환경에 맞춘다.
- UI 행동의 성공 기준을 장면별로 명시한다. 최종 보고의 app_checks 목록 존재만으로 모든 기대 결과가 검증됐다고 하지 않는다.
- 무한 잠금 대기, 타임아웃 없는 일부 프로세스, 고정 sleep과 좌표 기반 조작을 검토한다. 녹화 실패 시 장면 ID·원인·마지막 상태·캡처를 남긴다.
- TTS 캐시 키에 본문뿐 아니라 모델·voice·지시문을 포함한다. 원천 실습 tts.py는 본문만 비교하므로 목소리 설정을 바꿔도 예전 음성이 재사용될 수 있다.
- 원천 SRT는 글자 수 비례로 문장 시간을 배분한다. 실제 발화 정렬이 아니므로 정밀한 자막 동기화는 별도 검수가 필요하다.
- 음성보다 실제 UI 동작이 길면 영상이 늘어나지만 나레이션이 함께 다시 구성되지는 않는다. 장시간 설명 없는 화면이나 발화와 다른 동작을 검수한다.
- API로 준비하는 단계와 화면에서 보여줄 행동을 사양에 구분한다. 실측 결과·교육용 값·오프라인 대체 동작 표시를 유지한다.
